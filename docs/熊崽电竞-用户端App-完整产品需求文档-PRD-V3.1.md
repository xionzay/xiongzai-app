## 0. 文档使用说明

### 0.1 目的

本文档是用户端第一阶段 MVP 的完整开发基线，供产品、UI、前端、移动端、后端、测试、运营和验收共同使用。程序员应能依据本文档明确：

- 要实现哪些角色、页面、组件和业务能力；
- 每个页面展示什么、从哪里进入、点击后去哪里；
- 页面如何调用真实本地 API、如何处理并发和重复提交；
- 订单、支付、退款、投诉、评价、陪玩审核、提现等状态如何展示与流转；
- 加载、空数据、失败、断网、权限不足、图片失败、提交中等非理想状态如何处理；
- 哪些能力属于第一阶段，哪些只做占位，哪些明确不做；
- 功能完成后如何测试和验收。

### 0.2 需求优先级

| 标记 | 含义 | 执行规则 |
|---|---|---|
| P0 | 核心交易、安全、状态一致性 | 缺失即不得交付 |
| P1 | 完整体验、经营、售后、隐私 | 第一阶段必须完成 |
| P2 | 优化项、非主链路增强 | 不阻断主链路，但需记录 |
| 不在首期 | 明确排除 | 不得以假数据伪装已完成 |

### 0.3 事实来源与冲突处理

需求冲突时按以下优先级处理：

1. 后端状态机、数据库约束、服务端 `available_actions` 和权限校验；
2. 本文档的第一阶段固定范围与验收口径；
3. 当前用户端源码和接口实现；
4. 当前 Figma / 本地 UI 预览的视觉稿；
5. 更早版本 PRD、截图或口头描述。

UI 不得自行改变后端业务状态机。后端新增或调整终态时，必须同步更新本文档、前端映射和测试。

### 0.4 本版本相对 V2.0 的主要变化

- 只描述用户端与陪玩中心，不展开管理员后台页面。
- 补齐协议与隐私中心、协议详情与版本、我的接受记录、陪玩入驻协议确认。
- 补齐实名信息处理、声音名片公开试听的独立确认区域。
- 补齐微信/支付宝测试支付和支付六种结果页。
- 补齐手机号换绑、个人数据下载、账号注销的真实本地能力。
- 补齐完整订单、退款、投诉、评价、陪玩申请、卖家订单和提现状态。
- 补齐文件上传、声音名片、系统权限、全局状态和无障碍规范。
- 明确优惠券仅为 `0 张可用` 的占位功能。
- 明确聊天第一阶段只支持文字，不做实时语音/视频。

## 1. 产品概述

### 1.1 产品定位

熊崽电竞是面向和平精英玩家的 C2C 游戏陪玩交易平台。普通用户可浏览陪玩、购买服务、支付、聊天、申请退款、投诉和评价；通过审核的用户可进入陪玩中心发布服务、接单履约、处理售后并申请提现。

### 1.2 第一阶段目标

1. 建立“发现陪玩 → 选择服务 → 预约 → 下单 → 测试支付 → 履约 → 确认 → 评价”的完整买家闭环。
2. 建立“申请入驻 → 审核 → 维护主页 → 发布服务 → 接单 → 履约 → 收益 → 提现”的陪玩闭环。
3. 建立退款、投诉、平台客服和系统通知组成的售后闭环。
4. 对协议、实名、公开声音、个人数据、注销和资金相关操作提供明确确认与记录。
5. 在本地测试环境中使用真实数据库和真实业务状态，不使用前端假成功。

### 1.3 成功标准

- 新用户能完成登录、资料初始化和协议确认。
- 买家主交易链路不存在断路、死页或只能通过目录进入的页面。
- 陪玩经营主链路不存在无入口页面。
- 同一订单在买家端、陪玩端和后台显示的业务事实一致。
- 所有列表和详情都具备加载、空、失败、离线或受限处理。
- 金额计算、支付、退款、收益、提现均由后端数据决定。
- 关键动作具备防重复提交、幂等、并发冲突和明确反馈。
- 360×740 小屏、系统大字体、键盘弹出和安全区下可操作。

## 2. 第一阶段固定范围

### 2.1 必须实现

- 手机号 + 短信验证码登录与注册，无密码登录。
- 协议逐份展示、逐份确认、版本记录和接受记录。
- 和平精英陪玩与服务的浏览、搜索、排序、收藏和公开主页。
- SKU/服务规格、预约时间、订单确认、测试支付和支付结果。
- 买家订单、卖家订单、履约、退款、投诉、评价。
- 文字聊天、订单通知、账户通知、平台通知和平台客服。
- 陪玩申请、审核状态、资料管理、声音名片、服务管理。
- 收益中心、收益明细、微信/支付宝收款账户、提现和提现记录。
- 编辑资料、隐私设置、实名、手机号换绑、数据下载和账号注销。
- 加载、骨架、空数据、失败、离线、受限、Toast、弹窗、提交中。

### 2.2 明确限制

- 微信和支付宝均为本地测试渠道；界面必须标注“测试支付”，不产生真实扣款。
- 收款账户和提现仅显示微信、支付宝；不显示银行卡。
- 不做实时语音、实时视频、语音通话、视频通话、RTC 或房间通话。
- 保留声音名片录制、试听、上传、审核、公开试听。
- 聊天第一阶段只支持文字消息和系统消息。
- 不接真实短信、支付、退款、打款、实名、推送、内容审核或生产云存储。
- 协议均标注“本地测试草案”，不冒充正式法律文本或第三方电子签约。
- 不修改后端订单、支付、退款、投诉、审核和资金状态机。
- 不在隐私与安全页提供登录设备管理和黑名单。

### 2.3 占位能力

- 优惠券入口保留。
- 统一显示 `0 张可用`。
- 页面展示“第一阶段暂未开放”，不展示“5 张可用”等假数据。
- 不请求优惠券、领取、核销、折扣 API；下单金额不计算优惠券。

### 2.4 第一阶段不做

- 多游戏切换、游戏频道或游戏资产交易。
- 动态、直播、语音房、视频房、公会、排行榜、签到、抽奖、秒杀。
- 真实银行卡、信用卡或其他收付款渠道。
- 实时 WebSocket 聊天强依赖；当前允许前台 HTTP 轮询同步。
- 群聊、图片、文件、语音、视频、表情包消息。
- 登录设备管理、黑名单。
- 生产级外部推送、第三方地图或位置服务。

## 3. 用户角色与权限

| 角色 | 说明 | 可访问能力 |
|---|---|---|
| 游客 | 未登录用户 | 浏览首页、搜索、陪玩公开主页、服务详情、公开评价、协议中心 |
| 买家 | 已登录且资料已初始化 | 收藏、聊天、下单、支付、订单、售后、评价、个人中心 |
| 申请人 | 已提交陪玩申请 | 查看申请状态、补资料、重新提交 |
| 陪玩 | 申请审核通过 | 买家全部能力 + 陪玩中心经营能力 |
| 暂停陪玩 | 资格被暂停 | 查看经营历史和整改信息；不能接新单或上架新服务 |
| 封禁用户 | 账号或经营资格被封禁 | 按服务端原因进入受限页，不允许绕过 |

权限原则：

- 前端隐藏非法动作只是体验优化，后端必须做最终鉴权。
- 所有详情 API 必须校验资源归属或公开权限。
- 深链进入受限资源时，显示明确状态页，不泄露资源是否存在。
- 游客触发受保护动作时进入登录拦截页；登录后仅允许返回经过白名单校验的站内地址。

### 4.1 买家端底部导航

| 我的 | `mine` | 个人资料、收藏、规则、设置和陪玩中心入口 |

### 4.2 陪玩中心底部导航

| 导航 | 页面 | 说明 |
|---|---|---|
| 概览 | `seller` | 经营摘要和快捷入口 |

| 订单 | `sellerOrders` | 卖家订单和履约动作 |
| 收益 | `sellerEarnings` | 收益、明细、账户和提现 |

### 4.3 首页顶部

- 熊崽电竞 Logo、`推荐 / 陪玩 / 服务` 和搜索入口在同一行。
- 当前模式字号/字重放大，非当前模式保持正常；切换不刷新整个页面。
- 推荐模式展示在线陪玩和在售服务；陪玩模式展示陪玩列表；服务模式展示服务列表。

### 4.4 路由通则

- 返回优先回到来源页并恢复列表筛选、滚动位置和已选模式。
- 支付、退款、投诉、订单详情等流程页禁止依赖浏览器历史推断业务状态。
- 通知深链必须先验证目标资源权限；目标已删除则显示安全失败页。
- 支付完成后不能返回收银台重复创建支付。
- 账号注销完成、手机号换绑完成后清理会话并返回登录页。

## 5. 全局视觉、交互与组件规范

### 5.1 品牌规范

- 保留现有熊崽电竞 Logo、IP 形象、蓝色/橙色体系、暖白背景、圆角卡片。
- 不重做整体品牌，不替换已有核心图标含义。
- 主要操作使用橙色，信息与链接使用蓝色，成功使用绿色，警告使用橙色，失败使用红色。
- 相同业务含义必须使用相同图标、文案和颜色。

### 5.2 布局与尺寸

- 设计基准宽度 390px，同时适配 360px–430px。
- 内容不得横向溢出；长标题单行省略或按页面规则换行。
- 底部固定操作栏避让 iOS/Android 安全区。
- 键盘弹出后，当前输入框和主要提交按钮必须仍可见或可滚动到达。
- 主要触控目标最小 44×44px；视觉图标可小于点击区域。
- 列表使用连续页面布局，避免为每行增加过大的独立外卡。

### 5.3 消息列表专项规则

- 消息列表占满手机内容宽度，两侧不留卡片式大空白。
- 平台客服、普通用户会话、系统通知每行统一 74px 高。
- 普通头像、客服头像、系统通知图标统一 48×48px。
- 系统通知图标使用黑色轮廓，不使用蓝色实心填满。
- 会话标题、摘要、时间、未读角标对齐一致；摘要单行省略。
- 聊天气泡相对紧凑：头像约 44px、正文 13px、气泡内边距约 8px×10px、消息间距约 7px、页面横向边距约 11px。

### 5.4 评分星星

- 未选和已选必须使用同一条圆角五角星 SVG Path。
- 未选：`fill=transparent`，黄色描边。
- 已选：`fill=黄色`，描边同色；100% 填充，无透明度、渐变、阴影。
- 点击第 N 颗时前 N 颗全部选中；大小和间距不变化。

### 5.5 通用反馈组件

| 组件 | 使用场景 | 规则 |
|---|---|---|
| Toast | 轻量成功/失败反馈 | 2–3 秒自动消失；不遮住底部主按钮；同类消息去重 |
| ConfirmDialog | 不可逆或高风险动作 | 标题、影响说明、取消、确认；默认焦点不放在危险按钮 |
| BottomSheet | 规格、排序、渠道、日期 | 可关闭、可滚动、避让安全区 |
| InlineError | 表单单字段错误 | 放在对应字段附近，保留用户输入 |
| PageState | 加载、空、失败、离线、受限 | 标题、说明、主操作，必要时提供次操作 |
| BusyButton | 提交、支付、提现等 | 请求中显示加载，禁用重复点击，但不改变按钮宽度 |

## 6. 全局页面状态与网络规则

### 6.1 首屏加载

- 页面首次进入立即显示结构匹配的骨架屏，不能长时间空白。
- 骨架不得显示可点击假按钮或假金额。
- 登录恢复、协议加载、支付查询等安全相关页面可以显示专用加载页。

### 6.2 局部加载

- 下拉刷新保留旧数据，显示顶部刷新状态。
- 上拉分页保留当前列表，在底部显示分页加载状态。
- 按钮提交只锁定相关操作，非必要不锁定整个页面。
- 音频、图片和文件使用独立加载状态。

### 6.3 空数据

| 页面 | 空态文案 | 主操作 |
|---|---|---|
| 搜索 | 暂无相关陪玩或服务 | 修改关键词 / 返回首页 |
| 买家订单 | 还没有购买订单 | 去首页看看 |
| 消息 | 暂无消息 | 去找陪玩 |
| 收藏 | 还没有收藏内容 | 去发现 |
| 系统通知 | 暂无系统通知 | 返回消息 |
| 收益 | 暂无收益明细 | 查看经营规则 |
| 提现 | 暂无提现记录 | 发起提现 |
| 服务 | 还没有发布服务 | 发布服务 |

### 6.4 加载失败

- 页面显示“加载失败”和可理解原因，不显示堆栈、SQL、内部服务名或原始响应。
- 提供“重试”；有安全返回路径时提供“返回”。
- 协议加载失败必须明确写明“当前操作已阻止”，并禁用继续、登录、支付、实名、公开声音或投诉提交。
- 重试必须重新请求真实 API，不得把空数组当成功。

### 6.5 断网

- 全局展示非阻塞断网提示条：“网络不可用，请检查连接”。
- 已有缓存可继续只读浏览，但提交、支付、退款、上传、发送消息等动作禁用并说明原因。
- 恢复联网后自动刷新当前关键数据；不得自动重复资金或高风险提交。

### 6.6 图片/音频失败

- 图片失败显示同尺寸品牌占位图，保留布局和替代文本。
- 声音名片无法加载时停止播放并显示 Toast，可重试获取短时访问地址。
- 私有文件访问地址不得长期缓存、记录日志或持久化到本地存储。

### 6.7 HTTP 与错误映射

| 情况 | UI 行为 |
|---|---|
| 400 校验失败 | 显示字段错误或服务端用户文案 |
| 401 未登录/会话失效 | 尝试一次 refresh；失败后清会话并去登录 |
| 403 无权限 | 受限状态页，不暴露资源详情 |
| 404 不存在 | “内容不存在或已删除” |
| 409 版本冲突 | 刷新最新数据并提示“状态已变化，请重新操作” |
| 422 业务不可执行 | 显示服务端原因和允许的下一步 |
| 429 频率限制 | 显示剩余等待时间，按钮倒计时 |
| 5xx | 显示通用失败与重试；资金动作先查询结果，禁止盲目重提 |

## 7. 账号、登录、协议与隐私

### 7.1 启动页 `splash`（P0）

**入口**：App 冷启动、重新打开。  
**目标**：恢复安全会话并决定首个页面。

流程：

1. 读取安全凭证，调用 refresh；成功后 `GET /me`。
2. 未登录 → 登录注册。
3. 已登录但未初始化资料 → 资料初始化。
4. 已登录且资料完整 → 首页。
5. 临时网络失败时保留凭证，展示重试；不得误清账号。

### 7.2 登录注册 `auth`（P0）

**字段**：手机号、6 位验证码。无密码字段。  
**接口**：`POST /auth/sms/send`、`POST /auth/sms/login`、`GET /policies/current?scene=LOGIN`、`POST /policies/acceptances`。

规则：

- 手机号为中国大陆 11 位格式；验证码为 6 位。
- 获取验证码具备倒计时、频率限制和失败提示。
- 本地开发验证码由本地配置提供，不通过接口回传或写普通日志。
- 登录协议逐份展示，不允许默认勾选。
- 用户必须主动勾选当前 LOGIN 场景全部必需协议后才能登录。
- 协议失败或缺少发布版本时禁止登录。
- 请求中禁用按钮，避免重复登录。
- 成功后新用户进入资料初始化，老用户进入原受保护目标或首页。

### 7.3 资料初始化 `profileSetup`（P0）

**字段**：头像（可稍后）、昵称（必填）、简介（选填）。  
**接口**：`PATCH /me/profile`。

- 昵称 2–20 字，去首尾空格，不允许全空白。
- 头像走统一文件上传流程，不使用本地伪 URL。
- 处理用户版本和资料版本的并发冲突。
- 输入错误不清空已填写内容。

### 7.4 协议与隐私中心 `policyCenter`（P1）

展示：

- 用户服务协议、隐私政策、个人信息收集清单、第三方 SDK 及共享清单、系统权限说明、未成年人保护说明。
- 协议标题、当前版本号、发布日期、生效日期、本地测试草案标识。
- “我的接受记录”入口。

状态：加载、当前无发布版本、部分加载失败、完整失败、离线。

### 7.5 协议详情与版本 `agreementDetail`（P1）

- 展示协议标题、版本号、发布时间、生效时间、全文和历史版本入口。
- 长文支持目录、返回顶部和系统字体放大。
- 不把协议正文放进不可复制图片。
- 进入详情不代表接受；只有显式勾选并提交接受接口才产生记录。

### 7.6 我的接受记录 `policyAcceptances`（P1）

**接口**：`GET /policies/acceptances`。

每条展示协议名称、版本、使用场景、确认方式和接受时间。记录只读，不提供删除或修改。空态说明“尚无在线接受记录”。

### 7.7 陪玩入驻协议确认 `sellerPolicyConfirm`（P0）

- 进入陪玩申请前展示 SELLER_ONBOARDING 场景协议。
- 不默认勾选；每份协议可查看全文。
- 全部必需协议确认后才能进入申请表。
- 协议加载失败、版本缺失或提交失败均禁止继续。

### 7.8 场景化单独确认（P0）

以下场景不得复用一个笼统的“我同意全部”：

| 场景 | acceptance_scene | 独立说明 |
|---|---|---|
| 登录注册 | `LOGIN` | 账户服务和基础隐私处理 |
| 订单支付 | `ORDER_PAYMENT` | 测试支付、交易和退款规则 |
| 进入聊天 | `CHAT_ENTRY` | 文本内容处理、留存和审核 |
| 陪玩入驻 | `SELLER_ONBOARDING` | 经营、履约、结算和平台治理 |
| 实名提交 | `IDENTITY_VERIFICATION` | 姓名、证件号等敏感信息处理 |
| 声音名片 | `VOICE_SAMPLE_UPLOAD` | 录音上传、审核和公开试听 |
| 投诉提交 | `COMPLAINT_SUBMISSION` | 投诉内容及私有证据处理 |

### 7.9 游客登录拦截 `authGuard`（P0）

- 明确说明当前动作需要登录。
- 操作：立即登录、暂不登录。
- 登录成功后返回收藏、咨询、下单等原动作页面。
- `returnTo` 仅接受站内白名单，防止开放重定向。

## 8. 首页、搜索、陪玩与服务

### 8.1 首页 `home`（P0）

**接口**：陪玩列表、服务列表、未读摘要。  
**内容**：顶部 Logo/模式/搜索、推荐内容、陪玩列表、服务列表、买家底部导航。

规则：

- 推荐：展示已审核且可公开的在线陪玩与在售服务。
- 陪玩：排序支持综合、好评、销量；在线状态来自服务端。
- 服务：排序支持综合、销量、价格；仅展示可公开上架服务。
- 列表卡片使用真实数据，不展示测试代码名、Android 测试标题或乱码。
- 搜索关键词使用与和平精英业务相关的 2–4 字短词；不显示“已清洗为 2–4 字”等内部说明。
- 任何加载失败不展示混合假数据。

### 8.2 搜索 `search`（P1）

**内容**：搜索类型、输入框、搜索按钮、可搜索关键词、高评价内容。  
**规则**：

- 类型：陪玩/服务。
- 关键词去空格、限制长度、支持清空和键盘搜索。
- 热门关键词为真实上架内容聚合后的 2–4 字业务短词，如“经典四排”“地铁逃生”“稳定上分”。
- 不展示测试用例字符串、用户昵称长句或内部清洗标记。

### 8.3 搜索结果 `searchResults`（P1）

- 显示当前类型、关键词、结果数量、排序和筛选。
- 支持签名 Cursor 分页、下拉刷新、取消上一请求，避免快速搜索竞态。
- 陪玩结果进入陪玩主页；服务结果进入服务详情。
- 返回搜索页保留关键词；返回结果页保留筛选和滚动位置。

### 8.4 陪玩主页 `companion`（P0）

展示：封面、在线状态、昵称、段位、平台认证、标签、评分、完成订单、在售服务、收藏数、声音名片、介绍、和平精英资料、服务、真实评价。

操作：

- 收藏陪玩：未收藏为橙色圆角星描边，收藏后使用同一 Path 完全填充；操作成功后更新本地状态和 Toast。
- 咨询陪玩：蓝色对话气泡图标，进入咨询会话；游客先登录。
- 声音试听：获取短时访问地址后播放；再次点击暂停。
- 点击服务进入服务详情，点击全部评价进入评价列表。

底部“图标 + 文字”入口没有可见矩形外框，但保留足够点击区域，图标与文字垂直/水平对齐。

### 8.5 服务详情 `service`（P0）

展示：服务图片、完整标题、标签、价格、销量、评分、说明、服务规格、陪玩资料、预约说明、买家评价。

- 列表页截断的完整服务标题只在本页展示。
- 点击陪玩信息进入陪玩主页。
- 底部：咨询、收藏服务、选择规格；图标、颜色和文字规范与陪玩主页对应入口一致。
- 收藏成功/取消成功即时反馈；失败回滚。
- 服务不可购买时进入或内嵌 `serviceUnavailable`，展示服务端原因。

### 8.6 服务不可购买 `serviceUnavailable`（P0）

覆盖：服务下架、审核中、审核拒绝、陪玩暂停/封禁、SKU 全部失效、没有可预约时段、用户购买本人服务、资源删除。

页面只展示允许动作，例如“查看其他服务”“返回陪玩主页”“联系平台客服”；不得保留可点击购买按钮。

### 8.7 规格选择 `specs`（P0）

- 展示 SKU 名称、时长、计费单位、单价和状态。
- 默认不选择失效 SKU；只有有效 SKU 可点击。
- 选择后更新订单预估，但最终价格必须以预览接口为准。

### 8.8 预约时间 `bookingSchedule`（P0）

- 展示服务端返回的可约日期和时间段。
- 过滤已过期、已占用、被关闭时段。
- 时段被他人抢占时刷新并提示重新选择。
- 第一阶段取消“可接单时间”独立经营组件；仅在买家下单预约时展示真实可约时段。

### 8.9 我的收藏 `favorites`（P1）

- 分为“收藏的陪玩”“收藏的服务”，按钮大小不变，文字清晰。
- 陪玩列表的三张头像均为 1:1 同尺寸，左边距、上下位置一致。
- 昵称、段位/评分、标签、服务数/订单数各行左边缘和垂直间距统一。
- 取消收藏失败必须回滚；重复点击不得产生重复记录。

### 8.10 全部评价 `allReviews` 与评价详情 `reviewDetail`

- 只展示真实已公开评价；审核中评价仅对提交者显示状态。
- 评价列表支持分页、加载、空、失败。
- 匿名评价显示匿名昵称，不暴露买家真实资料。

## 9. 下单、支付与订单

### 9.1 确认订单 `checkout`（P0）

**接口**：`POST /orders/preview`、`POST /orders`。  
**展示**：陪玩、服务、规格、预约时间、数量、买家备注、商品金额、优惠、应付金额、协议确认。

规则：

- 进入时和提交前都要用服务端重新预览。
- 金额字段后端使用整数分字符串；客户端不得使用浮点计算。
- 优惠券固定不可用，优惠金额为 0。
- 价格、服务、SKU、时段变化时，阻止创建并要求用户确认最新信息。
- 创建订单带 `Idempotency-Key`；重复点击只生成一张订单。
- 支付协议不默认勾选，协议失败禁止提交订单/支付。

### 9.2 支付收银台 `payment`（P0）

渠道仅包括：

- 微信支付（测试）；
- 支付宝支付（测试）。

页面要求：

- 每个渠道展示图标、名称和“本地测试，不会真实扣款”。
- 选中态只有一条清晰描边/选中标记；不出现双层边框。
- 不展示银行卡，不默认选中支付渠道。
- 展示订单号、剩余支付时间、应付金额和测试说明。
- 未选渠道、协议未确认或协议加载失败时，支付按钮禁用。
- 创建支付使用幂等键；超时或网络中断先查询支付和订单状态。

### 9.3 支付处理中 `paymentProcessing`（P0）

- 展示正向不倾斜的处理中动画和订单信息。
- 有限退避轮询支付状态；前台恢复时立即重查。
- 达到超时时间进入支付确认超时页，不能无限转圈。
- 支付终态后停止轮询并替换到对应结果页。

### 9.4 支付结果全状态（P0）

| PageId | 后端状态/场景 | 标题 | 主操作 | 次操作 |
|---|---|---|---|---|
| `paymentResult` | `PAID` | 支付成功 | 查看订单 | 返回首页 |
| `paymentFailure` | `FAILED` | 支付失败 | 重新支付 | 查看订单 |
| `paymentCancelled` | 用户取消 | 已取消支付 | 重新支付 | 查看订单 |
| `paymentClosed` | `CLOSED`/订单关闭 | 订单已关闭 | 查看订单 | 返回首页 |
| `paymentTimeout` | 查询超时但未确认终态 | 支付确认超时 | 查询支付结果 | 联系客服 |

图标：成功勾号、失败感叹号、取消叉号必须正向；关闭使用正向卡通沙漏。无渐变、旋转或斜置导致歧义。

### 9.5 支付异常处理 `paymentExceptions`（P0）

覆盖价格变化、服务失效、时段失效、订单过期、重复支付、渠道不可用、状态未知。页面依据错误码给出明确下一步，不提供“假支付成功”。

### 9.6 买家订单列表 `orders`（P0）

- 筛选：全部、待付款、待接单、待开始/服务中、待确认、待评价、售后。
- 每项展示订单号、服务、陪玩、金额、状态、预约时间和允许动作。
- 使用签名 Cursor 分页；保留筛选和滚动位置。
- 状态文案来自统一映射，不直接显示英文枚举。

### 9.7 买家订单详情全状态（P0）

共同信息：订单号、服务快照、陪玩快照、SKU、预约时间、金额、支付、退款、售后、创建时间和状态时间线。动作以服务端 `available_actions` 为准。

| PageId | 状态 | 可见主动作 |
|---|---|---|
| `orderPendingPayment` | 待付款 | 去支付、取消订单 |
| `orderDetail` | 待接单 | 联系陪玩、取消/售后按服务端规则 |
| `orderAccepted` | 已接单待开始 | 文字沟通、查看预约 |
| `orderInService` | 服务中 | 联系陪玩、申请售后 |
| `orderPendingConfirm` | 待买家确认 | 确认完成、申请售后 |
| `orderCompleted` | 完成待评价 | 去评价、再次购买 |
| `orderReviewed` | 已评价 | 查看评价、再次购买 |
| `orderCancelled` | 已取消 | 查看原因、再次购买 |
| `orderSellerRejected` | 陪玩拒单 | 查看退款/关闭结果、重新选择 |
| `orderAfterSale` | 售后中 | 查看退款/投诉详情 |
| `orderRefunded` | 已退款 | 查看退款记录、联系客服 |

高风险动作使用二次确认；确认订单完成、取消和售后动作必须带最新 `version`，409 时刷新。

## 10. 退款、投诉与评价

### 10.1 申请退款 `refundApply`（P0）

**接口**：退款预览、`POST /refunds`。  
**字段**：退款原因、退款金额、说明。证据由投诉流程处理。

- 退款上限来自服务端预览，不能大于可退金额。
- 金额使用分字符串并格式化为两位小数。
- 提交带幂等键；请求中禁用重复点击。
- 成功进入退款详情。

### 10.2 退款详情全状态（P0）

| PageId | 业务状态 | 页面说明/动作 |
|---|---|---|
| `refundDetail` | 等待陪玩 | 展示申请、金额、理由、时间线；可按规则撤销 |
| `refundRejected` | 陪玩拒绝 | 展示拒绝原因；可申请平台介入 |
| `refundPlatform` | 平台介入 | 展示审核中和补充材料入口 |
| `refundProcessing` | 渠道处理中 | 禁止重复退款；可查询进度 |
| `refundCompleted` | 已完成 | 展示实际退款金额和完成时间 |
| `refundClosed` | 已关闭/拒绝/撤销 | 展示关闭原因和客服入口 |

### 10.3 投诉提交 `complaint`（P0）

**字段**：关联订单/退款、投诉类型、问题说明、证据。  
**规则**：

- 证据最多 6 张，私有存储；上传前确认投诉场景协议。
- 证据必须完成上传校验后才能提交。
- 不允许提交空描述、无归属文件或仍在上传的文件。
- 成功后进入投诉详情。

### 10.4 投诉详情全状态（P1）

| PageId | 状态 | 展示/操作 |
|---|---|---|
| `complaintDetail` | 处理中 | 投诉摘要、处理记录横向一行标题、时间线 |
| `complaintEvidence` | 待补证 | 补充证据和说明 |
| `complaintCompleted` | 处理完成 | 平台结论、完成时间、关联处理 |
| `complaintClosed` | 已关闭 | 关闭原因、客服入口 |

投诉证据不对另一方公开，仅授权人员按权限查看。

### 10.5 评价服务 `review`（P0）

- 仅已完成且未评价的真实订单可评价。
- 评分 1–5 星，点击第 N 颗选中前 N 颗。
- 文字评价选填并限制长度；可选择匿名。
- 同一订单只能提交一次；提交后不可伪造编辑。
- 状态：提交中、审核中、公开、隐藏；隐藏时展示原因（若允许）。

## 11. 消息、通知与平台客服

### 11.1 消息列表 `messages`（P0）

顶部入口顺序：系统通知、平台客服、最近会话。列表遵守 5.3 的统一尺寸。

每条展示：头像/图标、会话名称、最后消息摘要、最后时间、未读数。点击进入对应通知、客服或聊天页。

### 11.2 文字聊天 `chat`（P0）

**会话类型**：咨询、订单、客服。  
**消息类型**：`TEXT`、`SYSTEM`。

- 进入会话加载历史并定位到底部；向上加载更早消息时保持视觉锚点。
- 发送使用 `client_message_id` 幂等。
- 状态：发送中、已发送、已读、失败；失败原位重试，不重复生成气泡。
- 前台使用 HTTP 轮询同步新消息；离开前台暂停，恢复后补拉。
- 第一阶段不展示图片、语音、视频、文件、表情、通话按钮。
- 文本内容经过服务端审核/风控；失败使用用户可理解文案。

### 11.3 系统通知 `notifications` 与详情 `notificationDetail`（P1）

- 分类：订单、账户、平台。
- 支持未读/已读、分页、刷新和未读数同步。
- 进入详情后标记已读。
- 深链到订单、退款、投诉等资源前先验证权限；失败显示安全错误。
- 消息列表的系统通知图标为黑色轮廓，不使用蓝色实心块。

### 11.4 平台客服 `customerService`（P1）

- 可关联订单/退款/投诉，也可选择常见问题或纯文字咨询。
- 工单状态：排队中、服务中、已转交、已关闭；关闭后按规则重开。
- 展示客服文字聊天，不承诺实时语音/视频。
- 网络失败不得每次点击都重复创建工单；创建使用幂等或复用现有未关闭工单。

## 12. 我的、账户与隐私安全

### 12.1 我的 `mine`（P0）

展示头像、昵称、公开用户号、买家摘要、我的收藏、优惠券 `0 张可用`、编辑资料、文字消息、平台规则与售后、设置与隐私、陪玩申请/陪玩中心入口。

所有图标使用本地稳定资产或 SVG，不依赖会失效的远程路径；加载失败有同尺寸占位。

### 12.2 买家公开主页 `buyerProfile`（P1）

展示用户允许公开的头像、昵称、公开用户号、公开简介和必要的交易信誉摘要。受隐私设置控制，不展示手机号、实名信息、订单、支付、收货账户或接受记录。

### 12.3 编辑资料 `editProfile`（P1）

- 头像、昵称、简介。
- 输入框留空时保留当前内容的场景需明确区分“未修改”和“清空”；清空必须用显式操作。
- 版本冲突刷新并保留用户草稿。

### 12.4 隐私与安全 `privacySecurity`（P1）

入口：

- 手机号码与安全验证；
- 实名认证；
- 隐私设置；
- 个人数据下载；
- 注销账号。

不显示登录设备管理和黑名单。

### 12.6 实名认证（P0）

- 展示未认证、审核中、已认证、未通过、已过期/撤销状态。

- 创建导出任务、查看排队/处理中/完成/失败/过期。

- 下载地址只在内存中使用，不持久化、不写日志。

### 12.9 注销账号 `accountCancellation`（P0）

- 先查询资格与阻塞条件：未完成订单、售后、余额/负债、审核任务等。

- 冷静期内允许撤销；完成后清会话。
- 不允许前端伪注销或直接删除本地数据冒充完成。

### 12.10 平台规则 `rules` 与设置 `settings`

- 平台规则覆盖交易、支付、退款、投诉、评价、陪玩经营和隐私规则。
- 设置包含个人资料、隐私与安全、协议中心、平台规则、退出登录。
- 退出登录必须二次确认；成功后清安全凭证并返回登录页。

## 15. 文件、图片和声音名片

### 15.1 通用上传流程 `mediaWorkflow`（P0）

1. 请求上传策略和预签名地址。

- 文件过大、格式不支持、上传失败、审核拒绝均有明确文案。

### 15.3 声音名片（P0）

### 15.4 系统权限 `permissionCenter`（P1）

## 16. 业务状态机

### 16.1 订单状态机

```text
PENDING_PAYMENT
  ├─ 支付成功 → PENDING_ACCEPT
  └─ 取消/过期 → CLOSED/CANCELLED

PENDING_ACCEPT
  ├─ 陪玩接单 → ACCEPTED
  └─ 陪玩拒单/超时 → SELLER_REJECTED 或关闭并按规则退款

ACCEPTED → IN_SERVICE → PENDING_BUYER_CONFIRM → COMPLETED
                                   └─ 买家确认或超时自动确认

任一允许阶段可按规则进入售后；after_sale_status 与主订单 status 分开保存。
```

### 16.2 支付状态机

```text
CREATED → PAYING → PAID
              ├─ FAILED
              └─ CLOSED
PAID → REFUNDING → PARTIALLY_REFUNDED / REFUNDED
```

### 16.3 退款状态机

```text
REQUESTED
  ├─ SELLER_APPROVED → REFUND_PROCESSING → REFUNDED
  ├─ SELLER_REJECTED → PLATFORM_REVIEW / REJECTED
  ├─ NEGOTIATING → PLATFORM_REVIEW
  └─ CANCELLED
```

### 16.4 陪玩申请状态机

```text
DRAFT → SUBMITTED → UNDER_REVIEW
                    ├─ NEEDS_SUPPLEMENT → SUBMITTED
                    ├─ APPROVED
                    └─ REJECTED
APPROVED → SUSPENDED / BANNED（治理动作）
```

### 16.5 服务状态机

```text
DRAFT → PENDING_REVIEW → ON_SALE
                         ├─ OFF_SALE
                         └─ ADMIN_OFF_SALE
PENDING_REVIEW → REVIEW_REJECTED → 编辑后重新提交
```

### 16.6 投诉状态机

```text
SUBMITTED → ACCEPTED → PROCESSING → COMPLETED → CLOSED
                         └─ NEED_MORE_EVIDENCE → PROCESSING
```

### 16.7 收益和提现

```text
收益：PENDING_SETTLEMENT → AVAILABLE → WITHDRAWAL_LOCKED → WITHDRAWN
                                    └─ 售后冲正 → REVERSED / liability

提现：REQUESTED → REVIEWING/PROCESSING → SUCCEEDED
                                 ├─ FAILED
                                 └─ REJECTED/CANCELLED
```

## 17. API 与数据契约

### 17.1 通用请求规则

- API 前缀 `/api/v1`，浏览器请求使用 Cookie Session 和 `credentials: include`。
- 401 时只自动刷新一次；refresh 失败后登出。
- 有请求正文时使用 JSON；上传文件走预签名 PUT。
- 创建订单、支付、退款、投诉、消息、数据导出、注销、提现等写操作使用 `Idempotency-Key` 或客户端幂等 ID。
- 更新状态使用 `version` 乐观锁；409 重新读取。
- 列表使用签名 Cursor，不用不稳定的页码偏移。
- 客户端只显示服务端可公开文案；未知错误统一为“请求失败，请稍后重试”。

### 17.2 主要用户 API 目录

| 领域 | 主要接口 |
|---|---|
| 登录 | `/auth/sms/send`、`/auth/sms/login`、`/auth/token/refresh`、`/auth/logout` |
| 当前用户 | `/me`、`/me/profile`、`/me/privacy-settings`、`/me/identity-verification` |
| 协议 | `/policies/current`、`/policies/acceptances` |
| 生命周期 | `/me/phone-change-requests`、`/me/data-exports`、`/me/account-cancellations` |
| 发现 | `/companions`、`/services`、详情、声音访问、评价 |
| 收藏 | `/favorites` 与目标状态/列表接口 |
| 订单 | `/orders/preview`、`/orders`、订单详情和允许动作 |
| 支付 | `/payments`、支付查询、Mock 测试确认/失败/取消 |
| 退款 | `/refunds`、退款详情、介入/撤销等动作 |
| 投诉 | `/complaints`、详情、证据上传/绑定 |
| 评价 | `/reviews`、详情、陪玩评价列表 |
| 消息 | `/conversations/consultations`、`/conversations/orders`、消息列表/发送/已读 |
| 客服 | `/support-cases`、接入会话、关闭/重开 |
| 通知 | 通知列表、详情、已读、未读摘要 |
| 陪玩 | `/seller/applications`、`/seller/profile`、`/seller/services`、`/seller/orders` |
| 财务 | `/seller/finance/summary`、`/seller/finance/incomes`、`/seller/finance/liabilities` |
| 提现 | `/seller/payout-accounts`、`/seller/withdrawals` |

### 17.3 金额规范

- API 金额字段统一 `*_cent`，类型为十进制整数字符串。
- 客户端用 BigInt 或十进制定点库比较和加减，不使用 JS 浮点数。
- UI 统一显示 `¥0.00`，负数保留负号。
- 订单金额必须满足：`payable = total - discount`；实付、退款、平台费、陪玩收入由服务端返回。

### 17.4 快照和脱敏

- 历史订单保存服务、SKU、陪玩和价格快照；服务后续修改不改变旧订单。
- 手机号、证件号、收款账户只返回脱敏值。
- 买家端不得访问陪玩或其他用户的敏感资料。
- 日志不得记录验证码、令牌、证件、完整手机号、收款账号、预签名 URL。

## 21. 安全、隐私与合规要求

- Access/refresh 凭证存安全存储或 HttpOnly Cookie，不存普通 localStorage。
- 身份证、手机号、收款账号、验证码、令牌、预签名 URL 不进普通日志。
- 客户端不决定实名通过、退款成功、支付成功、提现成功或审核通过。
- 协议不默认勾选；保存版本、场景、确认方式和时间。
- 私有投诉证据、实名文件、数据副本使用短时授权访问。
- 数据导出完成后按过期策略失效。
- 账号注销必须验证阻塞条件和冷静期。
- 所有敏感页面截图/后台回显只使用脱敏值。
- 本地测试环境明确标识 Mock 能力，生产构建禁止 Mock 开关。

## 22. 非功能需求与无障碍

### 22.1 性能

- 首页/列表首屏在本地正常环境中快速显示骨架，不等待全部图片。
- 长列表虚拟化；分页请求不重复；图片按显示尺寸加载。
- 搜索输入防抖并取消过期请求。
- 聊天轮询在页面前台才运行，离开后停止。

### 22.2 适配

- 360×740 小屏无横向溢出。
- 系统字体放大到 200% 时，关键文字不裁切，主操作可达。
- 横屏非主要使用场景，但不得导致不可返回或不可提交。
- iOS/Android 顶部、底部安全区正确。
- 键盘弹出不遮住验证码、聊天输入、金额输入和提交按钮。

### 22.3 无障碍

- 文字和背景对比度至少满足 WCAG AA；普通文本建议 ≥4.5:1。
- 图标按钮提供可读 `accessibilityLabel` / `aria-label`。
- 选中态不只依赖颜色，同时有勾选、描边或文案。
- 表单字段有名称、错误关联和正确键盘类型。
- 加载使用 `status`，错误使用 `alert`，弹窗使用 modal 语义。
- 动画尊重“减少动态效果”。
- 触控目标至少 44×44px。

### 22.4 可用性与可靠性

- 资金、高风险和状态迁移动作可重试但不可重复执行。
- API 超时不直接宣告失败；查询当前资源状态后决定展示。
- App 前后台切换后刷新支付、订单、退款、提现和聊天。
- 客户端未知枚举显示安全兜底并上报，不崩溃。

## 24. 测试与验收

### 24.1 必测主链路

1. 新用户登录 → 协议确认 → 资料初始化 → 首页。
2. 搜索 → 陪玩主页 → 声音试听 → 收藏 → 咨询。
3. 服务 → 规格 → 预约 → 订单预览 → 测试支付成功 → 待接单。
4. 支付失败、取消、关闭、查询超时后重新支付/查询。
5. 买家待接单 → 陪玩接单 → 开始 → 完成 → 买家确认 → 评价。
6. 退款同意、拒绝、平台介入、渠道处理、完成/关闭。
7. 投诉提交、证据上传、补证、完成、关闭。
8. 陪玩申请、补资料、未通过、通过、暂停。
9. 发布服务、审核失败、修改、通过、上下架。
10. 收益生成、结算、收款账户、提现、提现详情。
11. 手机号换绑、实名、隐私设置、数据导出、注销/撤销。

### 24.2 状态测试

每个页面至少覆盖：

- 首次加载；
- 有数据；
- 空数据（适用时）；
- 请求失败；
- 离线；
- 401、403、404、409、429、5xx；
- 图片失败；
- 快速重复点击；
- 请求中返回/切后台；
- 旧版本并发冲突；
- 未知服务端枚举。

### 24.3 支付与资金验收

- 只出现微信、支付宝测试渠道。
- 不默认选中渠道；不确认协议不能继续。
- 不出现真实扣款或真实打款描述。
- 所有金额按分字符串计算，无浮点误差。
- 重复支付、退款、提现请求不重复记账。
- 买家、陪玩、后台的订单/退款/收益事实一致。

### 24.4 协议验收

- 所有必需场景均有协议列表、详情、版本和接受记录。
- 默认选中数量为 0。
- 加载失败时继续按钮不可用。
- 实名和声音公开试听有独立确认区域。
- 接受记录包含版本、场景、方式、时间。

### 24.5 UI/无障碍验收

- 360×740、390×844、430×932 无横向溢出。
- 大字体 200% 主流程可完成。
- 键盘不遮挡验证码、聊天和金额提交。
- 安全区不遮挡底部导航和固定按钮。
- 所有主要触控目标 ≥44×44px。
- 颜色对比度合格，选中态非仅颜色表达。
- 消息列表三类行高与图标/头像尺寸一致。

### 24.6 自动化与人工证据

交付必须包含：

- Web/移动端 TypeScript 与 ESLint 通过。
- 组件/领域单元测试通过。
- API 集成测试覆盖核心状态机、权限、幂等和并发。
- 浏览器 UI 测试覆盖导航、收藏、协议、支付和状态页。
- iOS/Android 模拟器或真机人工结果单独记录；未执行不得写“真机通过”。
- 本地 Mock 通过不等于生产微信/支付宝、短信、实名、推送和云存储通过。

### 24.7 Definition of Done

一个页面只有同时满足以下条件才可标记完成：

1. 有真实入口和返回路径；
2. 真实 API 与字段接入，不用假成功；
3. 权限与资源归属正确；
4. 加载、空、失败、离线、图片失败齐全；
5. 合法状态与动作完整；
6. 幂等、重复点击和版本冲突已处理；
7. 文案、金额、脱敏和协议符合本 PRD；
8. 小屏、大字体、键盘、安全区和触控验收通过；
9. 自动化测试通过且无控制台错误；
10. 页面目录、跳转关系和 PRD 同步更新。

## 27. 最终范围结论

第一阶段用户端是“买家 App + 同账号陪玩中心”的完整本地测试 MVP。核心交付不是页面数量，而是：所有页面有真实入口、所有状态有真实后端事实、所有关键操作可恢复且不重复、所有协议与敏感处理有显式确认、所有失败和空态可理解、所有资金与审核结论不由前端伪造。

优惠券继续作为 `0 张可用` 占位；银行卡、实时语音/视频、群聊、多游戏、生产外部支付/短信/实名/推送不属于本阶段。进入生产前必须按照 25.2 完成外部集成和独立验收。
