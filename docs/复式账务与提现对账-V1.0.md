# 熊崽电竞复式账务、收益、欠款、提现与对账 V1.0

## 1. 原则

- 金额在数据库、服务和测试中均为 bigint 分，HTTP 使用十进制字符串。
- 每笔 `POSTED` 交易至少两条分录，事务提交前由延迟约束触发器校验借贷合计相等。
- `ledger_entries` 禁止更新和删除；已入账 `ledger_transactions` 禁止修改业务字段或删除。
- 差错修正通过 `REVERSAL` 新交易交换原分录借贷方向，并将原交易标记为 `REVERSED`。
- 订单主收益由 `seller_incomes.order_id` 唯一约束保证每单一条。
- 提现锁定在陪玩行锁内按 `available_at, id` FIFO 选择收益，避免并发重复占用。

## 2. 借贷模板

| 业务事件 | 借方 | 贷方 |
|---|---|---|
| 订单完成 | 平台应收：订单实付 | 平台佣金；陪玩待结算 |
| 收益可用 | 陪玩待结算 | 陪玩可用收益 |
| 退款（未提现部分） | 平台佣金；陪玩待结算/可用收益 | 退款清算 |
| 已提现收益退款 | 陪玩欠款 | 退款清算 |
| 提现锁定 | 陪玩可用收益 | 陪玩提现锁定 |
| 提现完成 | 陪玩提现锁定 | 陪玩已提现；平台佣金（手续费） |
| 提现失败释放 | 陪玩提现锁定 | 陪玩可用收益 |
| 后续收益抵扣欠款 | 陪玩可用收益 | 陪玩欠款 |
| 冲正 | 原贷方账户 | 原借方账户 |

零金额分录不会创建。部分退款的陪玩承担金额按订单累计退款比例计算，使用“本次累计目标减前次累计目标”处理整数分舍入。

## 3. 收益与欠款

订单完成时创建 `ORDER_COMPLETED` 交易和唯一 `seller_incomes`，并按照活动平台配置 `finance.settlement_delay_seconds` 安排 `FINANCE_INCOME_AVAILABLE` 作业。手动确认和 Scheduler 自动确认使用同一账务引擎。

收益到期时由 `INCOME_AVAILABLE` 将待结算转为可用。如果存在 `OPEN` 或 `PARTIALLY_OFFSET` 欠款，随后按欠款 `created_at, id` 顺序创建独立 `LIABILITY_OFFSET` 交易和 `seller_liability_allocations`。欠款完全结清后解除 `risk_hold`。

退款优先扣减尚未提现的可用和待结算收益；已锁定或已提现而无法直接扣回的陪玩份额创建 `seller_liabilities`。有效欠款或陪玩维度 `HIGH/URGENT` 开放风险事件会阻止提现。

## 4. 提现

收款账户类型是闭集，仅允许 `WECHAT` 和 `ALIPAY`；HTTP Zod 校验与 PostgreSQL `payout_account_type` Enum 双重拒绝银行卡或任意字符串。本地账户验证、打款和回调全部由 Mock Payout Provider 执行；`/callbacks/v1/payouts/mock` 仅在 development/test 可用。

收款账户姓名和账号在应用层 AES-256-GCM 加密，使用域隔离 HMAC 作为查询哈希，只向客户端返回脱敏值。相同陪玩和账号哈希不能重复；同一陪玩、账户类型只能有一个未删除默认账户。

提现费率、最低和最高金额分别读取活动配置：

- `finance.withdrawal_fee_bps`
- `finance.withdrawal_min_cent`
- `finance.withdrawal_max_cent`

创建提现时先锁定陪玩资料行，再锁定 FIFO 收益行，创建 `WITHDRAWAL_LOCK`、提现单、收益分配和不可变提现日志。管理员批准后通过抽象 `PayoutProvider` 提交渠道；测试使用签名 Mock。回调由 Inbox 去重：成功创建 `WITHDRAWAL_COMPLETE`，失败创建 `WITHDRAWAL_RELEASE`，均不修改历史分录。

## 5. 对账

对账批次记录渠道、账单日期、总项数和差异数。每条渠道明细与支付或提现记录比较，产生：

- `MATCH`
- `MISSING_PLATFORM`
- `AMOUNT_MISMATCH`
- `STATUS_MISMATCH`

匹配项自动解决；差异项保持 `OPEN`，管理员可以 `RESOLVE` 或 `IGNORE`，必须填写原因并写管理员审计。差异处理本身不会改写支付、提现或账务历史；需要账务修正时另行创建调整或反向交易。

## 6. 接口

陪玩端：

- `GET /api/v1/seller/finance/summary`
- `GET /api/v1/seller/finance/incomes`
- `GET /api/v1/seller/finance/liabilities`
- `GET/POST /api/v1/seller/payout-accounts`
- `POST /api/v1/seller/payout-accounts/:id/default`
- `DELETE /api/v1/seller/payout-accounts/:id`
- `GET/POST /api/v1/seller/withdrawals`
- `GET /api/v1/seller/withdrawals/:id`

后台与渠道：

- `GET /admin-api/v1/finance/ledger-transactions`
- `GET /admin-api/v1/finance/ledger-transactions/:id`
- `POST /admin-api/v1/finance/ledger-transactions/:id/reverse`
- `GET/POST /admin-api/v1/finance/reconciliation-runs`
- `GET /admin-api/v1/finance/reconciliation-runs/:id`
- `POST /admin-api/v1/finance/reconciliation-items/:id/resolve`
- `GET /admin-api/v1/withdrawals`
- `POST /admin-api/v1/withdrawals/:id/approve`
- `POST /callbacks/v1/payouts/mock`

## 7. 测试重点

真实 PostgreSQL 集成测试覆盖超出 JavaScript 安全整数的金额、所有已入账交易平衡、主收益唯一、FIFO 与并发提现、提现失败释放、提现完成、分录冲正、已提现退款欠款、后续收益抵扣、风险暂停、收款账户密文/哈希/脱敏和对账差异处理。
