熊崽电竞｜用户端 App 开发十阶段提示词

使用说明

1. 不要一次把所有提示词同时发送，也不要并行开发，否则多个聊天框可能同时修改同一批文件。
2. 按阶段 1 至阶段 10 的顺序执行。
3. 每个阶段测试全部通过后，再发送下一阶段提示词。
4. 可以在同一个“用户端 App”聊天框连续发送，也可以新建聊天框，但必须使用同一个项目目录。
5. 每个阶段都必须保留已有修改，不得撤销其他任务成果。

阶段 1：App 工程、认证和首页底座
============================================================

继续开发“熊崽电竞”React Native 原生用户端 App。

开始前先检查当前仓库、Git Diff、PRD、技术架构、原生App认证文档、现有Web用户端UI和后端真实接口。保留当前所有未提交修改，不得撤销、覆盖其他任务成果，不创建Git commit。

本阶段目标：

创建 apps/mobile，并完成：

B01 启动页
B02 短信登录
B03 新用户资料初始化
B04 首页基础版
B28 我的基础版
买家端四个主导航：首页、订单、消息、我的

技术要求：

- React Native + TypeScript
- Expo Development Build/Prebuild
- Expo Router
- TanStack Query
- React Hook Form + Zod
- Expo SecureStore或同等级Keychain/Keystore方案
- 统一设计令牌、API Client、错误处理、环境配置和路由守卫
- 代码按功能拆分，禁止巨型单文件

接入真实接口：

- POST /api/v1/auth/sms/send
- POST /api/v1/auth/mobile/sms/login
- POST /api/v1/auth/mobile/token/refresh
- POST /api/v1/auth/mobile/logout
- GET /api/v1/me
- PATCH /api/v1/me/profile
- GET /api/v1/companions
- GET /api/v1/services

认证要求：

- Access Token只放运行时内存
- Refresh Token和稳定device_id放SecureStore
- 禁止使用AsyncStorage保存Token
- Bearer Access Token访问API
- 实现单例刷新队列
- 多个401只能触发一次刷新
- 刷新成功后原请求最多重试一次
- 刷新失败原子清理认证状态并进入登录页
- 冷启动通过Refresh Token恢复Session
- 退出时调用服务端并清理全部本地认证状态
- 禁止在日志、错误和测试输出中泄露Token、验证码、完整手机号
- 生产环境只允许HTTPS

UI要求：

- 严格参考app/page.tsx、app/globals.css、public/assets和PRD第6章
- 不重新设计品牌风格
- 建立颜色、字号、间距、圆角、阴影、按钮等统一Token
- 首页实现推荐、陪玩、服务三级分栏
- 首页必须有加载、空数据、失败、重试、断网和图片失败状态
- 订单和消息本阶段允许明确的空状态，但不得伪造业务数据
- 我的页面显示真实脱敏用户资料和退出登录
- 金额使用服务端返回的十进制分字符串安全格式化，不使用浮点数参与交易计算

补齐测试：

- SecureStore读写
- 登录成功与失败
- 冷启动恢复
- 单例Token刷新
- 无限刷新防护
- 退出清理
- 路由守卫
- 表单校验
- 首页加载、空数据、失败、重试
- 金额格式化

完成后运行Mobile类型检查、测试、lint、Expo配置检查，以及现有后端和根项目回归测试。模拟器不可用时不得伪造结果。

最后报告修改文件、运行方法、测试结果、已完成页面和剩余问题。直接实现，不要只给方案。

阶段 3：预约、下单和支付状态
============================================================

继续开发“熊崽电竞”React Native原生用户端App。本阶段实现从服务详情到订单创建及支付结果的完整购买链路。

开始前检查PRD、订单预约支付文档、后端实际Controller/Service、契约和测试。保留现有修改，不创建Git commit，不连接真实付费支付渠道。

实现页面：

- B43 预约时间
- B11 确认订单
- B12 支付收银台
- B13 支付处理中
- B14 支付结果
- B16 订单详情中的待付款和待接单状态
- B45 支付异常处理
- 相关二次确认弹窗、Toast和业务错误状态

主链路：

B09服务详情
→ B10规格选择
→ B43预约时间
→ B11确认订单
→ B12支付收银台
→ B13支付处理中
→ B14支付结果
→ B16订单详情

要求：

- 接入真实订单预览、创建订单、支付创建、支付查询和测试环境支付确认接口
- 具体路径、DTO和错误码必须从当前后端代码确认
- 订单创建必须使用Idempotency-Key
- 重复点击、网络重试和页面恢复不能创建重复订单
- SKU、价格、陪玩、佣金、时段均以服务端订单预览和快照为准
- 金额只使用分字符串或安全整数处理
- 禁止使用浮点数计算应付金额
- 预约时间展示真实可用时段
- 正确处理预约冲突、时段失效、服务下架、陪玩暂停和价格变化
- 创建订单前重新执行服务端预览
- 客户端不能自行决定最终价格
- 支付状态不能只相信客户端回跳
- App回到前台后必须向服务端查询支付状态
- 支付处理中采用有限轮询、退避和超时
- 支付成功、失败、取消、关闭均进入对应状态
- 支付异常后能够安全返回订单详情或重新发起支付
- 禁止重复支付已付款或已关闭订单
- 外部支付返回和深链结构要预留，但本阶段继续使用后端Mock Payment Provider
- 未登录用户下单先进入B42，登录后恢复SKU和来源页面，但下单前重新校验预览
- 支付完成页不能通过返回键回到重复提交页面

状态要求：

- 提交中
- 网络超时
- 订单幂等重试
- 预约冲突
- 价格变化
- 服务失效
- 支付渠道不可用
- 支付查询超时
- 支付成功
- 支付失败
- 用户取消
- 订单关闭

测试至少覆盖：

- 金额安全格式化
- 规格和时段选择
- 订单预览
- 创建订单Idempotency-Key
- 重复点击不重复下单
- 预约冲突
- 价格变化
- 支付处理中轮询
- 前后台切换后的状态查询
- 支付四种结果
- 认证刷新期间的下单请求
- 页面恢复不重复提交
- 深链返回
- 服务器错误映射

不得接入或购买真实微信、支付宝资源。完成后运行Mobile检查、订单支付相关API测试、后端回归和根项目测试，并报告真实结果。

聊天要求：

- 明确记录“实时网关尚未实现”的上线阻断

- 深链前检查登录、资源权限和目标是否存在
- 未读数由真实数据计算，不使用写死数字

客服要求：

- 接入真实客服工单创建、列表、重开和关联会话
- 支持关联订单、退款、投诉或提现
- 工单关闭后不能继续发送，需先重开

- 无权限深链
- 客服工单创建、关闭和重开
- 未读数量

阶段 6：个人资料、设置、隐私和安全

继续开发“熊崽电竞”React Native原生用户端App。本阶段实现“我的”、个人资料、协议、隐私与账户安全。

开始前读取PRD身份与用户模块文档和后端真实接口。敏感信息只使用后端脱敏响应，不得尝试获取数据库密文。

实现页面：

- B28 我的完整版
- B30 优惠券占位
- B31 编辑个人资料
- B32 买家基础公开主页

- B34 设置

要求：

- 使用真实/me、资料、隐私设置、Session、实名认证、协议版本与接受记录接口
- 编辑资料使用user version和profile version乐观锁
- 冲突时重新加载服务端资料，不能覆盖其他设备的新修改
- 手机号、姓名、证件号只显示后端脱敏值
- 实名提交禁止记录或输出完整敏感数据
- 隐私设置失败时回滚开关并重新读取服务端状态
- 协议内容、版本和发布时间来自服务端

- 当前后端未实现的数据下载、手机号换绑、注销任务必须显示明确状态，不得伪造完成
- 优惠券固定为PRD要求的0张占位，不实现虚假优惠券业务
- Session列表显示真实设备摘要，支持撤销其他Session
- 撤销当前Session后立即清理本地认证并进入登录页
- 注销属于危险操作，必须有二次确认；没有后端接口时只能展示说明，禁止本地假注销
