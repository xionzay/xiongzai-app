## 3. API 与契约变化

公共统一错误 JSON 格式不变。Web HttpOnly Cookie、App Bearer、后台 Session/MFA/RBAC 保持原实现。无新增生产凭据或业务配置键；本地测试配置仍使用开发验证码、人工实名、Mock 支付/退款/账户验证/提现和本地 MinIO。

| API | 新增/改变 |
|---|---|
| POST/PATCH `/api/v1/seller/services` | game、fulfillment_seconds、pricing_mode、price_cent；创建 SINGLE 自动默认 SKU；PATCH 保留原有完整 title/description 契约 |
| POST/PATCH `/api/v1/seller/services/:id/skus` | 新商品不要求 duration_minutes；金额字符串，SKU 编辑也递增商品 version |
| PUT `/api/v1/seller/services/:id/images` | image_kind=GALLERY/DETAIL；首商品图唯一封面；所有 file_id 服务端检查 |
| GET `/api/v1/services`、详情/店铺详情 | game 筛选/字段、期限、定价模式、图片类型、main_games；旧字段保持 |
| POST `/api/v1/orders/preview`、`/orders` | 新单无需 slot_id/service_starts_at；SINGLE 可不传 sku_id；服务端规则/价格快照 |
| GET `/api/v1/orders/:id`、卖家详情/列表 | PENDING_SERVICE；游戏/期限/凭证/核查/延期/催促字段；新单 after_sale_capabilities |
| POST `/api/v1/seller/orders/:id/start` | 新待服务进入履约中，旧已接单保留预约时间限制 |
| POST `/api/v1/seller/orders/:id/complete` | 新单 `version,evidence_file_ids`；旧单 version-only 保留 |
| POST `/api/v1/orders/:id/extend-receipt` | 新：买家一次 +24h，当前 version |
| POST `/api/v1/orders/:id/remind` | 新：买家待服务/履约中每 24h 一次催促，当前 version |
| GET `/api/v1/files/order-evidence/:orderId/:fileId/access` | 新：关联双方私有凭证运行时短链接，no-store/private |
| POST `/admin-api/v1/files/:id/moderation` | 录屏批准时必须 continuous_recording_confirmed=true，MFA/RBAC，审计显式记录确认 |

支付接口继续要求 `payment_channel=WECHAT_APP|ALIPAY_APP`，不接受银行卡或其他渠道。本轮没有新增支付供应商或收费服务。付款 PROCESSING 由本地 PAYING 与 provider_result 表示，客户端不能只凭 Provider 查询结果自行标记订单完成。

主要新增业务错误（保留现有格式）：`ORDER_IDENTITY_REQUIRED`、`ORDER_ADULT_VERIFICATION_REQUIRED`（403）；`ORDER_LEGACY_FIELDS_NOT_ALLOWED`、`ORDER_SKU_REQUIRED`、`ORDER_EVIDENCE_INVALID`、`ORDER_EVIDENCE_IMAGES_REQUIRED`、`ORDER_EVIDENCE_VIDEO_REQUIRED`、`ORDER_EVIDENCE_ALREADY_BOUND`、`ORDER_EVIDENCE_DUPLICATE_CONTENT`、`ORDER_ACTION_NOT_SUPPORTED`、`ORDER_EVIDENCE_REVIEW_PENDING`、`ORDER_EXTENSION_EXHAUSTED`、`ORDER_REMIND_RATE_LIMITED`、`FILE_VIDEO_CONTINUITY_REVIEW_REQUIRED`（409）；Schema/字段校验沿用 VALIDATION_FAILED（400）。订单不存在/越权沿用统一 404；版本冲突仍为 RESOURCE_VERSION_CONFLICT。部分错误在服务层产生，字段层不合法输入会先返回 400。

新增 scheduled_jobs 类型 `ORDER_FULFILLMENT_DUE`、`ORDER_RECEIPT_REMINDER`；自动确认沿用 `ORDER_AUTO_CONFIRM`。Worker Outbox 不调用真实推送：仅本地 IN_APP 通知记录和现有本地发布器。退款冻结后驳回恢复会安排新 version/deadline 任务；旧任务运行安全 no-op。

## 4. 请求示例（全部为占位/合成数据）

各写操作的 `version` 必须使用刚读取/上一步响应的值；下面数字仅示意。需要登录的调用沿用 Cookie 或 Bearer，不在文档存 Token。订单和支付创建携带独立 `Idempotency-Key`，重试同一操作复用同键；跨订单/渠道不能复用付款键。

### 4.1 商品发布与审核

先用 `/api/v1/files/uploads` 申请 PRODUCT_IMAGE 上传，直传本地 MinIO、complete、后台人工审核，获得已批准 file_id。

POST `/api/v1/seller/services`：

```json
{"game":"PEACE_ELITE","title":"和平精英本地测试商品","description":"商品说明与具体履约需求通过文字聊天沟通。","fulfillment_seconds":604800,"price_cent":"19995","cover_file_id":"11111111-1111-4111-8111-111111111111"}
```

PUT `/api/v1/seller/services/<product_id>/images`：

```json
{"version":0,"images":[{"file_id":"11111111-1111-4111-8111-111111111111","sort_order":0,"is_cover":true,"image_kind":"GALLERY"},{"file_id":"22222222-2222-4222-8222-222222222222","sort_order":1,"image_kind":"DETAIL"}]}
```

POST `.../submit-review` 传最新 `{"version":1}`；后台 POST `/admin-api/v1/products/<product_id>/review` 传 `{"action":"APPROVE","version":2}`。在售修改必须先 `off-sale`，改完重新提交审核；不能直接改 SKU 偷换公开价格。

多规格：创建 `pricing_mode=MULTI`（不填单价），调用 `.../skus`：`{"sku_name":"规格一","price_cent":"20000"}`，至少一个 ACTIVE SKU，再提交审核。默认单价商品添加第二个 SKU 会转 MULTI，默认 SKU 仍保留为一个规格；不需要 duration_minutes。编辑商品的 PATCH 仍需完整 title/description 和最新 version；新商品改 cover_file_id 会同步首图与文件绑定，不能只改公开 URL。

### 4.2 预览与下单

POST `/api/v1/orders/preview`：

```json
{"product_id":"33333333-3333-4333-8333-333333333333","quantity":1}
```

POST `/api/v1/orders`（`Idempotency-Key: local-order-example-001`）：

```json
{"product_id":"33333333-3333-4333-8333-333333333333","quantity":1,"expected_payable_amount_cent":"19995"}
```

MULTI 另传服务端返回的 sku_id。不得传 slot_id/service_starts_at 或必填买家备注。双方需现有有效人工实名成年，买家需通过协议场景 ORDER_PAYMENT 接受当前真实 policy_version_id；交易与退款使用现有合并规则协议版本，不虚构签署。

### 4.3 两渠道 Mock 付款

POST `/api/v1/payments`（`Idempotency-Key: local-wechat-example-001`）：

```json
{"order_id":"44444444-4444-4444-8444-444444444444","payment_channel":"WECHAT_APP"}
```

支付宝在另一付款请求选择 `ALIPAY_APP` 并使用其自己的幂等键。POST `/api/v1/payments/<payment_id>/query` 查询；development/test 下 POST `.../mock-confirm` 模拟成功、`.../mock-fail` 失败、`.../mock-cancel` 关闭。成功后订单 PENDING_SERVICE，失败/关闭可在订单未过期时创建新付款记录，不能修改历史记录渠道。过期由 Scheduler 关单，迟到成功回调明确拒绝；重复成功不重复状态变化。

退款继续 `/api/v1/refunds` 与商家/平台审核，回调必须走原 payments.channel；成功回调才记录到账与免佣，失败不伪造到账。没有真实支付 SDK 调用。

### 4.4 履约与收货

商家 POST `/api/v1/seller/orders/<order_id>/start`：`{"version":2}`。

截图申请上传类型 ORDER_FULFILLMENT_IMAGE（PRIVATE）；实付 200 元起录屏用 ORDER_FULFILLMENT_VIDEO（PRIVATE，video/mp4）。上传完成不等于审核通过。后台录屏审核示例：`{"decision":"APPROVED","reason":"本地人工核验本单材料","continuous_recording_confirmed":true}`；必须实际人工核验，不能由客户端自动设置。

商家 POST `.../complete`：

```json
{"version":3,"evidence_file_ids":["11111111-1111-4111-8111-111111111111","22222222-2222-4222-8222-222222222222","33333333-3333-4333-8333-333333333333","44444444-4444-4444-8444-444444444444","55555555-5555-4555-8555-555555555555"]}
```

这些 ID 是凭证占位，不是上文商品图；实际必须分别申请该用途、归卖家所有且已审核。高金额另追加录屏 file_id。进入 PENDING_BUYER_CONFIRM 并返回绝对 auto_confirm_at（72h）；客户端按服务端时间显示。

买家 POST `/api/v1/orders/<id>/confirm` 或 `/extend-receipt`：`{"version":4}`。延期返回 +24h 和 receipt_extension_used=true，后续不可重置。待服务/履约中 `/remind` 同样用最新 version，24h 冷却。自动确认需运行 Scheduler，Worker 处理收益结算，不要用前端定时器完成订单。
