# 1. 文档目的与使用方式

## 1.1 文档目的

本 PRD 用于统一以下团队的开发口径：

- 产品：确认第一阶段范围、流程和业务规则。
- UI/UX：补齐现有设计未覆盖的页面和全部页面状态。
- 买家端 App：实现浏览、咨询、购买、履约、售后和评价。
- 陪玩中心：实现身份申请、主页经营、服务经营、订单履约和收益管理。
- 服务端：提供统一身份、交易状态机、支付、聊天、财务和审核能力。
- 数据库：持久化业务事实、快照、状态历史和审计日志。
- 文件存储：管理头像、主页封面、服务图片和声音名片。
- 管理员后台：审核、治理、客服、财务和平台配置。
- 测试：按照页面、接口、状态机和端到端场景验收。

## 1.2 需求优先级

- P0：缺失会导致注册、发布、购买、支付、履约、售后或结算闭环无法完成。
- P1：缺失不会中断交易，但会明显影响经营、管理、安全或用户体验。
- P2：可在 MVP 上线后优化，不影响核心闭环。

除明确标记 P1/P2 的内容外，本文核心功能均按 P0 执行。

## 1.3 事实来源优先级

开发发生歧义时，按以下优先级判断：

1. 已冻结的 PRD V2.x 变更记录。
2. 本 PRD 的业务状态机、权限规则和数据约束。
3. 当前 Figma/熊崽电竞 UI 中与本 PRD 一致的交互。
4. 接口文档和数据库设计。
5. 口头描述不得直接覆盖已冻结需求，必须形成变更记录。

# 2. 产品定义

## 2.1 产品定位

熊崽电竞是面向年轻《和平精英》玩家和个人陪玩的 C2C 游戏服务交易平台。

平台不是自由发布任何闲置物品的综合市场，也不是俱乐部或内容社区。平台通过“陪玩主页—服务—规格—订单—履约—评价”的结构，让个人陪玩能够稳定展示并交易服务，让买家能够在统一交易保障下完成发现、咨询、支付和售后。

## 2.2 核心价值

### 对买家

- 快速发现高人气、高评价的和平精英陪玩。
- 同时按陪玩和按服务两种方式浏览。
- 先查看公开主页、声音名片和历史评价，再决定购买。
- 服务价格和规格清楚，订单状态明确。
- 全程平台文字沟通、支付、退款和投诉。

### 对陪玩

- 拥有独立公开主页，不以“店铺”作为对外名称。
- 可发布多个服务，每个服务可自定义多个规格和价格。
- 统一处理卖家订单、服务状态和收益。
- 通过评分、销量和服务积累长期复购。

### 对平台

- 建立可审核、可追踪、可结算、可治理的交易闭环。
- 买家、陪玩、管理员读取同一套业务事实。
- 通过订单佣金形成平台商业模式。

## 2.3 第一阶段目标

第一阶段只验证一件事：真实跑通《和平精英》陪玩服务的 C2C 完整交易闭环。

核心成功链路：

1. 用户手机号登录并初始化资料。
2. 用户申请成为陪玩并通过审核。
3. 陪玩完善公开主页和声音名片。
4. 陪玩发布带自定义规格和价格的服务。
5. 管理员审核服务后上架。
6. 买家在首页或搜索中发现陪玩/服务。
7. 买家查看主页、试听、收藏、咨询。
8. 买家选择规格、填写服务时间和备注并支付。
9. 陪玩接单、提供服务并提交完成。
10. 买家确认完成并评价。
11. 平台生成佣金与陪玩收益。
12. 买家可发起退款/投诉，管理员可处理。

## 2.4 第一阶段成功指标

上线前以业务闭环完整性为主，不以增长指标代替功能验收：

- P0 端到端用例通过率：100%。
- 核心订单状态转换接口自动化测试覆盖：100%。
- 支付回调、退款、收益入账幂等测试通过率：100%。
- 核心页面 Loading/Empty/Error/Success 状态覆盖率：100%。
- 崩溃率目标：低于 0.5%。
- API P95（不含第三方支付/短信/文件上传）：小于 800ms。
- 聊天在线消息端到端 P95：小于 2 秒。
- 订单和财务金额差异：0。

## 2.5 明确不做

第一阶段禁止加入：

- 其他游戏、多游戏入口或游戏切换。
- 附近、GPS、地图、同城。
- 俱乐部、战队、公会。
- 社区、动态、帖子、短视频、直播、语音房。
- 图片/表情/语音/视频/文件消息及音视频通话。
- 粉丝、关注、排行榜、等级成长、会员、VIP、积分。
- 礼物、打赏、签到、抽奖、广告。
- AI 推荐、AI 客服、AI 聊天、AI 商品生成。
- 和平精英官方数据同步或自动获取 K/D。
- 复杂推荐算法和复杂预约日历。

# 3. 产品术语与统一命名

| 产品术语 | 对外 UI 名称 | 内部技术名称 | 定义 |
|---|---|---|---|
| 普通用户 | 用户/买家 | User | 注册后默认身份，可浏览和购买 |
| 陪玩 | 陪玩 | Seller / SellerProfile | 审核通过后拥有经营能力的用户 |
| 陪玩公开主页 | 陪玩主页 | Seller Public Profile | 展示资料、声音、服务和评价，不称“店铺” |
| 商品 | 服务 | Product | 陪玩发布并售卖的服务商品 |
| 商品规格 | 服务规格 | ProductSku | 陪玩自定义的名称、价格和说明 |
| 买家订单 | 我的订单 | Order where buyer_id=current_user | 只显示当前用户购买的订单 |
| 卖家订单 | 卖家订单 | Order where seller_id=current_seller | 只在陪玩中心显示 |
| 收益 | 收益 | SellerIncome | 已完成订单生成的陪玩账务记录 |
| 声音名片 | 声音名片 | VoiceSample | 陪玩公开主页唯一一条 10–30 秒音频 |

强制规则：

- App 对外统一使用“服务”，不使用“商品”作为一级用户文案。
- App 对外统一使用“陪玩”，不使用“店铺”。
- 数据库和接口可保留 Product/SKU/Seller 等标准技术命名。
- 买家订单与卖家订单在 UI 中完全分离，但底层读取同一 Order 记录。

# 4. 用户角色、身份和权限

## 4.1 角色模型

### 买家

所有注册账号默认拥有买家权限。买家可浏览、收藏、咨询、下单、支付、查看本人购买订单、退款、投诉和评价。

### 陪玩

陪玩不是独立账号。User 的 SellerProfile 审核通过后，同一账号增加陪玩权限。陪玩保留全部买家能力，并获得陪玩中心、公开主页、服务管理、卖家订单和收益能力。

### 管理员

管理员使用独立 Web 后台和独立 AdminAccount，不能通过 App 普通用户角色获得后台权限。

## 4.2 身份状态

### 用户状态 UserStatus

- NORMAL：正常。
- DISABLED：后台禁用，禁止登录或执行交易操作。
- CANCELLED：账号注销，历史交易数据按合规要求保留。

### 陪玩状态 SellerStatus

- NOT_APPLIED：未申请。
- DRAFT：申请资料未提交。
- PENDING_REVIEW：审核中。
- APPROVED：审核通过。
- REJECTED：审核未通过，可查看原因并重新提交。
- SUSPENDED：暂停经营；公开页按规则展示，不能新增交易。
- BANNED：封禁；服务全部停止交易。

## 4.3 权限矩阵

| 能力 | 买家 | 审核中陪玩 | 已通过陪玩 | 管理员 |
|---|---:|---:|---:|---:|
| 浏览陪玩/服务 | 是 | 是 | 是 | 查看管理 |
| 收藏/咨询/购买 | 是 | 是 | 是 | 否 |
| 申请陪玩 | 是 | 查看状态 | 不重复申请 | 审核 |
| 发布服务 | 否 | 否 | 是 | 审核/下架 |
| 查看卖家订单 | 否 | 否 | 仅本人 | 全部 |
| 接单/履约 | 否 | 否 | 仅本人订单 | 只可治理，不代替正常履约 |
| 查看收益 | 否 | 否 | 仅本人 | 查看全部账务 |
| 修改订单金额/支付状态 | 否 | 否 | 否 | 不允许手工伪造支付成功 |
| 处理退款 | 发起/申请介入 | 同买家 | 卖家处理本人订单 | 平台介入 |

所有权限必须在服务端校验，客户端隐藏按钮不能替代鉴权。

# 5. 信息架构与导航

## 5.1 买家端主导航

现有 UI 的最终顺序为：

1. 首页
2. 订单
3. 消息
4. 我的

说明：买家端订单页只展示“我购买的”。发布服务、卖家订单和收益均不进入买家主导航。

## 5.2 陪玩中心入口

入口位于：我的 → 设置 → 陪玩身份。

- 未申请：显示“申请成为陪玩”。
- 审核中：显示“申请审核中”。
- 未通过：显示“申请未通过”，可查看原因并修改。
- 已通过：显示“进入陪玩中心”。
- 已暂停/封禁：显示对应状态和限制说明。

## 5.3 陪玩中心主导航

1. 概览
2. 服务
3. 订单
4. 收益

主页管理作为概览经营工具入口，不单独占底部 Tab。

## 5.4 首页内容导航

首页搜索框下方使用紧凑型三级分栏：

- 推荐：混合展示 Banner、热门陪玩和热门服务。
- 陪玩：仅展示陪玩列表，支持综合/好评/销量排序。
- 服务：仅展示服务列表，支持综合/销量/价格排序。

排序规则：

- 综合：后台推荐权重 + 质量规则，第一阶段可使用固定可解释排序。
- 好评：评分优先；评分相同按有效评价数、完成订单数降序。
- 销量：完成订单数量降序/升序切换。
- 价格：最低有效规格价格降序/升序切换。
- 第一阶段不提供筛选抽屉。

## 5.6 页面跳转与原型主链路

`B24 消息列表 → B26 系统通知 → B27 通知详情 → 关联订单/退款/投诉/账户页`

`S03 概览 / S12 收益中心 → S13 收益明细 → S14 收益提现 → S15 收款账户管理 → S16 提现记录 → S18 提现记录详情`

### 状态页跳转补充

- 支付收银台确认支付进入“支付处理中”，根据服务端查询结果进入支付成功、失败、用户取消或订单关闭；任何状态都可回到对应订单详情。
- 买家订单列表的每张卡片进入同状态订单详情；待付款进入支付，待接单等待陪玩响应，陪玩接单后进入待开始，待确认可确认完成，完成待评价进入评价，售后中和已退款进入对应退款详情。
- 退款详情覆盖等待陪玩、陪玩拒绝、平台介入、渠道处理中、退款完成和退款关闭；陪玩拒绝时可发起平台介入。
- 投诉详情覆盖处理中、等待补证、处理完成和已关闭；补证页提交后回到处理中。
- 陪玩申请覆盖审核中、需补资料、未通过、已通过和资格暂停；只有已通过状态可以进入陪玩中心。
- 卖家订单详情覆盖新订单、待开始、服务中、待买家确认、已完成、已关闭和已退款；售后订单进入卖家退款处理页。
- 服务管理“审核未通过”卡片进入 S17；提现记录卡片进入 S18。
- 陪玩申请、头像/封面、服务主图和投诉证据上传统一先经过 G10 权限检查，再进入 G09 选择、1:1 裁剪、上传和失败重试。

### 返回规则

- 从详情页返回来源列表，并保留列表滚动位置、搜索词和排序。
- 支付、提交申请、提交退款等完成页禁止返回重复提交页；系统返回时进入结果页或订单详情。
- 底部主导航切换保留每个 Tab 的一级页面状态；二级页面不显示底部主导航，除非现有核心页已经明确保留。
- 外部支付返回、推送通知和冷启动深链必须先完成会话校验，再进入目标页面；无权限时进入对应 G05 状态页。

# 6. 全局 UI 与交互规范

## 6.1 视觉定位

风格关键词：游戏社区、年轻潮流、轻电竞、清爽交易、真实陪玩、温和未来感。

视觉基线：

- 浅色为主，不使用大面积暗黑底色。
- 页面背景采用暖白、浅蓝或低饱和渐变。
- 主要品牌色为熊崽蓝，交易强调使用活力橙。
- 荧光黄绿、紫色只用于局部标签、规格票券和状态提示。
- 卡片具备轻微空间层次、柔和阴影和圆角；玻璃效果克制。
- 不使用普通企业后台式白卡堆叠，也不做高噪声电竞霓虹。

## 6.2 建议设计令牌

| 类型 | Token | 建议值 |
|---|---|---|
| 品牌蓝 | Brand/500 | #278FE8 |
| 深品牌蓝 | Brand/700 | #155E9F |
| 活力橙 | Accent/500 | #FF5A24 |
| 黄绿色 | Lime/500 | #CBEA2B |
| 紫色 | Violet/500 | #7D62F2 |
| 页面暖白 | Surface/Base | #FFF9EF |
| 卡片白 | Surface/Card | #FFFFFF |
| 浅蓝背景 | Surface/Blue | #EAF6FF |
| 主文字 | Text/Primary | #181A1F |
| 次文字 | Text/Secondary | #666B75 |
| 边框 | Border/Default | #E8E2D8 |

| 警告 | Status/Warning | #F59E0B |
| 危险 | Status/Danger | #E5484D |

具体色值以冻结后的 Figma Design Token 为准，开发不得在页面中散落硬编码色值。

## 6.3 字体与尺寸

- 页面主标题：24–28px，700–800。
- 区块标题：18–20px，700。
- 卡片主标题：16–18px，600–700。
- 正文：15–16px。
- 辅助文字：13–14px，不得小于 12px。
- 核心金额：24–32px，700–800。
- 底部导航图标：26–30px；文字 13–14px。
- 返回图标视觉尺寸不少于 28px，点击区域不少于 48×48px。
- 所有可点击控件最小热区 44×44px。

## 6.4 图标规范

- 首页、订单、消息、我的、服务、收藏、售后、设置、收益、优惠券、提现等统一使用已确认的线性图标体系。
- 相同语义跨页面必须复用同一 SVG 源文件，不得重复近似绘制。
- 图标图形在固定 ViewBox 中水平和垂直居中。
- 不使用 Unicode 字符作为正式图标。
- 激活态只改变颜色/线宽或使用轻量填充，不改变主体比例。

## 6.5 全局页面状态

所有远程数据页面必须实现：

- Initial：首次进入前的初始状态。
- Loading：骨架屏或局部加载，不长时间白屏。
- Success：正常数据。
- Empty：明确说明暂无数据，并提供合理下一步。
- Error：说明加载失败并提供重试。
- Refreshing：保留旧数据进行刷新。
- LoadingMore：列表底部加载更多。
- NoMore：列表到底提示。
- Offline：网络不可用。
- PermissionDenied：无权限或身份状态不允许。

### 状态视觉与交互标准

| 状态 | UI 表现 | 用户操作 | 动效/时长 |
|---|---|---|---|
| 首次加载 | 与真实卡片结构一致的暖白/浅蓝骨架；不得使用全屏空白 | 可返回；关键提交页不可误触 | shimmer 1.2–1.6s 循环，尊重“减少动态效果” |
| 局部加载 | 保留旧内容，仅刷新区域显示小型进度 | 其他无冲突区域可继续使用 | 淡入 150ms |
| 按钮加载 | 保持按钮原宽高，文字替换为加载符号+“处理中” | 禁止重复点击 | 旋转 800ms 循环 |
| 空数据 | 轻量熊崽插画、明确标题、原因和一个下一步动作 | 去首页/去逛逛/重新搜索等 | 插画淡入+上移 200ms |
| 加载失败 | 错误插画、简短原因、重试；必要时显示错误编号 | 重试、返回 | 重试后局部替换，不整页闪白 |
| 断网 | 顶部常驻弱提示条；首次进入断网时使用整页状态 | 重试、打开网络设置（系统能力允许时） | 网络恢复 Toast 2s，自动刷新一次 |
| 无权限 | 说明需要的权限及用途 | 去系统设置、暂不 | 弹层 180ms；不循环索权 |
| 列表到底 | 列表尾部“已经到底啦” | 无 | 静态 |

### 按钮状态

- Default：主按钮橙色填充，次按钮蓝色描边或浅蓝填充。
- Pressed：整体缩放至 0.97，色值加深约 6%，120ms ease-out。
- Disabled：保持可识别轮廓，文字与底色对比度不低于 3:1；不以透明度低于 40% 作为唯一表达。
- Loading：尺寸、位置不变；同时屏蔽重复请求。
- Success：仅短暂用于提交成功反馈，随后进入结果页，不让按钮长期变成状态标签。

### Toast、弹窗与底部弹层

- Toast：距离底部安全区至少 88px；成功/错误/提示三类；默认 2s，重要错误 3.5s；同类消息 1s 内合并。
- 二次确认弹窗：标题、风险说明、取消和确认；危险确认使用红色，不使用橙色造成混淆。
- 选择类底部弹层：圆角 24px，顶部拖拽条，选项最小高度 52px；点击遮罩关闭前需确认不会丢失已编辑内容。
- 表单底部弹层：键盘弹起后主要输入和确认按钮必须可见；不得被 iOS 灵动岛、Home Indicator 或 Android 手势区遮挡。

## 6.6 Prototype 交互与动效规范

- 页面前进：Move In from Right，220ms，ease-out。
- 页面返回：Move Out to Right，200ms，ease-in。
- 底部 Tab：Instant 或 Dissolve 120ms，不使用左右滑动暗示层级。
- Bottom Sheet：Move In from Bottom，220ms，背景遮罩 24% 黑色。
- Dialog：Dissolve + Scale 0.96→1，180ms。
- Toast：Smart Animate，上移 8px + 淡入 160ms，停留后淡出 120ms。
- 收藏、评分、接单等即时操作：乐观更新仅用于可安全回滚的操作；失败必须恢复原状态并显示 Toast。
- 支付、订单、退款、提现等资金与核心状态操作：不做纯前端乐观成功，必须展示 Loading 并以服务端结果页为准。
- Prototype 必须为每条主链路设置起始点、返回路径和至少一个异常分支；无链接的孤立页面不通过设计验收。

## 6.7 特定 UI 调整

### 聊天头像

- 消息列表头像：48px。
- 聊天气泡旁买卖双方头像：36–40px。
- 头像按钮透明，不额外绘制白色底板。
- 头像顶部与气泡顶部对齐。
- 点击对方陪玩头像进入陪玩公开主页；点击普通买家头像只进入基础公开资料，不暴露手机号等隐私。

### 陪玩主页收藏

- 底部左侧为“收藏陪玩”，右侧为“咨询”，两者高度和宽度一致。
- 收藏图标周围没有白色圆形/方形容器。
- 未收藏：橙色描边星，内部透明。
- 已收藏：橙色实心星，不使用白色内部填充。
- 咨询按钮使用蓝色图标、蓝色文字和蓝色边框。

# 7. 买家端详细页面需求

## 7.1 启动页 Splash

**目标：** 完成应用初始化和安全路由，不允许只作为固定延时动画。

**页面结构：**

- 完整熊崽电竞 Logo，整体显示，不裁切、不拆分。
- 浅蓝到暖白渐变背景。
- 轻量品牌动效或加载指示。
- 底部版本号，可选显示备案/版权信息。

**初始化任务：**

1. 读取本地会话。
2. 刷新或校验 Token。
3. 获取 User/Profile/SellerStatus。
4. 获取客户端基础配置和规则版本。
5. 判断新用户是否已完成资料初始化。

**路由：**

- 无会话 → 登录注册页。
- 会话有效、资料未初始化 → 新用户资料页。
- 会话有效、资料完整 → 首页。
- Token 刷新失败 → 清理会话并进入登录页。
- 网络失败 → 错误态，“重新加载”。

**验收：** Logo 完整；初始化不重复请求；冷启动失败可恢复；启动过程不出现超过 1 秒的无内容白屏。

## 7.2 登录注册页

**目标：** 使用手机号验证码统一完成登录和注册。

**页面字段：**

- country_code：默认 +86，第一阶段不可切换其他国家。
- phone：11 位中国大陆手机号。
- sms_code：4–6 位，长度由后端配置。
- agreements_checked：用户协议和隐私政策勾选。

**按钮与状态：**

- 获取验证码：手机号合法且未倒计时时可点击。
- 倒计时：默认 60 秒，实际值由服务端配置。
- 登录/注册：手机号、验证码、协议均有效时可点击。
- 请求中：按钮禁止重复提交。

**业务规则：**

- 已存在手机号：登录。
- 不存在手机号：自动创建 User 后登录。
- 短信发送需要图形/设备风控预留，但 MVP 可按手机号+设备+IP 限流。
- 服务端只保存验证码哈希，不保存明文。
- 连续错误需要限流和短暂锁定。

**异常文案：** 手机号格式错误、验证码错误/过期、发送频繁、账号禁用、网络失败、服务繁忙。

## 7.3 新用户资料初始化

**字段：**

- avatar_file：必填；上传成功后保存 file_id/url。
- nickname：必填，2–16 个可见字符。

**规则：**

- 头像限制类型、大小、尺寸并进行内容安全审核。
- 昵称去除首尾空格，过滤违规内容。
- 初始化完成前再次启动仍进入本页。
- 保存成功后进入首页并创建资料完成事件。

## 7.4 首页

**结构：**

1. 左上完整熊崽电竞 Logo，底部留安全间距。
2. 搜索框。
3. 紧凑分栏：推荐/陪玩/服务。
4. 推荐内容或排序栏。
5. 列表内容。
6. 买家端底部导航。

### 推荐分栏

- 品牌/活动 Banner，仅围绕和平精英和平台交易。
- 热门陪玩：标题辅助文案“高人气高评价的优秀陪玩”。
- 热门服务：展示近期购买表现和质量良好的服务。
- 推荐列表必须排除暂停接单、无有效在售服务、封禁和审核异常陪玩。

### 陪玩分栏

卡片字段：头像、在线状态、昵称、段位、评分、完成订单、标签、在售服务数、最低价格。

排序：综合、好评、销量；好评/销量可切换升降序。

### 服务分栏

卡片字段：主图、标题、规格摘要、标签、最低价格、已售、陪玩头像/昵称、评分。

排序：综合、销量、价格；销量/价格可切换升降序。

**分页：** cursor 优先；默认 page_size=20；支持下拉刷新和上拉加载。

**埋点：** 首页曝光、分栏切换、Banner 点击、陪玩卡点击、服务卡点击、排序切换。

## 7.5 搜索页

**入口：** 首页搜索框。

**结构：** 返回、自动聚焦输入框、搜索按钮、搜索历史、清空历史。

**搜索范围：**

- 陪玩昵称。
- 服务标题。
- 服务说明关键词。
- 当前仅《和平精英》，不显示游戏类型筛选。

**历史：** 默认只存本机最近 10 条；去重；最新置顶；可删除单条/全部。

**交互：** 输入防抖 300ms 可做建议，但只有点击搜索或回车才写入历史和进入结果。

## 7.6 搜索结果页

**结果类型继承搜索页选择，不在结果页混合展示：**

- 搜索类型=陪玩：只进入“陪玩结果页”，占满内容区域，不同时出现服务。
- 搜索类型=服务：只进入“服务结果页”，占满内容区域，不同时出现陪玩。
- 用户需要切换类型时返回搜索页，或点击结果页搜索框左侧的同款类型切换控件后重新搜索。

**陪玩排序：** 综合、好评、销量。

**服务排序：** 综合、销量、价格。

**规则：**

- 关键词高亮但不破坏昵称/标题。
- 搜索结果只返回可公开且符合当前状态的数据。
- 陪玩暂停接单可显示“暂停接单”，但不能进入购买。
- 服务下架不进入普通搜索结果。

## 7.7 陪玩公开主页

**目标：** 建立买家对真实陪玩能力、风格和履约质量的判断。

**结构优先级：**

1. 顶部返回、分享。
2. 主页封面/人物视觉、在线接单状态。
3. 头像、昵称、身份信息、标签。
4. 评分、完成订单、在售服务、被收藏数。
5. 声音名片。
6. 关于我与和平精英资料。
7. 全部服务。
8. 买家评价。
9. 固定底栏：收藏陪玩、咨询。

**展示字段：**

- seller_nickname、seller_avatar、cover_image。
- accepting_orders、last_active_at。
- introduction。
- game_rank、kd、preferred_mode、play_style、game_experience。
- voice_sample、voice_duration。
- rating、review_count、completed_order_count、favorite_count。
- active_service_count、services。

**声音名片：** 支持播放/暂停/进度/时长；离开页面停止；失败显示重试；无声音显示“暂无声音名片”。

**操作：** 收藏幂等；咨询创建或复用会话；服务卡进入服务详情；评价列表分页。

## 7.8 服务详情页

**结构：**

- 返回、分享；右上不放收藏。
- 服务图片轮播与页码。
- 标题、最低价格、销量、评分、标签。
- 服务规格区域。
- 陪玩信息卡，点击进入陪玩主页。
- 服务说明、可约时间、沟通方式、平台保障。
- 服务评价。
- 固定底栏：咨询、收藏服务、立即下单。

**购买限制：**

- 服务必须 ON_SALE。
- 陪玩必须 APPROVED 且 accepting_orders=true。
- 至少存在一个 ACTIVE SKU。
- 当前用户不能购买自己发布的服务。
- 不满足条件时按钮禁用并显示原因。

**快照提醒：** 页面展示实时服务信息；创建订单时服务端重新校验并保存快照。

## 7.9 服务规格选择

推荐在服务详情中使用底部弹层，也可直接使用当前卡片选择。

每个规格显示：sku_name、price、description、预计时长说明。默认选择第一个有效规格；切换规格同步更新底部价格。

服务端提交时只接收 sku_id 和 quantity，不接受客户端计算的最终价格。

## 7.10 我的收藏

**分栏：** 收藏的陪玩、收藏的服务。

**能力：** 分页、取消收藏、进入详情、下拉刷新。

**异常状态：**

- 陪玩暂停/封禁：显示状态，不可购买。
- 服务下架/删除：保留收藏记录的必要快照，显示“已下架”，不可购买。
- 空状态分别引导“去看看陪玩/去看看服务”。

## 7.11 消息列表

**每条会话：** 对方头像、昵称、最后消息摘要、最后时间、未读数。

**排序：** last_message_at 降序。

**行为：** 点击进入会话；进入后更新本人 read_cursor/unread_count；无会话显示安全提示和返回首页入口。

**限制：** 第一阶段不提供群聊、通讯录、通话和媒体消息。

## 7.12 文字聊天页

**结构：**

- 返回、对方昵称、在线/响应辅助信息、对方主页入口。
- 平台安全提示。
- 历史消息区域。
- 可选服务引用卡或订单引用卡。
- 文字输入框和发送按钮。

**消息状态：** SENDING、SENT、FAILED、READ。

**规则：**

- 仅自己发送的最后一条消息展示“已读/未读”。
- 发送失败可点击重试，重试复用 client_message_id 保证幂等。
- 历史消息向上分页，每页 30–50 条。
- 服务引用卡不是普通聊天消息。
- 买卖双方头像均显示，尺寸按 36–40px。
- 输入内容 trim 后为空不可发送；最大长度默认 500 字，由配置控制。
- WebSocket 不可用时降级为短轮询或连接重试，发送结果仍以服务端持久化为准。

## 7.13 确认订单页

**展示：** 服务主图、标题、陪玩昵称、已选规格、规格说明、单价、数量、期望服务时间、备注、金额明细、平台保障。

**字段：**

- product_id、sku_id。
- quantity：MVP 固定 1，接口仍保留。
- expected_service_time：纯文本，必填或按平台配置。
- buyer_note：可选，最大 200 字。
- submit_token/idempotency_key。

**提交：** 服务端重新校验服务、陪玩、SKU 和金额后创建 PENDING_PAYMENT 订单；成功进入支付页。

## 7.14 支付页

**支付渠道：** 微信支付、支付宝支付。未开通正式商户时只允许明确标识的沙箱环境。

**结构：** 订单号、金额、订单倒计时、渠道选择、支付按钮、支付安全说明。

**规则：**

- 应付金额来自服务端订单。
- 同一订单只能存在一个有效支付意图。
- 支付中禁止重复提交。
- App 从第三方返回后查询服务端支付状态，不直接相信客户端回调。

**页面状态：**

| UI 状态 | 触发条件 | 页面反馈 | 可用操作 |
|---|---|---|---|
| 待选择渠道 | 未选择支付方式 | 支付按钮禁用并说明“请选择支付方式” | 选择微信/支付宝、返回 |
| 可支付 | 渠道已选、订单有效 | 显示金额、倒计时和主按钮 | 立即支付 |
| 创建支付中 | 正在创建支付意图 | 按钮加载、禁止返回重复提交 | 等待、系统返回仍查询状态 |
| 唤起渠道失败 | 渠道 SDK/环境不可用 | 原位错误提示+Toast | 重试、切换支付方式 |
| 订单超时 | 倒计时归零或服务端已关闭 | 收银台不可支付 | 查看订单、返回首页 |
| 金额/服务变化 | 服务端校验失败 | 显示原因，不自动修改金额 | 返回确认订单或查看订单 |

## 7.15 支付结果页

状态包括：支付成功、支付失败、支付处理中、用户取消、订单已关闭/超时。

- 成功：查看订单/返回首页。
- 失败：重新支付/查看订单。
- 处理中：轮询服务端，超时后提示稍后到订单查看。
- 用户取消：返回收银台或查看待付款订单；不得标记支付失败。
- 已关闭/超时：不可再次支付原支付意图；如业务允许，重新从服务详情创建新订单。

支付结果页必须显示订单号、服务陪玩、预约时间、支付金额和结果时间；成功、失败、处理中使用不同图形与文案，但页面结构保持一致，避免跳动。

## 7.16 买家订单列表

**范围：** 仅 buyer_id=当前用户。

**分栏：** 全部、待付款、待接单、服务中、待确认、已完成、售后。已取消在全部中展示或通过二级状态查看。

**订单卡：** 陪玩昵称、订单状态、服务快照图片、标题快照、规格快照、实付金额、当前可执行操作。

**操作映射：**

- 待付款：去支付、取消。
- 待接单：联系陪玩、按规则申请退款。
- 服务中：联系陪玩、售后/投诉。
- 待确认：确认完成、联系陪玩、售后。
- 已完成：去评价/查看评价、再次查看服务。
- 售后：查看售后进度。

**完整订单 UI 状态：**

| 订单状态 | 买家文案 | 主操作 | 次操作 |
|---|---|---|---|
| PENDING_PAYMENT | 待付款 | 去支付 | 取消订单 |
| PENDING_ACCEPT | 待陪玩接单 | 联系陪玩 | 申请退款/取消（按规则） |
| IN_SERVICE | 服务中 | 联系陪玩 | 投诉/售后 |
| PENDING_BUYER_CONFIRM | 待确认完成 | 确认完成 | 联系陪玩、申请售后 |
| COMPLETED 未评价 | 已完成 | 去评价 | 查看详情 |
| COMPLETED 已评价 | 已完成 | 查看评价 | 再次查看服务 |
| CANCELLED | 已取消 | 再次查看服务 | 查看详情 |
| CLOSED/EXPIRED | 已关闭 | 重新下单 | 查看详情 |
| SELLER_REJECTED | 陪玩未接单 | 查看退款 | 联系陪玩 |
| AFTER_SALE | 售后中 | 查看售后 | 联系陪玩 |
| REFUNDED | 已退款 | 查看退款详情 | 再次查看服务 |

订单卡统一使用 1:1 服务主图，标题、规格和 `¥25.00` 两位小数价格；服务与陪玩信息均使用下单快照。按钮不得因状态变化造成整卡左右跳动。

## 7.17 买家订单详情

**展示：** 状态说明、状态时间线、订单号、服务与规格快照、陪玩、金额、期望时间、备注、创建/支付/接单/完成时间、售后信息。

**操作按钮由服务端返回 action list 控制，客户端不自行推断关键权限。**

详情页必须覆盖与订单列表相同的全部状态；顶部状态区包括状态名称、用户下一步和预计时间。待接单默认文案为“预计 3 分钟内响应”，如服务端有更准确 ETA 则覆盖。时间线至少记录创建、支付、接单、完成服务、买家确认、退款/关闭等实际发生节点，不展示未发生节点的虚假时间。

取消订单、确认完成、申请退款和投诉均先弹出对应确认层；确认成功进入新状态或结果页，失败保留当前页并显示可重试提示。

## 7.18 退款申请页

**字段：** order_id、refund_reason_code、reason_text、description、requested_amount。

**规则：**

- 可申请金额由服务端计算，默认不超过实付减已退。
- 不上传图片证据；第一阶段只支持文字说明和平台可读取的关联交易记录。
- 提交成功创建 Refund 并进入退款详情。

**表单状态：** 初始空值、原因选择弹层、输入中、校验错误、提交中、提交失败、提交成功。不得预填用户说明；字数统计使用正常字形，不使用斜体。

## 7.19 退款详情页

展示退款编号、订单、金额、申请原因、双方处理意见、当前状态、状态时间线和平台结果。

买家可在卖家拒绝后申请平台介入；卖家可同意或拒绝；管理员处理结果对双方同步。

**完整退款 UI 状态：**

| 退款状态 | 买家看到的标题 | 买家操作 |
|---|---|---|
| REQUESTED | 等待陪玩处理 | 撤销申请（规则允许时）、联系陪玩 |
| SELLER_APPROVED | 陪玩已同意退款 | 等待渠道处理 |
| SELLER_REJECTED | 陪玩拒绝退款 | 申请平台介入、补充说明 |
| NEGOTIATING | 协商处理中 | 继续沟通、申请平台介入 |
| PLATFORM_REVIEW | 平台处理中 | 补充证据、联系客服 |
| REFUND_PROCESSING | 退款处理中 | 查看进度；预计 24h 内更新 |
| REFUNDED | 退款完成 | 查看退款去向、返回订单 |
| REJECTED | 平台判定不支持退款 | 查看处理记录、投诉（符合条件时） |
| CANCELLED | 退款申请已撤销 | 返回订单 |
| CLOSED | 售后已关闭 | 查看处理记录 |

每种状态使用同一信息结构：当前进度、预计时间、退款金额、原因、方式、处理记录。金额使用两位小数；时间线仅显示真实事件。

## 7.20 投诉页面

支持订单投诉、服务举报、用户举报。

字段：target_type、target_id、order_id（可选/按类型必填）、complaint_type、description。

提交后生成投诉编号；用户可在关联订单/售后入口查看结果。

## 7.21 评价页面

**前置：** 订单 COMPLETED 且当前用户为买家且未评价。

**字段：** rating=1–5、content（可选或按平台配置）、anonymous_display（仅控制脱敏展示，不改变真实 buyer_id）。

**规则：** 每单一次；提交幂等；评价需通过内容审核状态后公开；违规评价可被后台隐藏/删除并触发评分重算。

**评分交互：** 五颗星必须使用同一个圆角五角星 SVG 路径。未选中为黄色描边、透明填充；已选中为同一路径的 100% 黄色填充，不使用系统默认尖角星、渐变、阴影或透明度。点击第 N 颗时第 1–N 颗选中，其余保持描边；星形尺寸和间距始终不变。

**页面状态：** 未评分、已选择 1–5 星、内容输入中、提交中、提交失败、提交成功、订单已评价不可重复提交、评价审核中/公开/隐藏。提交成功进入“已提交评价详情”，不能返回表单重复提交。

## 7.22 我的页面

**结构：** 用户头像/昵称；我的收藏；优惠券占位；编辑个人资料；文字消息；平台规则与售后；设置。

优惠券第一阶段明确不实现业务：入口保留，固定显示“0 张可用”；点击进入 B30 占位页或显示“第一阶段暂无可用优惠券”Toast。不得展示“5 张可用”等假数据，不提供领券、兑换、核销、优惠计算或优惠券接口。

不展示：买家等级、普通买家称号、钱包、买家订单状态宫格、直接进入陪玩中心。

## 7.23 编辑个人资料

支持修改普通用户头像和昵称。陪玩公开头像/昵称属于 SellerProfile，应在陪玩主页管理中修改，二者可相同但不强制联动。

## 7.24 平台规则

分组展示：用户协议、隐私政策、交易规则、陪玩服务规则、退款售后规则、禁止发布内容、投诉说明。

规则内容来自后台版本化配置；订单需要记录交易时适用的关键规则版本。

## 7.25 设置

包含：个人资料、隐私与安全、陪玩身份卡、申请/进入陪玩中心、平台规则、退出登录。

不在“我的”首页直接放陪玩中心入口；只有设置中根据 SellerStatus 展示。

## 7.26 系统通知列表

**入口：** 消息列表顶部“系统通知”；底部主导航消息角标计入未读系统通知。

**分栏：** 全部、订单、账户、平台。每条显示类型图标、标题、摘要、时间和未读点；按 `created_at` 降序；点击后标记该条已读并进入通知详情。

**操作：** 全部已读、分页加载、下拉刷新。第一阶段不支持用户删除平台必须留存的交易通知。

**状态：** Loading、正常列表、分类空状态、全部空状态、加载失败、断网、加载更多、已到底。

## 7.27 系统通知详情

展示通知标题、完整正文、时间、业务类型、关联对象摘要和主操作。关联订单进入 B16；关联退款进入 B18；关联投诉进入 B20；关联账户安全进入 B35；无关联对象时不展示虚假按钮。

通知正文由安全模板和结构化变量生成，不渲染任意不可信 HTML。已撤销或无权访问的关联对象进入说明状态，不出现死链接。

## 7.28 投诉详情

展示投诉编号、当前状态、投诉类型、问题说明、证据缩略图、关联订单/用户/服务、提交时间、预计处理时限和处理记录。

状态：已提交、平台已受理、需要补充证据、处理中、处理完成、已关闭。用户可在允许状态补充证据或联系客服；管理员处理结论、时间和依据需要同步展示。

## 7.29 全部评价与已提交评价

### 陪玩全部评价

展示综合评分、星级分布、有效评价总数、全部/有图/最新筛选和分页评价列表。评价条目显示脱敏买家信息、星级、正文、购买服务快照和时间；无评价使用空状态，不伪造示例评价。

### 已提交评价详情

只读展示本人已提交星级、正文、匿名选择、所购服务/规格、提交时间和审核状态。若平台允许追加评价，展示一次“追加评价”入口；不允许直接修改原评价。审核中、公开、被隐藏三种状态文案必须明确。

## 7.30 隐私与安全

页面项目：绑定手机号、实名认证状态、登录设备、修改登录手机号、隐私设置、黑名单、数据下载、账号注销、协议与隐私政策版本。

高风险操作需二次验证；敏感信息默认脱敏；账号注销必须展示影响、等待期和不可恢复后果。登录设备支持查看设备名、最近活跃和退出指定设备；当前设备不得误标为陌生设备。

## 7.31 买家基础公开主页

从聊天、评价或交易公开区域点击普通买家头像进入。展示头像、昵称、用户 ID、个性简介、加入时间、公开评价摘要和用户主动设为公开的信息。

明确不展示手机号、实名认证姓名、精确位置、钱包、订单、收藏、登录状态、设备信息或陪玩等级。可执行操作仅包含返回、投诉/拉黑等安全能力；普通买家没有“陪玩服务”和“立即下单”。

## 7.32 优惠券占位页

第一阶段固定展示“0 张可用”和轻量空状态，说明“优惠券功能将在后续版本开放”。页面不得请求优惠券列表、展示券模板、显示虚构有效期或参与订单计价。我的页面点击入口可进入本页；若采用 Toast 方案，文案为“第一阶段暂无可用优惠券”。

# 8. 陪玩中心详细页面需求

## 8.1 申请成为陪玩

采用三步流程：基本资料 → 游戏资料与声音 → 确认提交。

**基本资料：** 陪玩头像、陪玩昵称、主页介绍、主页封面（可选）。

**游戏资料：** 当前段位、K/D、擅长模式、擅长玩法、游戏经验介绍；均为用户自填并标注“陪玩自行填写”。

**声音名片：** 上传或录制、试听、删除、重传；10–30 秒；格式与大小由配置控制。

**提交：** 创建 SellerApplication 快照，SellerStatus 进入 PENDING_REVIEW。审核中允许查看，不允许发布服务。

## 8.2 陪玩申请状态

完整状态：草稿未提交、已提交、审核中、需要补充资料、审核通过、审核未通过、重新提交中、资格暂停/封禁。

需要补充资料或未通过必须显示管理员原因、需修改字段、审核时间和“修改并重新提交”。重新提交生成新审核版本，历史审核记录保留。审核通过后入口改为“进入陪玩中心”；资格暂停/封禁时展示原因和申诉/联系客服入口，不得进入经营功能。

所有申请表单默认使用空占位，不预填示例陪玩昵称、主页介绍、游戏资料或联系方式；已有草稿/退回修改时只回填用户本人上次保存的数据。

## 8.3 陪玩中心概览

**顶部收益区：**

- 左侧中部：今日收入、金额、较昨日变化。
- 右下角：“查看收益”。
- 不将提现按钮放在概览收益卡中。

**核心指标：** 新订单、服务中、待确认、在售服务；字体和点击区域清晰。

**经营工具：** 卖家订单、服务管理、主页管理、收益提现；图标与全局同语义图标一致。

**待办事项：** 待接单、审核未通过服务、退款待处理等；显示数量、最紧急剩余时间、处理入口。

**公开主页预览：** 进入买家视角主页。

## 8.4 主页管理

支持修改陪玩头像、昵称、封面、介绍、游戏资料、声音名片、当前接单状态。

敏感资料修改是否重新审核由后台配置。需要审核的字段采用“线上旧版本继续展示、修改版本待审核”的双版本策略，避免编辑后主页立即消失。

## 8.5 查看公开主页

复用买家陪玩主页组件，通过 preview=true 展示；不显示买家本人不可执行的购买行为，或明确标识“这是买家看到的效果”。

## 8.6 发布服务

**字段：** 多张图片、主图、服务标题、服务详情、服务时间说明、自定义规格列表。

**校验建议：**

- 图片：1–9 张，实际上限由配置返回。
- 标题：5–40 字。
- 详情：20–1000 字。
- 服务时间：1–100 字。
- 规格数量：1–20 个。
- 规格名称：1–30 字。
- 规格价格：大于 0，且不超过平台单价上限。
- 规格说明：0–100 字。

**能力：** 图片排序/设主图、规格增删改排序、保存草稿、提交审核。

## 8.7 服务管理

一级分区为 2×2 入口：出售中、审核中、已下架、草稿箱。审核失败服务在“审核中”内以明确失败状态展示，也可通过状态二级筛选直接定位。

卡片展示：主图、标题、最低价格、销量、状态、审核原因摘要。

操作随状态变化：

- DRAFT：继续编辑、提交、删除。
- PENDING_REVIEW：查看，必要时撤回（若平台允许）。
- REVIEW_REJECTED：查看原因、修改、重新提交。
- ON_SALE：查看、编辑、下架。
- OFF_SALE：编辑、重新上架/重新审核、删除。
- ADMIN_OFF_SALE：查看原因，不可直接上架。

**完整服务 UI 状态：**

| 状态 | 页面文案 | 可用操作 |
|---|---|---|
| DRAFT | 未编辑/草稿 | 继续编辑、提交审核、删除草稿 |
| PENDING_REVIEW | 审核中 | 查看；允许时撤回 |
| REVIEW_APPROVED | 审核通过待上架（如平台采用人工上架） | 上架、查看 |
| REVIEW_REJECTED | 审核未通过 | 查看原因、修改、重新提交 |
| ON_SALE | 出售中 | 查看、编辑、下架 |
| OFF_SALE | 已下架 | 编辑、上架/重新审核、删除 |
| ADMIN_OFF_SALE | 平台下架 | 查看原因、申诉/修改，不可直接上架 |
| DELETED | 已删除 | 普通列表不展示；后台保留审计 |

所有服务卡使用 1:1 主图，标题、规格摘要、价格、销量、状态和操作字号满足全局规范；价格统一两位小数。发布/编辑提交后立即在“审核中”看到刚提交的服务，不等待审核接口列表缓存刷新。

## 8.8 服务编辑

与发布页复用表单和校验。价格、图片、标题等修改不得影响历史订单快照。

若平台规则要求重新审核：保存为新修订版，旧版本在审核期间是否继续售卖由配置决定，默认重大字段修改需暂停新交易。

## 8.9 卖家订单列表

**范围：** seller_id=当前 SellerProfile。

分栏：新订单、服务中、待确认、已完成、售后。全部和已取消可通过二级入口/筛选提供。

卡片：买家脱敏昵称/头像、状态、服务快照、规格、期望时间、备注摘要、金额、可执行操作。

**完整卖家订单 UI 状态：**

| 状态 | 卖家主操作 | 次操作 |
|---|---|---|
| PENDING_ACCEPT | 接单 | 联系买家、拒单 |
| IN_SERVICE | 完成服务 | 联系买家、查看详情 |
| PENDING_BUYER_CONFIRM | 提醒确认 | 联系买家、查看详情 |
| COMPLETED | 查看详情 | 联系买家 |
| CANCELLED/CLOSED | 查看详情 | 无资金动作 |
| SELLER_REJECTED | 查看详情 | 无重复拒单 |
| AFTER_SALE | 处理退款 | 联系买家、查看详情 |
| REFUNDED | 查看退款详情 | 查看订单详情 |

卖家订单卡与买家订单卡复用同一服务快照组件：1:1 主图、相同标题/规格/两位小数价格；只改变身份信息和操作。联系买家使用蓝色填充、白色文字。

## 8.10 卖家订单详情

展示同一 Order 记录及状态日志。根据状态显示：接单、拒单、开始/继续服务、完成服务、联系买家、处理退款。

- 拒单必须填写原因并二次确认。
- 完成服务必须二次确认，状态进入 PENDING_BUYER_CONFIRM。
- 所有操作需要 idempotency_key 和服务端状态校验。

详情页完整覆盖新订单、已接单服务中、待买家确认、已完成、已取消/关闭、售后中、已退款。每个状态展示当前说明、时间线、买家头像/脱敏昵称、预约时间、文字沟通方式、备注、服务快照和金额；不得把不存在的步骤显示为已完成。

## 8.11 卖家退款处理

入口来自售后订单和概览待办。展示买家申请金额、原因、说明、关联订单、平台规则和剩余处理时间。

操作：同意退款、拒绝退款、联系买家。拒绝必须选择原因并可补充说明；同意/拒绝均二次确认。提交中禁止重复操作；状态冲突时刷新真实售后状态。平台介入后卖家只可补充说明，不可覆盖平台结论。

## 8.12 收益中心

**顶部余额区：**

- 左侧：可提现金额、待结算金额。
- 右侧中部：提现按钮。

**时间范围：** 今日、昨日、本周、本月、本年、累计。

**自定义筛选：** 年份、月份、周次；展开菜单使用与页面一致的卡通轻电竞样式，按钮位置不贴边。

**数据：** 选定范围收益、完成订单、平均客单、待结算、趋势图、收益明细。

**口径：** 所有汇总由服务端聚合；“今日”按平台时区自然日；一周起止规则由平台配置并固定。

## 8.13 收益明细

每条显示：订单号、服务标题快照、订单金额、平台佣金、陪玩收益、收益状态、完成时间、可用时间。

支持时间筛选、状态筛选、分页和进入订单详情。

## 8.14 提现

展示可提现金额、最低提现金额、收款方式、提现金额、手续费、预计到账、确认按钮。

提现金额不得超过可提现余额；提交时锁定对应余额；重复提交必须幂等。

提现金额和金额明细统一两位小数；输入框聚焦态的蓝色描边包含 `¥`、输入区域和“全部”。收款方式支持在已验证的微信和支付宝账户间切换；无账户时必须先进入收款账户管理。

## 8.15 收款账户管理

展示已绑定微信/支付宝账户卡片、脱敏账号、实名校验状态、默认账户、编辑和删除。支持新增账户底部弹层：账户类型、真实姓名、账号和验证信息均使用空占位；不得预填示例账号。

新增/修改需短信或等价二次验证；账户正在被提现使用时不可删除。切换默认账户需明确成功 Toast。删除账户必须二次确认并说明对提现的影响。

## 8.16 提现记录

展示申请时间、金额、手续费、状态、完成时间和驳回原因。状态：PENDING、PROCESSING、COMPLETED、REJECTED、CANCELLED（如允许撤回）。

提现记录详情还需显示收款方式脱敏信息、申请编号、预计到账、实际完成时间和状态时间线。空数据、加载失败、断网和分页状态复用 G01–G04。

# 9. 管理员 Web 后台详细需求

## 9.1 后台整体框架

左侧导航：数据总览、用户管理、陪玩审核、陪玩管理、服务审核、服务管理、订单管理、退款管理、投诉管理、评价管理、财务数据、提现管理、平台配置、操作日志。

后台为桌面 Web，使用轻量品牌化浅色界面；信息密度可高于 App，但状态、金额、风险操作必须清晰。

## 9.2 管理员登录

账号+密码，建议强制 MFA。包含验证码/风控、登录失败锁定、会话超时、退出登录和登录日志。

## 9.3 数据总览

指标：注册用户、今日新增、陪玩总数、待审陪玩、服务总数、在售/待审服务、今日/累计订单、GMV、佣金、退款金额、待处理退款/投诉/提现。

所有指标必须显示统计口径和时间范围，不从前端自行累加。

## 9.4 用户管理与详情

列表：用户 ID、头像、昵称、脱敏手机号、身份、状态、注册/最近活跃时间。

搜索：用户 ID、昵称、手机号精确查询。操作：查看、禁用、解禁。详情展示基础资料、身份、订单摘要、投诉摘要、操作记录。

## 9.5 陪玩审核列表与详情

列表支持状态、提交时间筛选。详情展示申请版本、头像、昵称、介绍、游戏资料、声音播放、历史审核记录。

通过/驳回均需二次确认；驳回原因必填；写入审核记录、通知和管理员日志。

## 9.6 陪玩管理

查看公开主页、服务、订单和经营数据；可暂停、恢复、封禁。风险操作必须填写原因并记录影响范围。

## 9.7 服务审核列表与详情

查看服务图片、标题、详情、服务时间、全部 SKU、价格、陪玩资料和历史版本。通过进入 ON_SALE；驳回进入 REVIEW_REJECTED 并填写原因。

## 9.8 服务管理

按状态、陪玩、关键词、时间筛选；查看、强制下架、删除违规服务。强制下架记录管理员、原因、时间和原状态，并通知陪玩。

## 9.9 订单管理与详情

列表字段：订单号、买家、陪玩、服务、规格、金额、支付状态、订单状态、创建时间。

详情：订单快照、买卖双方、支付、状态日志、聊天取证入口（受权限和隐私审计限制）、退款、投诉、评价、收益记录。

管理员不得直接随意修改订单状态；异常修复需专用受控操作并形成审计。

## 9.10 退款管理与详情

列表展示退款号、订单号、申请方、金额、当前状态、申请时间。详情展示买卖双方说明、订单日志、支付与可退金额。

管理员操作：同意、拒绝、其他处理结果；必须填写处理意见并触发支付退款流程。

## 9.11 投诉管理与详情

支持待处理、处理中、已完成筛选。详情展示投诉对象、关联订单、说明和可用证据。管理员可填写结果、封禁用户、暂停陪玩、下架服务；每个治理动作分别审计。

## 9.12 评价管理

支持按订单、买家、陪玩、服务、评分和状态查询。可隐藏/删除违规评价并填写原因；操作后异步重算服务和陪玩评分。

## 9.13 财务数据

展示 GMV、实收、退款、平台佣金、陪玩应结算、已结算、待结算、可提现和已提现。支持日期筛选和导出权限控制。

财务报表必须从账务明细聚合，不以可编辑余额字段作为唯一依据。

## 9.14 提现管理

展示陪玩、金额、收款方式脱敏信息、申请时间、风险状态、处理状态。审核/处理需要双重确认或分权机制预留。

## 9.15 平台配置

至少支持：

- 佣金比例。
- 待付款自动取消时间。
- 待接单提醒/超时策略。
- 待确认自动完成时间。
- 收益结算等待时间。
- 最低/最高提现金额。
- 服务图片数量与大小。
- 标题/描述/备注/聊天最大长度。
- 声音名片格式、大小、时长。
- 规则文本及版本。
- 推荐运营位和排序权重。

关键配置必须版本化、校验、灰度生效并记录操作日志。

## 9.16 管理员操作日志

记录：admin_id、角色、action、target_type、target_id、reason、before_json、after_json、request_id、IP、UA、created_at。

日志不可通过普通后台删除。

# 10. 核心业务状态机

## 10.1 服务状态

```text
DRAFT
  └─提交审核→ PENDING_REVIEW
       ├─审核通过→ ON_SALE
       └─审核驳回→ REVIEW_REJECTED
            └─修改并重新提交→ PENDING_REVIEW

ON_SALE
  ├─陪玩下架→ OFF_SALE
  └─管理员下架→ ADMIN_OFF_SALE

OFF_SALE
  └─重新上架/需审核→ ON_SALE 或 PENDING_REVIEW

任意允许状态
  └─删除→ DELETED（软删除）
```

## 10.2 订单主状态

```text
PENDING_PAYMENT
  ├─支付成功→ PENDING_ACCEPT
  ├─买家取消→ CANCELLED
  └─支付超时/支付意图关闭→ CLOSED

PENDING_ACCEPT
  ├─陪玩接单→ ACCEPTED
  ├─陪玩拒单→ SELLER_REJECTED → 退款
  └─达到平台超时策略→ CLOSED 或平台自动退款

ACCEPTED（已接单、待开始）
  ├─陪玩开始服务→ IN_SERVICE
  ├─买家申请取消/退款→ 进入退款状态机
  └─达到预约时间仍未开始→ 提醒、申诉或退款入口

IN_SERVICE（服务中）
  └─陪玩完成服务→ PENDING_BUYER_CONFIRM

PENDING_BUYER_CONFIRM
  ├─买家确认→ COMPLETED
  └─达到配置时间且无售后→ COMPLETED
```

订单额外维护 after_sale_status（NONE/IN_PROGRESS/RESOLVED）和 refund_summary，不用把主状态强行改写成模糊的“售后”。退款和投诉不应抹掉主订单历史；通过 Refund/Complaint 子状态与 Order 的售后标识协同。

## 10.3 退款状态

- REQUESTED：买家已申请，等待陪玩处理。
- SELLER_APPROVED：陪玩同意，等待退款执行。
- SELLER_REJECTED：陪玩拒绝，买家可申请介入。
- NEGOTIATING：双方协商中。
- PLATFORM_REVIEW：平台介入。
- REFUND_PROCESSING：支付渠道退款中。
- REFUNDED：退款完成。
- REJECTED：最终驳回。
- CANCELLED：申请方撤销（仅在允许状态）。

## 10.4 支付状态

- CREATED、PAYING、PAID、FAILED、CLOSED、REFUNDING、PARTIALLY_REFUNDED、REFUNDED。

支付状态和订单状态不能混用；支付回调只通过受控服务转换订单状态。

## 10.5 收益状态

- PENDING_SETTLEMENT：待结算。
- AVAILABLE：可提现。
- WITHDRAWAL_LOCKED：提现锁定。
- WITHDRAWN：已提现。
- REVERSED：因退款/纠纷冲正。

## 10.6 陪玩申请状态

```text
DRAFT
  └─提交→ SUBMITTED → UNDER_REVIEW
       ├─要求补充→ NEEDS_SUPPLEMENT
       │    └─修改并重新提交→ SUBMITTED
       ├─通过→ APPROVED
       └─驳回→ REJECTED
            └─修改并重新提交→ SUBMITTED

APPROVED
  ├─平台暂停资格→ SUSPENDED
  └─严重违规→ BANNED
```

每次提交生成 application_version；SellerStatus 只表示当前有效身份，审核记录不可覆盖历史版本。

## 10.7 投诉状态

- SUBMITTED：已提交。
- ACCEPTED：平台已受理。
- NEED_MORE_EVIDENCE：需要补充证据。
- PROCESSING：处理中。
- COMPLETED：处理完成。
- CLOSED：已关闭。

## 10.8 通知已读状态

- UNREAD：未读。
- READ：已读。

“全部已读”只修改当前用户通知，幂等执行；通知已读不代表关联订单/退款/投诉已处理。

# 12. 数据库设计

## 12.1 数据库原则

- 推荐 PostgreSQL；若原型基础设施使用 D1，正式交易系统仍需评估事务、并发和支付账务要求。
- 主键使用 UUIDv7/有序 ID；对外订单号单独生成。
- 所有核心表包含 created_at、updated_at；软删除使用 deleted_at。
- 金额为 BIGINT 整数分。
- 手机号、收款信息等敏感数据加密或令牌化。

# 13. 文件与对象存储设计

## 13.1 文件类型

| 文件类型 | 建议限制 | 可见性 | 使用位置 |
|---|---|---|---|
| USER_AVATAR | JPG/PNG/WebP，≤5MB | 公开 | 用户资料、聊天 |
| SELLER_AVATAR | JPG/PNG/WebP，≤5MB | 公开 | 陪玩主页 |
| SELLER_COVER | JPG/PNG/WebP，≤10MB | 公开 | 陪玩主页 |
| PRODUCT_IMAGE | JPG/PNG/WebP，单张≤10MB | 公开 | 服务列表/详情 |
| VOICE_SAMPLE | AAC/M4A/MP3，10–30秒，≤10MB | 公开受控 | 陪玩主页 |
| PAYMENT_PAYLOAD | JSON/文本 | 私有 | 支付审计 |
| ADMIN_EVIDENCE | 合规格式 | 私有 | 售后治理 |

限制值必须由平台配置返回，不在 App 硬编码。

## 13.2 上传流程

1. 客户端请求上传凭证，提交用途、MIME、大小和哈希。
2. 服务端校验权限并返回短时签名 URL/object_key。
3. 客户端直传对象存储。
4. 客户端提交完成确认。
5. 服务端校验文件元数据并进入病毒/内容安全审核。
6. 审核通过后才可绑定到公开业务对象。

## 13.3 存储安全

- Bucket 按公开与私有数据分离。
- object_key 不使用原始文件名，不包含手机号等 PII。
- 私有文件通过短时签名 URL 访问。
- 上传后校验真实 MIME、大小、音频时长和图片尺寸。
- 删除业务对象时先软删除引用，异步进行对象生命周期清理。
- CDN 使用缩略图和格式转换，原图不直接用于列表。

# 14. 支付、佣金、收益和提现

## 14.1 金额规则

- 所有金额使用整数分。
- 所有折扣、佣金、退款由服务端计算。
- 佣金使用基点 bps，例如 10%=1000bps。
- 舍入规则必须统一并有单元测试，建议每个订单分账时向下/银行家舍入策略固定写入技术规范。

## 14.2 订单计价

```text
服务小计 = SKU 单价快照 × 数量
应付金额 = 服务小计 - 优惠金额（如启用）
平台佣金 = 按佣金快照计算
陪玩应得 = 实付金额 - 平台佣金 - 已确认退款影响
```

优惠券若暂未实现真实业务，现有 UI 入口不得参与计价；需要单独需求后才能上线。

## 14.3 账务原则

- 数据库余额不是支付机构真实资金账户。
- 平台必须保留支付、退款、佣金、收益、提现之间的可追溯关系。
- 已完成订单先进入待结算，等待配置的风险期后变为可提现。
- 退款可能触发待结算取消、可提现余额冲正或后续提现抵扣，规则必须由财务和法务确认。

## 14.4 对账

需要支持日对账任务：支付订单、退款、平台业务订单三方核对；差异进入告警和后台处理清单。

# 15. 通知与实时通信

## 15.1 站内通知

买家事件：支付成功、接单、拒单、服务完成待确认、退款变化、平台介入、投诉结果。

陪玩事件：新订单、买家付款、退款申请、买家确认、评价、身份审核、服务审核、管理员下架、提现变化。

## 15.2 投递规则

- 每个业务事件生成唯一 event_id。
- Notification Consumer 幂等创建站内通知。
- App 未读角标由服务端未读数驱动。
- 推送可作为后续通道，但不替代站内通知和订单真实状态。

## 15.3 WebSocket

- 登录后获取短时 WebSocket ticket。
- 支持连接、心跳、重连、ACK、消息推送、已读游标和未读数同步。
- 服务端先持久化再确认发送成功。
- 多设备登录需要按 user_id 分发，read_cursor 跨设备同步。

# 16. 安全、隐私与风控

## 16.1 认证安全

- 短信发送按手机号、设备、IP 限流。
- Refresh Token 哈希存储并支持撤销。
- 管理后台强制更高安全级别和 MFA。
- 账号禁用立即撤销会话。

## 16.2 权限安全

- 所有资源以当前身份和资源归属校验，防止 IDOR 越权。
- 陪玩接口必须验证 SellerStatus=APPROVED。
- 后台使用 RBAC；财务、退款、封禁等高风险权限分离。
- 管理员查看聊天取证必须有业务理由、权限和审计。

## 16.3 内容安全

- 昵称、主页介绍、服务内容、规格、备注、聊天、评价和投诉均需文本审核。
- 头像、封面、服务图片和声音名片需内容安全审核。
- 风险内容可先拦截、后审核或延迟公开，策略按场景配置。

## 16.4 隐私

- 手机号在后台默认脱敏。
- App 不展示买卖双方手机号。
- 收款账户信息令牌化，前端仅显示脱敏结果。
- 日志不得记录验证码、Token、完整手机号和支付敏感数据。

# 17. 非功能要求

## 17.1 性能

- App 冷启动可交互目标：中端设备正常网络下 ≤3 秒。
- 首页首屏 API P95 ≤800ms；图片首屏采用缩略图和 CDN。
- 列表默认 20 条，消息 30–50 条。
- 搜索防抖 300ms。
- 图片懒加载；详情按需加载大图。

## 17.2 可用性

- 核心服务目标可用性 ≥99.9%。
- 支付回调、订单超时、自动确认、结算任务需要重试和死信处理。
- 第三方短信/支付/内容审核不可用时降级并明确提示。

## 17.3 可观测性

- 每个请求携带 request_id/trace_id。
- 记录 API 延迟、错误率、WebSocket 在线数、消息失败、支付回调失败、状态机冲突、对账差异。
- 核心告警：支付成功但订单未推进、订单完成但收益未生成、退款成功但账务未冲正、提现余额异常。

## 17.4 兼容与无障碍

- 适配 375/390/430px 宽度与安全区。
- 系统字体放大后核心操作不截断。
- 颜色不能作为唯一状态表达。
- 交互控件有可读 label；图片有合理替代文本。

# 19. 测试与验收

## 19.1 测试层级

- 单元测试：金额、佣金、权限、状态转换、校验器。
- 集成测试：数据库事务、Outbox、支付回调、文件上传确认。
- API 合约测试：OpenAPI 请求响应与错误码。
- 端到端测试：买家、陪玩、管理员完整链路。
- 视觉回归：关键页面和所有状态。
- 安全测试：越权、重放、注入、限流、敏感信息泄露。
- 性能测试：首页、搜索、订单、聊天和支付回调峰值。

## 19.2 买家主验收

1. 登录并初始化资料。
2. 首页推荐/陪玩/服务正常展示和排序。
3. 搜索陪玩和服务。
4. 查看陪玩主页、试听、收藏、咨询。
5. 查看服务、选规格、创建订单、支付。
6. 在订单中看到陪玩接单和服务完成。
7. 确认完成并评价。
8. 发起退款、平台介入和投诉。

## 19.3 陪玩主验收

1. 提交申请、管理员审核、结果同步。
2. 编辑公开主页、上传声音、切换接单状态。
3. 发布多图服务、自定义多规格价格、提交审核。
4. 管理员审核后在买家端可见。
5. 接收同一笔订单，接单、沟通、完成服务。
6. 查看收益、明细、佣金和提现记录。

## 19.4 管理后台验收

完成用户治理、陪玩审核、服务审核、订单查询、退款处理、投诉处理、评价治理、财务查询、提现处理、配置修改和操作日志核对。

## 19.5 必测异常

- 重复点击提交订单只生成一单。
- 重复支付回调只入账一次。
- 买卖双方同时推进订单时仅合法状态成功。
- 服务改价不影响历史订单。
- 陪玩暂停接单时无法新建订单。
- 退款与提现并发不会导致负余额。
- WebSocket 重连不重复显示同一消息。
- 图片/声音审核失败不公开。
- 管理员无相应权限不能执行高风险操作。

## 19.6 UI/UX 与 Figma Prototype 验收

### 页面完整性

- 5.5 页面目录中的所有“必做/新增/全状态”页面均有独立 Frame 或可复用的明确 Variant，不以一张静态正常态代替完整状态。
- 支付、订单、退款、陪玩申请、服务、卖家订单和提现的 UI 状态与第 10 章枚举逐项对应。
- 优惠券只显示“0 张可用”及占位说明，不出现假券、假余额或优惠计算入口。
- 所有列表具有 Loading、Success、Empty、Error、Offline 和分页状态；所有提交具有 Default、Pressed、Disabled、Loading、Success/Error 反馈。

### Prototype 跳转

- 5.6 六条主链路均可从起点完整点击到终点，并可以按返回规则回到正确来源。
- 危险操作、提交、支付和售后均通过弹窗/结果状态连接，不允许点击后无反馈。
- 深链目标无权限、关联对象失效、网络失败时进入对应异常状态，不跳空白页。
- Prototype 中不存在无入口、无返回的孤立核心页面。

### 跨端与可用性

- 使用至少一款带灵动岛/刘海的 iPhone、一款普通 iPhone、一款 Android 中置挖孔屏和一款 Android 手势导航设备进行安全区检查。
- 页面内容使用系统 safe-area inset；顶部标题/返回/操作不被状态栏遮挡，底部按钮不被 Home Indicator 或手势区遮挡。
- 返回、导航、排序、卡片操作和金额操作热区不小于 44×44px；核心正文不小于 15px，主要操作文字不小于 16px。
- 1:1 服务图片、两位小数金额、同语义图标、卡片圆角、阴影和间距在买卖双方页面一致。
- 200% 文字缩放或系统大字体下，关键标题、金额和主操作不重叠、不被裁切。

### 视觉回归检查清单

1. 无医疗白、企业蓝或普通 SaaS 观感；保持暖白、熊崽蓝、活力橙和局部黄绿/紫色。
2. 不改变已冻结核心页结构，只对缺失页和状态进行同系统扩展。
3. 所有中文文案可读，无截断占位、斜体字数统计和预填示例数据。
4. 空状态和错误状态不使用假订单、假余额、假评价或假优惠券。
5. 动效 120–250ms 为主，支持减少动态效果；加载动效不阻塞取消/返回。

# 21. 开发计划与交付门禁

## 21.1 推荐批次

1. 基础架构、数据库迁移、认证、权限、配置、文件上传。
2. 用户资料、陪玩申请、审核和公开主页。
3. 服务、SKU、审核、上下架和搜索。
4. 首页、收藏、消息和文字聊天。
5. 订单报价、创建、状态机和订单详情。
6. 正式/沙箱支付、回调、支付结果和对账。
7. 退款、投诉、评价和管理员处理。
8. 收益、佣金、提现和财务后台。
9. 全页面状态、视觉回归、性能和安全测试。
10. 全链路预发布演练与数据核对。

## 21.2 Definition of Done

一个功能只有同时满足以下条件才算完成：

- UI 正常态和异常态齐全。
- 接口契约冻结并有权限校验。
- 数据库迁移、索引和约束完成。
- 核心日志、埋点和告警完成。
- 单元/集成/E2E 测试通过。
- 买家、陪玩、后台显示同一业务状态。
- 产品和测试按验收标准签字。

# 22. 风险与待确认事项

以下项目在研发冻结前需要明确，但不影响本文整体架构：

1. 正式支付主体、支付渠道和平台代收/分账合规方案。
2. 陪玩服务类目的经营资质、未成年人保护和平台协议。
3. 收益结算等待期、退款后收益冲正规则。
4. 提现账户类型、手续费和审核流程。
5. 优惠券已确认不纳入第一阶段真实功能：保留入口和“0 张可用”占位，不建立优惠券业务、接口、数据库表或订单优惠计算。
6. 陪玩资料和服务修改后哪些字段需要重新审核。
7. 待接单是否设置自动退款时限，或仅提醒陪玩处理。
8. 自动确认完成的具体默认时间。
9. 评价是否允许买家在一定时间内修改，以及匿名展示规则。
10. 后台聊天取证的权限范围和隐私留痕规则。

# 23. 最终范围声明

第一阶段完成后，熊崽电竞必须是可以真实测试完整业务逻辑的《和平精英》C2C 游戏陪玩交易平台，而不是仅可点击的 UI Demo。

平台必须做到：

- 买家能够发现、搜索、咨询、购买、支付、履约、售后和评价。
- 陪玩能够申请、经营主页、发布服务、处理订单、获得收益和提现。
- 管理员能够审核、治理、查询、处理售后、管理财务和配置平台。
- 服务端、数据库、文件存储和管理后台与 App 每个核心功能一一对应。
- 用户、陪玩、管理员看到的是同一服务、同一订单、同一支付和同一售后事实。

**最终产品定位：让个人陪玩能够被看见、被搜索、被咨询、被购买，并通过稳定履约获得长期客户。**
