# 熊崽电竞管理员后台发布与回滚手册 V1.0

## 1. 发布原则

发布必须使用可追踪的不可变应用产物和明确版本号。应用启动不会自动执行数据库迁移；迁移、应用发布和流量切换是三个独立审批动作。测试服务器与生产必须使用不同数据库、Bucket、密钥、域名和 Provider 账号，禁止把测试连接串改名后用于生产。

## 2. 发布前

1. 冻结待发布提交并保存 `git status`、版本号和构建来源，不覆盖工作区修改。
2. 在本地隔离依赖执行 `pnpm admin:preprod`；任何失败、skip、临时 Schema 或测试对象残留都阻止发布。
3. 审批配置清单，只比较键名和来源，不把 Secret 值放入工单或日志。
4. 对目标数据库做一致性备份并验证可恢复性，记录备份标识、时间、RPO/RTO 和责任人。
5. 使用只读账号执行 `MIGRATION_STATUS_ALLOW_EXTERNAL=1 pnpm db:migration:status`。该命令不执行迁移；目标状态不匹配则阻止发布。
6. 审核每个迁移 SQL 的锁范围、预计耗时、可逆性和向前/向后兼容窗口。不可逆迁移必须有已验证的恢复或前向修复方案。
7. 确认代理、TLS、CORS、可信代理、Cookie、限速、监控和回调白名单已配置。

## 3. 迁移顺序

仓库迁移严格按 `packages/database/migrations/meta/_journal.json` 的索引顺序执行。只允许经审批的部署作业显式运行迁移，不允许 API、Worker 或 Scheduler 启动时静默执行。建议顺序为：停止不兼容写入或启用兼容窗口 → 数据库备份 → 单一迁移执行者应用迁移 → 只读状态复核 → 部署兼容的新应用 → ready 后逐步切流。

## 4. 应用发布

1. 先部署一个不接流量实例，确认进程非零失败语义、`/health/live` 和 `/health/ready`。
2. 验证结构化日志有服务、时间、route、status、duration、request ID、trace ID 和脱敏 actor，且没有密码、TOTP、Token、Cookie、连接串、对象键、预签名 URL、手机号、实名或收款账户明文。
3. 小比例切流，复验管理员登录/TOTP、权限拒绝、关键只读列表、文件 200/206/416 和任务积压。
4. 逐批替换旧实例，每批等待 ready。停止旧实例前先摘流量并等待活动请求结束；确认数据库连接、文件流和本进程预览租约释放。
5. 观察错误率、延迟、数据库连接/锁、Outbox/Scheduler 积压、对象存储失败、429 和资金幂等指标后才完成发布。

## 5. 应用回滚

当新版本在数据库仍向后兼容时：停止继续扩流 → 摘除新实例 → 部署上一个已验证的不可变应用产物 → 等待 ready → 小流量验证 → 恢复流量。不得用 `git reset`、`git checkout` 或“回退代码文件”替代产物回滚，也不得在脏工作区临时重建未知版本。

回滚期间暂停可能产生不兼容写入的 Worker/Scheduler；恢复后检查 Outbox 陈旧 PROCESSING 恢复、有限重试和幂等键，确认重复回调/重复消费没有重复资金副作用。

## 6. 数据库无法回滚时

禁止把 Git 回滚描述为数据库恢复。若迁移不可逆或旧应用不兼容新 Schema，只能选择：

- 部署与新 Schema 兼容的前一个应用变体；
- 编写并审批前向修复迁移；
- 在明确停机、数据损失边界和负责人审批后，从已验证备份恢复到独立目标，再核对后切换。

任何恢复都先保留故障数据库用于取证，不直接覆盖唯一副本。恢复后必须核对资金账本、支付/退款/打款幂等表、Outbox、任务状态、文件数据库指针与对象存储，不通过核对不得恢复写流量。

## 7. 回滚完成判定

- 应用版本、配置版本和数据库迁移状态均有记录。
- live/ready、管理员登录/MFA/RBAC、核心列表和文件预览正常。
- 没有新增重复资金副作用、永久卡住任务、泄露日志或测试数据残留。
- 监控恢复到审批阈值并完成事故记录；后续修复重新走完整 `admin:preprod`，不得绕过门禁。

## 8. 当前未具备的外部条件

本手册不授权实际部署。服务器、域名/TLS、代理、隔离数据库/对象存储、Secret Manager、真实短信/资金 Provider、EventPublisher、监控告警和备份恢复方案未提供前，只能完成本地部署准备和自动化验收。
