## 本轮实现与根因

App 今日经营数据原来明确显示“—”，现有 seller/overview 只有累计状态数量和资金摘要；finance/summary 是资金余额，不能用作营业额。PRD V3.6 §16.4、D11 明确允许本地继续按创建时间统计，因此无需等待正式支付时间口径冻结即可补齐兼容读接口。

聚合按认证主体派生 seller_id，使用 orders_seller_created_idx 所覆盖的店铺/时间筛选；不联接 payments，避免重复支付尝试放大金额。SQL SUM 保持 numeric 精度，计数和金额转 text 后返回，不经过 JavaScript number。退款仅展示订单事实中的累计成功退款，不扣原营业额；真实退款回调重放测试验证只增加一次。

其他真实缺口：新订单基础退款已有实现，但不能把它称作完整 V3.1 两轮方案、补充履约、平台裁决与两级申诉闭环。本轮未扩建此领域，保留明确禁用能力，不伪造完整实现。

根测试装配修复：VM 抽取页面函数后缺少新拆分的 MineOrderStrip、HomeAnnouncementCarousel 导入，导致 ReferenceError。现加载真实子组件源码，保留原有行为断言；订单入口测试改为检查真实组件的传入 children，并补充 SSR 容器断言，避免仍假定其为父函数内联 DOM。没有用空组件消除这些失败。

剩余一项根测试要求“我的”仍能进入平台客服，而当前页面已移除该按钮。PRD V3.6 §15.3 仍列双方“我的”客服入口，另一个客户端任务的测试则已改为客服移到聊天列表。此处存在待核对的产品基线差异，本轮不修改页面，也不删除客服可达性断言来宣称通过。

## API 与客户端交接

新增：`GET /api/v1/seller/finance/business-statistics?period=TODAY`。

- period：TODAY / YESTERDAY / WEEK / MONTH / YEAR / ALL；省略默认 TODAY。
- 本人店铺，不接受 seller_id、用户 ID 或自定义角色等额外参数。
- 同时供首页和经营统计使用；客户端不要各算一套，也不要使用 finance/summary 代替。
- TODAY/WEEK/MONTH/YEAR 截止当前服务端查询时刻；YESTERDAY 为完整昨日；ALL 起点为 null；左闭右开。
- 钱和数量均为十进制字符串，金额单位分。查询失败显示失败，不显示 0；无记录才返回真实 0。
- Cache-Control: no-store, private；沿用用户认证与 Session 校验。
- 复用错误格式：未登录 401；无店铺 SELLER_NOT_FOUND / 404；非法周期及额外参数 VALIDATION_FAILED / 400。无新增业务错误码。
- 不改变现有 Web Cookie、App Bearer、管理员 MFA/RBAC、财务汇总或提现接口。后台不调用此接口代替全平台报表。

示例（合成数据，仅表示结构）：

```json
{
  "period": "TODAY",
  "timezone": "Asia/Shanghai",
  "attribution": "ORDER_CREATED_AT",
  "scope": "按北京时间订单创建时间归属周期；营业额为其中已付款订单累计实付，成功退款另列，不扣佣金或退款；不是可提现余额。正式统计口径待 D11 冻结。",
  "start_at": "2026-10-29T16:00:00.000Z",
  "end_at_exclusive": "2026-10-30T04:00:00.000Z",
  "server_time": "2026-10-30T04:00:00.000Z",
  "created_order_count": "3",
  "paid_order_count": "2",
  "paid_amount_cent": "40000",
  "refunded_amount_cent": "100"
}
```

新的共享契约为 SellerBusinessPeriod、sellerBusinessPeriods、SellerBusinessStatistics。配置、Schema、迁移变更：无。实际页面接入由客户端任务完成，本轮没有替客户端修改文件。

## 测试方法与限制

数据库和 E2E 使用本地专用测试库与随机隔离 Schema。统计新用例通过现有真实建单、付款、退款 API 检查结果，没有直接改订单支付/退款状态来制造成功。日期单元测试覆盖北京跨日、周一、周日、月初、年初、闰年昨日和 ALL。

既有集成套件中有隔离夹具直接构造账务或调整时间用于边界测试，stage-one 亦使用注入存储和已审核文件夹具；这些是分层自动化，不算真实上传审核或人工判责验收。API 套件包含独立真实本地 MinIO 合成媒体上传、校验和审核契约测试，但未把它们拼称为一个完整真机交易。

测试 after/finally 清理自身随机 Schema 和精确对象，未删除其他任务资源。结束后只读查询确认 stage_one 前缀 Schema 数为 0、PostgreSQL 16.13；未做全部 MinIO 对象归零审计，部分旧清理钩子吞掉删除异常，不能据测试通过承诺全部对象已删除。未做开发业务数据测试前后完整指纹对比；本轮业务测试不以开发库为目标。
