熊崽电竞｜后端开发十步提示词
================================

使用方法：每次只复制一步发给 Codex。当前一步全部完成并通过测试后，再发送下一步。


第一步：真实 PostgreSQL 落库验证
--------------------------------

请执行熊崽电竞数据库落库验证。

当前项目目录是 /Applications/c2c游戏服务软件。

请先阅读：
1. docs/数据库设计-V1.0.md
2. packages/database/README.md
3. packages/database/src/schema.ts
4. packages/database/migrations
5. docs/熊崽电竞-技术架构设计-V1.0.md

目标：
1. 检查当前环境是否已经配置 DATABASE_URL 和 TEST_DATABASE_URL，但不要输出密码或完整连接串。
2. 如果已经配置，连接 PostgreSQL 16 测试数据库执行全部迁移和集成测试。
3. 验证 62 个 Enum、67 张表、btree_gist 扩展、外键、索引、部分唯一索引、预约 GiST 排斥约束和延迟触发器。
4. 执行 packages/database 下全部测试，确保 PostgreSQL 集成测试不再跳过。
5. 验证迁移重复执行安全、Drizzle Schema 与迁移无漂移。
6. 不连接或修改生产数据库，不插入生产演示数据。
7. 如果缺少 PostgreSQL 或连接配置，明确告诉我需要提供什么，并给出最短配置步骤，不要擅自安装云服务或创建付费资源。

完成后请报告：
- 实际执行了哪些迁移
- 数据库版本
- 表和 Enum 数量
- 测试通过、失败、跳过数量
- 发现并修复的问题
- 下一阶段是否可以开始

请直接检查和执行，不要只给方案。


第二步：搭建后端 API 基础设施
------------------------------

请开始熊崽电竞后端 API 基础设施阶段。

请先阅读 PRD、技术架构设计、docs/数据库设计-V1.0.md，以及现有用户端和管理后台 UI。严格遵循现有技术架构，不重新设计 UI。

目标：
1. 按技术架构建立 API 服务、Worker 和 Scheduler 的基础目录。
2. 接入 @xiongzai/database，不重复定义数据库表。
3. 建立配置校验、数据库连接池、事务封装、统一错误码、日志、trace_id、request_id。
4. 建立用户端认证中间件、管理员认证中间件、RBAC 权限检查。
5. 建立请求参数校验、游标分页、bigint 金额序列化、UTC 时间序列化。
6. 建立 idempotency_keys、outbox_events、inbox_events、scheduled_jobs 的公共基础设施。
7. 建立健康检查和数据库就绪检查。
8. 提供测试环境配置，不写生产 Seed。
9. 不实现具体业务模块，不修改现有 UI 视觉。

验收：
- API 服务可以启动
- 健康检查通过
- 可以连接 PostgreSQL
- 事务回滚测试通过
- BigInt 不被转换为浮点数
- 鉴权、错误响应和日志格式有测试
- Outbox 与业务事务同提交有测试
- 类型检查、构建和全部现有测试通过

请直接实现、测试并报告修改文件和测试结果。


第三步：登录、用户、隐私和实名认证
----------------------------------

请实现熊崽电竞身份与用户模块。

请基于现有 users、user_profiles、identity_verifications、auth_sessions、sms_codes、user_devices、privacy_settings、policy_versions、user_policy_acceptances 表实现。

范围：
1. 手机号验证码发送和登录接口，开发环境使用可替换的短信 Provider，不接入真实付费渠道。
2. Access Token、Refresh Token、退出登录、会话撤销和过期处理。
3. 用户资料查询和修改。
4. 隐私设置查询和修改。
5. 协议版本查询、接受记录。
6. 实名认证提交、状态查询和后台审核基础接口。
7. 手机号、姓名、证件信息使用应用层加密、HMAC 查询哈希和脱敏值。
8. 日志和响应禁止出现验证码、Token、手机号、证件号明文。
9. 所有核心更新使用 version 乐观锁。
10. 将现有用户端登录、个人中心、设置、实名认证页面接入真实 API，但不改变 UI 视觉。

测试：
- 验证码过期、重复使用和错误次数
- 手机号哈希唯一
- Refresh Token 轮换和撤销
- 隐私设置乐观锁
- 实名敏感数据不泄漏
- 未登录和封禁用户访问控制
- 用户端现有测试继续通过

请直接实现并给出接口清单、测试结果和下一阶段建议。


第四步：陪玩入驻、审核和服务商品
--------------------------------

请实现熊崽电竞陪玩与服务商品模块。

范围：
1. 陪玩资料创建、查询和修改。
2. 陪玩入驻申请，每次提交创建不可变 seller_applications 版本快照。
3. 管理后台入驻审核、补充资料、通过、拒绝、暂停、恢复。
4. 服务创建、修改、提交审核、上下架。
5. 每次服务提交创建不可变 product_versions。
6. SKU 时长、价格和状态管理。
7. 服务图片上传引用和排序。
8. 陪玩可用时间段管理。
9. 陪玩和服务收藏、取消收藏。
10. 服务列表、筛选、详情和游标分页。
11. 后台每次审核写审核日志和管理员操作审计。
12. 接入现有用户端服务列表、服务详情、陪玩中心和后台审核 UI，不修改视觉样式。

约束：
- 金额使用 bigint 分
- 不实现优惠券
- 不实现复杂推荐和循环预约
- 审核历史禁止覆盖
- 已删除或下架服务不能下单

请补齐接口测试、权限测试、审核版本测试、收藏唯一性测试，并报告结果。


第五步：订单、预约锁定和支付
----------------------------

请实现熊崽电竞订单、预约和支付核心链路。

范围：
1. 创建订单预览和正式创建订单。
2. 一个订单只能购买一个 SKU，可通过 quantity 购买多份。
3. 创建订单时保存商品、图片、陪玩、SKU、价格、佣金和预约时间完整快照。
4. discount_cent 必须保持 0，不实现优惠券。
5. 创建限时 order_slot_reservations 预约占用。
6. 使用数据库排斥约束处理陪玩时间冲突。
7. 支付单创建、支付状态查询、支付回调接口。
8. 支付渠道使用抽象 Provider 和测试 Mock，不绑定具体支付商。
9. 支付超时关单、接单超时、自动确认使用 scheduled_jobs。
10. 订单取消、拒单或关闭时释放预约。
11. 订单状态、支付状态、售后状态独立维护。
12. 所有状态更新使用 id + current_status + version CAS。
13. 业务事务同时写状态日志和 Outbox。
14. 接入现有用户端确认订单、支付结果、订单列表、订单详情，以及陪玩端接单页面。

必须测试：
- 两个请求争抢同一陪玩时段
- 重复创建订单幂等
- 重复支付回调幂等
- 支付金额与订单金额不一致
- 买卖双方相同
- 超时关单和预约释放
- 状态机非法跳转
- BigInt 金额序列化

请直接实现完整链路并报告接口、事务边界和测试结果。

第七步：退款、投诉和评价
------------------------

请实现熊崽电竞售后、退款、投诉和评价模块。

范围：
1. 发起退款、陪玩处理、平台介入、渠道退款和退款完成。
2. 允许多次历史部分退款，但同一时刻只能存在一个有效退款流程。
3. 原子维护订单累计退款金额，禁止超过实付金额。
4. 重复退款回调必须幂等。
5. 投诉创建、证据上传、客服受理、补充证据和结案。
6. 投诉、退款的每次状态变化都写不可修改日志。
7. 订单完成后提交一次评价。
8. 评价不可编辑，隐藏后不能重新评价。
9. 评价隐藏或恢复时重新计算 rating_aggregates。
10. 接入用户端售后、投诉、评价页面和后台售后处理页面。

测试：
- 两次部分退款
- 并发退款申请
- 累计退款超过实付
- 重复渠道退款回调
- 评价订单唯一
- 评分必须为 1–5
- 隐藏评价后的评分重算
- 管理员处理审计

请直接实现并报告状态机、接口和测试结果。


第八步：复式账务、收益、欠款、提现和对账
----------------------------------------

请实现熊崽电竞财务模块。

这是高风险模块，请严格使用现有 ledger_accounts、ledger_transactions、ledger_entries、seller_incomes、seller_liabilities、seller_liability_allocations、payout_accounts、withdrawals、withdrawal_income_allocations、withdrawal_logs、reconciliation_runs、reconciliation_items。

范围：
1. 订单完成、收益待结算、收益可用的复式账务。
2. 退款、提现锁定、提现完成、提现失败释放的复式账务。
3. 每笔已入账交易借贷必须平衡。
4. 分录禁止修改和删除，冲正必须创建新反向事务。
5. 每个订单只创建一条主收益。
6. 提现按 available_at 和 id 顺序 FIFO 锁定收益。
7. 两个提现请求不能争抢同一份收益。
8. 收款账户密文、查询哈希、脱敏值及默认账户唯一。
9. 已提现收益退款时创建陪玩欠款。
10. 欠款按后续可用收益顺序抵扣。
11. 有高风险事件或有效欠款时暂停提现。
12. 渠道提现使用抽象 Provider 和测试 Mock。
13. 实现对账批次、对账明细和差异处理。
14. 接入陪玩端收益、提现、收款账户页面和后台财务页面。

必须提供：
- 每种业务事件的借贷模板
- 借贷平衡测试
- 并发提现测试
- 提现失败和冲正测试
- 已提现订单退款测试
- 欠款抵扣测试
- 对账差异测试
- 金额全程 bigint 验证

请直接实现，不要用修改历史账务记录的方式修复差错。

十步工作类型说明
================

这些步骤不全是单纯写代码：

第一步：环境配置、数据库迁移和实库测试，少量修复代码。
第二步：主要是后端基础代码和基础测试。
第三至第九步：主要是业务代码、数据库事务、API、前后端接入和自动化测试。
第十步：主要是联调、E2E 测试、安全检查、性能检查、部署和上线文档，可能包含必要修复代码。

推荐严格按顺序完成，不要同时开发十步。
