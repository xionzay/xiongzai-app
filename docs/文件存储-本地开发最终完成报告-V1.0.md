## 3. 已冻结的架构

### 3.1 对象存储提供商

V1 配置值冻结为：

- `disabled`：未启用对象存储，其他 API 可运行，文件操作安全失败。
- `minio`：本地开发提供商，使用 S3 Signature V4。
- `aliyun-oss`：未来正式环境提供商，保留独立官方 SDK 适配边界；当前没有安装 SDK、连接账号或声称联调成功。
- `injected`：仅测试使用，不是部署环境配置。

业务服务只依赖 `ObjectStorageProvider` 的签名上传、HEAD、受限读取/流读取、签名下载、复制、删除和只读分页列举能力，不直接依赖 MinIO、R2 或 OSS 专有 API。Cloudflare R2 已停止采用。

### 3.2 Bucket 模型

| 配置 | 本地 Bucket | 冻结用途 | 匿名访问 |
| --- | --- | --- | --- |
| `FILE_QUARANTINE_BUCKET` | `xiongzai-dev-quarantine-media` | 所有新上传和被拒绝文件 | 关闭 |
| `FILE_PUBLIC_BUCKET` | `xiongzai-dev-public-media` | 审核通过的 `PUBLIC` 文件 | 关闭；当前仍使用短时访问 |
| `FILE_PRIVATE_BUCKET` | `xiongzai-dev-private-media` | 审核通过的 `SIGNED/PRIVATE` 文件 | 关闭 |

三个 Bucket 必须互不相同。新文件只能先进入 quarantine；审核通过后由服务端精确复制到 public 或 private；审核拒绝不能进入最终 Bucket。客户端不能提交或覆盖 Bucket、对象键和最终位置。

quarantine 的浏览器 CORS 只允许 `http://localhost:3001` 与 `http://127.0.0.1:3001`，方法为 PUT/GET/HEAD，请求头仅开放上传所需的 Content-Type、SHA-256 和大小元数据。不使用通配 Origin。

### 3.3 文件用途

冻结规范值如下：

| 用途 | 本地用户端核心接入 | 最终可见性 | 审核后 Bucket |
| --- | --- | --- | --- |
| `USER_AVATAR` | 完成 | PUBLIC | public |
| `SELLER_AVATAR` | 完成 | PUBLIC | public |
| `SELLER_COVER` | 完成 | PUBLIC | public |
| `PRODUCT_IMAGE` | 完成 | PUBLIC | public |
| `COMPLAINT_EVIDENCE` | 完成 | PRIVATE | private |
| `VOICE_SAMPLE` | 完成 | SIGNED | private |
| `ADMIN_EVIDENCE` | 服务端策略预留，当前用户端不交付 | PRIVATE | private |
| `PAYMENT_PAYLOAD` | 服务身份策略预留，当前用户端不交付 | PRIVATE | private |

阶段 8 任务文字中的 `SELLER_GALLERY` 对应现有规范值 `SELLER_COVER`。本阶段没有新增同义枚举，以免破坏数据库约束、API、客户端和历史审核数据。未来若需要真正的多图卖家图集，应作为新业务版本设计。

各用途均由服务端复核所有权、策略 MIME、大小、真实 MIME、图片尺寸或音频轨/时长、审核状态、可见性、最终位置与业务绑定资格。客户端预检只用于提前提示，不能替代服务端裁决。

## 4. 已冻结的接口

### 4.1 用户接口

- `GET /api/v1/files/policies`
- `POST /api/v1/files/uploads`
- `POST /api/v1/files/:fileId/complete`
- `GET /api/v1/me/files`

- `DELETE /api/v1/files/:fileId`
- `GET /api/v1/files/:fileId`
- `GET /api/v1/companions/:sellerId/voice`

### 4.2 管理接口

- `GET /admin-api/v1/files`
- `POST /admin-api/v1/files/uploads`
- `POST /admin-api/v1/files/:fileId/complete`
- `GET /admin-api/v1/files/:fileId/access`
- `GET /admin-api/v1/files/:fileId/preview`
- `POST /admin-api/v1/files/:fileId/moderation`

管理员文件访问继续要求 Cookie Session、MFA、CSRF Origin 和 RBAC。`file.read` 控制读取，`file.review` 控制预览和审核，`admin_log.read` 控制操作日志。管理员浏览器只获得安全元数据和同源二进制响应，不获得 MinIO Endpoint、Bucket、对象键或预签名 URL。

### 4.3 客户端安全边界

- 客户端不持有对象存储 AccessKey 或 Secret。
- 客户端不能决定 Bucket、对象键或公开/私有迁移。
- 预签名 URL 只在当前请求/页面内存中短暂使用，不写入数据库、日志、路由、localStorage 或 sessionStorage。
- PUT 只发送服务端指定上传头，不携带登录 Bearer。
- PUT 成功而 complete 暂时失败时只重试 complete，不重复 PUT。
- 上传恢复以服务端文件状态为事实，不复用过期 PUT 地址。

## 7. 上传恢复、幂等与生命周期

- PUT 成功、complete 暂时失败：只重试 complete，不重复 PUT。
- 页面退出或应用重开：通过本人文件列表恢复服务端状态，不持久化旧 PUT URL。
- 上传取消：取消信号传播；未成功 PUT 不调用 complete。
- 重复 complete：幂等。
- 重复或并发审核：只能一个成功，另一请求返回版本冲突；不会覆盖先成功结果。
- 客户端 Bucket/对象键参数：不参与服务端对象位置决定。
- 已绑定文件：活动 `file_usages` 阻止底层删除。
- 过期 `PENDING/UPLOADED`：事务内复核后按数据库精确位置清理。
- `VERIFIED`、已绑定或未知对象：不会被过期上传任务误删。
- 删除任务：支持不存在幂等、有界重试、稳定抖动和永久失败分类。
- 孤儿对象：默认只读、分页、有限量，报告只含计数和哈希标识；不按相似前缀删除未知对象。
