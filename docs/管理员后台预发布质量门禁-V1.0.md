# 熊崽电竞管理员后台预发布质量门禁 V1.0

## 1. 目的与边界

`pnpm admin:quality` 用于在本机对 `/admin`、`/admin-api/v1`、PostgreSQL、MinIO 和 Chrome 执行严格的预发布回归。命令不会部署、创建数据库、创建 Bucket、安装云资源、连接外部服务、调用真实短信/支付/退款/打款，也不会修改生产配置。

质量门禁通过只代表当前代码在本地隔离环境满足自动化检查，不代表生产发布、真实云存储、真实资金渠道、反向代理、容量或安全验收完成。

## 2. 运行方法与本地依赖

```bash
pnpm admin:quality
```

需要：

- Node.js 22.13 或更高版本与仓库锁定的 pnpm。
- 本机 Google Chrome；非标准路径可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 告知预检，但 Playwright 的 Chrome channel 仍必须可启动。
- `.env.backend.local` 中的 `TEST_DATABASE_URL`，且主机必须为 `localhost`、`127.x.x.x` 或 `::1`。
- `.env.minio.local`/`.env.backend.local` 中的 `FILE_STORAGE_ENDPOINT`、`FILE_STORAGE_REGION`、`FILE_STORAGE_ACCESS_KEY_ID`、`FILE_STORAGE_SECRET_ACCESS_KEY`、`FILE_PUBLIC_BUCKET`、`FILE_PRIVATE_BUCKET`、`FILE_QUARANTINE_BUCKET`；Endpoint 必须为回环地址。
- 已启动且可达的本地 PostgreSQL 和 MinIO，三个测试 Bucket 已按本地开发说明配置。

预检只输出缺失或无效的配置键名，不输出连接串、Access Key、Secret、Bucket 对象键或其他值。依赖不可达会在执行测试前失败，不会自动连接云服务替代。

## 3. 串行门禁步骤

命令按顺序执行：

1. 根前端生产构建。
2. 根 TypeScript 检查。
3. 全工作区 `typecheck`。
4. 后端与工作区包构建。
5. 管理员契约/SSR、质量门禁及真实角色组件行为测试（`tests/admin-rbac-behavior.test.mjs`）。
6. 管理员 Playwright 真实浏览器 E2E。
7. 管理员治理 PostgreSQL 集成。
8. 财务 PostgreSQL 集成。
9. 商家商品集成。
10. 售后与客服集成。
11. 文件单元测试。
12. 文件 PostgreSQL + MinIO 集成。
13. 管理员查询性能测试。
14. 管理员相关定向 ESLint。
15. `git diff --check`。

任一步骤返回非零后立即停止，整体返回非零。`scripts/admin-quality.mjs` 的单元测试还验证了环境值不泄漏、外部地址拒绝、依赖不可达不运行命令，以及第一步失败后后续步骤不会执行。

## 4. 测试类型必须区分

- `[real backend E2E]`：本机 Chrome 打开真实 `/admin`，使用随机管理员密码、真实 TOTP、HttpOnly Cookie、随机 PostgreSQL Schema、随机 API 端口、本地 Mock Payment/Payout Provider 和本地 MinIO。业务写操作真正进入 Service 与数据库事务。
- `[browser mock errors]`：只在浏览器层拦截请求，用于稳定构造 5xx、离线、空数据、详情 403/404、409 和延迟响应。它验证页面状态机，不代表相应后端失败已经真实发生。
- API 集成测试：通过 Fastify 注入调用真实 Service 和隔离 PostgreSQL；文件测试还会真实访问本地 MinIO。
- SSR/源码契约测试：验证服务端渲染、权限显示和源码约束，不等同于浏览器 E2E。
- 人工浏览器检查：用于视觉、交互和辅助功能抽查，不替代自动化，也不被记录为生产验收。

测试产物目录 `test-results/`、`playwright-report/`、`blob-report/` 和 `playwright/.auth/` 继续由 Git 忽略。默认关闭截图、视频和 Trace，避免随机密码、TOTP 流程或管理员身份进入产物。

## 5. 危险运营操作覆盖

真实浏览器 E2E 覆盖：

- 陪玩申请批准，以及另一管理员先驳回后陈旧批准请求返回 409并刷新最终状态。
- 服务批准/驳回；延迟真实响应期间无成功提示、提交按钮禁用且强制二次点击不产生第二个写请求。
- 退款批准/拒绝；超过申请或剩余实付金额被拒绝；重复处理返回 409；Mock Payment Provider 不连接真实渠道。
- 投诉受理、开始处理、完成；陈旧版本返回 409；原因进入审计。
- 客服接入、真实消息回复、转交、再次接入和关闭；消息从服务端消息接口重新读取，前端不生成聊天记录。
- 提现脱敏详情、批准、驳回；驳回事务释放锁定收益且不调用 Payout Provider；并发/陈旧审批由财务集成测试验证只产生一次 Provider 副作用。
- 风险详情、结案、重复结案冲突和原因审计。
- 配置 v2 发布、旧 v1 ACTIVE 退休、唯一 ACTIVE 和发布原因审计。
- 只读运营角色可以查看事实，但看不到危险按钮；直接手工 POST 返回 403。未完成 TOTP 时尚未获得管理员业务 Session。

## 6. 文件流式预览与限流

管理员预览已真正改为支持背压的流式代理：MinIO/Web Stream 转 Node Stream，通过有字节上限的 pipeline 发送给 Fastify。图片返回 200；单段音频 Range 返回 206；非法或越界 Range 返回 416。服务端验证安全 MIME、20 MiB 最大声明、响应长度、总大小与范围，设置 `no-store`、`nosniff`、安全 `Content-Disposition`、`Accept-Ranges` 和 `Content-Range`，且不向页面返回 Bucket、对象键、Endpoint 或预签名 URL。

默认 `InMemoryPreviewConcurrencyLimiter` 的上限为 4，只在单进程有效。测试覆盖前 4 个流进入、第 5 个 429、正常结束释放、存储失败释放、流销毁/客户端断开释放与后续可再次进入。未来多实例需要替换 `PreviewConcurrencyLimiter`，本版本未连接 Redis，也不能把每实例 4 个描述为全局 4 个。

## 7. 隔离与清理

每次管理员 E2E 创建 `xiongzai_admin_browser_<随机值>` Schema，只运行仓库迁移并写合成数据。文件只写入本次唯一精确对象位置。全局 teardown：

1. 从本次 Schema 读取当前文件精确位置。
2. 关闭本次 API。
3. 只删除当前位置和本次原始位置，逐个 HEAD 断言对象已不存在。
4. 删除本次随机 Schema，并查询 `pg_namespace` 断言数量为 0。

不使用 Bucket 全量清空、通配删除或未知对象清理。初始化失败也按已记录的精确位置尽力清理。一次完整 E2E 后额外只读查询确认 `xiongzai_admin_browser_%` 临时 Schema 数量为 0。

## 8. 跳过与失败语义

- `admin:quality` 预检缺少 PostgreSQL、MinIO 或 Chrome时直接失败，不进入会因环境缺失而 `skip` 的测试。
- 单独运行测试文件时，如果测试自身显示 `skipped`，必须在报告中列为跳过，不得计入通过。
- 命令启动失败、断言失败、清理验证失败、ESLint 错误、构建错误和 `git diff --check` 错误均为门禁失败。
- 已执行但失败的命令必须记录为失败；修正后重跑通过时，可同时保留首次失败原因用于审计。

## 9. 上线前人工检查清单

- 在生产等价反向代理后验证 HttpOnly/SameSite/Secure Cookie、CORS、200/206/416、断连取消和安全响应头。
- 使用脱敏的生产等价数据验证慢查询、索引膨胀、autovacuum、连接池、长稳态内存与并发资源占用。
- 评审多实例全局预览限流方案；在此之前按“每实例最多 4 个”容量计算。
- 完成真实 OSS SDK、RAM 最小权限、Bucket/CORS/生命周期、恶意文件扫描和密钥轮换验收。
- 完成真实支付、退款、打款、短信供应商的沙箱/签名/回调/幂等/对账验收；不得用本地 Mock 结果替代。
- 抽查所有危险操作的 RBAC、MFA、理由、审计、版本冲突和双击保护。
- 检查浏览器 URL、localStorage/sessionStorage、控制台、服务日志和测试产物没有敏感信息。
- 由业务、财务、安全、运维共同审批生产发布与回滚方案；本门禁不会自动发布。

## 10. 第五阶段 `admin:preprod`

`pnpm admin:preprod` 是部署测试服务器前的更严格门禁。它先执行完整 `admin:quality`，再串行执行部署配置与 Mock 防误用契约、前后端生产构建产物启动/关闭、生产前端真实 Chrome E2E、迁移产物一致性、文件流稳定性、Scheduler/Outbox 恢复与有限重试、敏感日志扫描、临时 Schema/本地测试 Bucket 只读残留审计、定向 ESLint 和 `git diff --check`。任一步非零立即停止；本地 PostgreSQL、MinIO 或 Chrome 缺失时预检直接失败，不使用 `skip` 计为通过。

生产产物测试使用 `vinext build` 后的 `vinext start`，不是 `vinext dev`。API 测试启动 `apps/api/dist/main.js`，验证 `/health/live`、匿名 `/admin-api/v1/auth/session` 的 401、管理员接口 `no-store`、安全 request ID、受控关闭和配置错误非零退出。生产前端 Playwright 使用 `playwright.preprod.config.mjs`，真实登录、TOTP、HttpOnly Cookie、业务 API、文件 200/206/416 与清理流程继续复用隔离后端。

```bash
pnpm admin:preprod
pnpm db:migration:status
```

`db:migration:status` 只开启 PostgreSQL `READ ONLY` 事务并检查 `drizzle.__drizzle_migrations`，不会执行迁移。默认只允许回环地址；获批检查外部目标时必须显式设置 `MIGRATION_STATUS_ALLOW_EXTERNAL=1`，并使用只读数据库账号。门禁内部只检查仓库迁移产物完整性，不对本地或外部数据库自动写入。

门禁通过只证明本地隔离环境满足当前自动化契约，不是生产容量、真实 Provider、TLS、代理、云存储、备份恢复或线上发布已经验收。实际结果必须引用本次命令输出，不能沿用历史通过数。
