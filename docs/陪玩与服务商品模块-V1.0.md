# 熊崽电竞｜陪玩与服务商品模块 V1.0

## 1. 已实现范围

本模块复用 `@xiongzai/database` 既有 PostgreSQL 表，不重复定义 Schema。已实现陪玩资料、入驻版本快照、后台审核、服务商品、SKU、图片引用、可用时段、收藏和公开发现接口。

关键规则：

- 陪玩入驻前必须完成实名认证。
- 陪玩身份复用买家已有的 `users.id` 和登录 Session，不创建独立卖家账户或登录体系。
- 入驻提交前必须具备头像、介绍、段位、K/D、擅长模式、玩法、游戏经验和声音名片；媒体引用必须属于当前用户且已校验、已审核。
- 每次入驻提交新增一条 `seller_applications`，`snapshot_json` 不更新；管理员审核只更新该申请的流程字段，并追加 `seller_review_logs`。
- 每次服务提交新增一条 `product_versions`，快照同时包含商品、有效 SKU 和图片引用。
- 金额请求和响应均使用整数字符串分，例如 `"2500"`；服务端存储为 PostgreSQL `bigint`。
- 草稿、审核驳回和卖家下架状态允许编辑。审核中、在售、平台下架和已删除状态不允许直接编辑。
- 卖家下架后，服务立即从公开列表和详情接口消失。重新上架必须生成新版本并重新审核。
- 图片接口只接受归当前用户所有、上传已校验且内容审核通过的 `PRODUCT_IMAGE` 文件引用，不在本模块中重复实现文件上传。
- 开放可用时段不允许重叠，相邻时段允许；不实现循环预约。
- 收藏由数据库部分唯一索引兜底，重复收藏是幂等操作。
- 管理员审核同时写业务审核日志、`admin_operation_logs` 和 Outbox 事件。

## 2. 用户与公开接口

### 陪玩入驻

- `POST /api/v1/seller/profile`：创建陪玩资料
- `GET /api/v1/seller/profile`：查询自己的陪玩资料和最新申请
- `PATCH /api/v1/seller/profile`：使用 `version` 乐观锁修改资料
- `GET /api/v1/seller/overview`：仅限 `APPROVED` 陪玩，聚合真实服务数量、卖家订单数量和财务摘要
- `POST /api/v1/seller/applications`：提交不可变入驻快照
- `GET /api/v1/seller/applications`：查询历次申请

### 服务商品

- `POST /api/v1/seller/services`
- `GET /api/v1/seller/services`
- `GET /api/v1/seller/services/:productId`
- `PATCH /api/v1/seller/services/:productId`
- `POST /api/v1/seller/services/:productId/submit-review`
- `POST /api/v1/seller/services/:productId/off-sale`
- `DELETE /api/v1/seller/services/:productId?version=...`：软删除
- `POST /api/v1/seller/services/:productId/skus`
- `PATCH /api/v1/seller/services/:productId/skus/:skuId`
- `PUT /api/v1/seller/services/:productId/images`

### 可用时段与收藏

- `GET|POST /api/v1/seller/availability`
- `PATCH|DELETE /api/v1/seller/availability/:slotId`
- `GET /api/v1/favorites`
- `PUT|DELETE /api/v1/favorites/:targetType/:targetId`

### 公开发现

- `GET /api/v1/companions`
- `GET /api/v1/companions/:sellerId`
- `GET /api/v1/services`
- `GET /api/v1/services/:productId`

列表采用 HMAC 签名游标。公开接口只返回已审核陪玩和在售服务；服务详情只返回启用且未删除的 SKU。

## 3. 管理后台接口

- `GET /admin-api/v1/seller-applications`：权限 `seller_application.read`
- `POST /admin-api/v1/seller-applications/:applicationId/review`：权限 `seller_application.review`
- `POST /admin-api/v1/sellers/:sellerId/status`：权限 `seller.status.manage`
- `GET /admin-api/v1/product-reviews`：权限 `product.read`
- `POST /admin-api/v1/products/:productId/review`：权限 `product.review`

全部后台接口要求有效管理员数据库会话和 MFA。API 支持 Bearer Token，也支持未来后台登录模块设置的 `xiongzai_admin_access` HttpOnly Cookie。当前管理后台的审核列表和动作已经调用真实接口；在管理员认证模块尚未提供真实会话时，页面保留原有演示数据，不伪造数据库审核成功。

## 4. UI 接入

React Native 用户端已接入陪玩身份入口与完整申请状态、陪玩中心概览、主页管理、公开主页预览、接单状态切换、服务草稿、SKU 管理、提交审核、审核详情、下架和软删除。经营数据均来自真实接口；空库或接口失败时显示明确状态，不使用演示数据冒充服务端事实。

真实对象存储直传接口仍未实现。React Native 端明确阻断新申请媒体提交和新封面上传，不生成假 `file_id`，也不把本地路径当作服务端文件地址；已有且经服务端验证的文件引用会原样保留。

## 5. 明确未实现
