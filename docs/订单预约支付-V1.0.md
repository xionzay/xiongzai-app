# 熊崽电竞订单、预约与支付实现说明 V1.0

## 1. 实现范围

本阶段实现单 SKU 订单预览与创建、预约占用、支付单、支付回调、订单状态流转、超时任务以及买家/陪玩端现有页面的数据接入。订单金额使用 bigint 分，`discount_cent` 永远为 0，不包含优惠券逻辑。

生产超时与费率不写死在表结构或业务代码中。下列配置必须以 `platform_configs` 的 ACTIVE 版本启用：

- `order.payment_timeout_seconds`
- `order.accept_timeout_seconds`
- `order.auto_confirm_seconds`
- `finance.commission_rate_bps`

## 2. 用户端接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/orders/preview` | 校验商品、SKU、陪玩、可用时间并计算金额 |
| POST | `/api/v1/orders` | 使用 `Idempotency-Key` 创建订单和预约占用 |
| GET | `/api/v1/orders` | 买家订单游标分页 |
| GET | `/api/v1/orders/:orderId` | 买家或关联陪玩查看订单详情、支付和状态日志 |
| POST | `/api/v1/orders/:orderId/cancel` | 买家取消待付款订单 |
| POST | `/api/v1/orders/:orderId/confirm` | 买家确认服务完成 |
| GET | `/api/v1/companions/:sellerId/availability` | 查询陪玩未来开放的可预约区间 |

## 3. 陪玩端接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/seller/orders` | 陪玩订单游标分页 |
| GET | `/api/v1/seller/orders/:orderId` | 陪玩订单详情 |
| POST | `/api/v1/seller/orders/:orderId/accept` | 接单 |
| POST | `/api/v1/seller/orders/:orderId/reject` | 拒单并释放预约 |
| POST | `/api/v1/seller/orders/:orderId/start` | 开始服务 |
| POST | `/api/v1/seller/orders/:orderId/complete` | 提交完成并创建自动确认任务 |

## 4. 支付接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/payments` | 使用 `Idempotency-Key` 创建支付单 |
| GET | `/api/v1/payments/:paymentId` | 查询支付状态 |
| POST | `/callbacks/v1/payments/mock` | Mock Provider 签名回调；生产应替换 Provider |
| POST | `/api/v1/payments/:paymentId/mock-confirm` | 仅非生产 Mock 模式可用的测试支付确认 |

支付 Provider 只暴露创建支付、校验回调和渠道标识，业务服务不绑定微信、支付宝或其他具体渠道。生产环境禁止启用 Mock Provider。

## 5. 事务边界

创建订单在一个数据库事务中完成：幂等键占位、订单快照、预约占用、初始状态日志、付款超时任务、Outbox 事件和幂等响应。任一步失败全部回滚。`order_slot_reservations` 的 GiST 排斥约束是最终并发保护，同一陪玩的有效预约不能重叠。

支付成功回调在一个数据库事务中完成：支付事件去重、支付单 CAS、订单 CAS、预约 HELD 转 CONFIRMED、接单超时任务、订单日志和 Outbox。支付渠道调用本身不放在长事务中。

取消、接单、拒单、开始、完成和买家确认均锁定订单，并使用 `id + current_status + version` 更新。状态日志和 Outbox 与业务状态同事务提交。取消、拒单、付款超时、接单超时和最终完成都会释放预约。

## 6. 定时任务

- `ORDER_PAYMENT_TIMEOUT`：待付款订单到期后关闭订单与未完成支付单，并释放预约。
- `ORDER_ACCEPT_TIMEOUT`：已支付但陪玩未接单时关闭订单并释放预约；后续退款阶段消费该事件创建退款流程。
- `ORDER_AUTO_CONFIRM`：陪玩提交完成且买家超时未确认时自动完成订单并释放预约。

Scheduler 通过 `scheduled_jobs` 竞争领取任务，业务处理器本身可重复调用；状态 CAS 保证重复执行不产生第二次状态变化、日志或 Outbox。

## 7. UI 接入

用户端沿用原视觉样式，服务详情把真实商品与 SKU 传入规格页；预约页读取开放时间；确认订单页先预览再幂等创建；收银台使用 Mock Provider 完成开发支付；订单列表和详情读取真实订单。陪玩订单页读取真实订单，并将接单、开始和完成按钮连接到真实状态机接口。

当数据库没有真实业务数据时，现有展示数据仍保留为页面空环境预览，不会被提交到生产数据库。
