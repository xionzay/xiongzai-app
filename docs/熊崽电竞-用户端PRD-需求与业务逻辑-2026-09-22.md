# 熊崽电竞用户端 PRD：需求与业务逻辑

版本：2026-09-22 整理版。适用项目：`/Applications/c2c游戏服务软件`。覆盖买家端、同账号陪玩中心及其后台依赖。

**产品目标：让《和平精英》玩家找到可信陪玩，在平台内完成咨询、预约、支付、履约、售后、评价和复购；让通过审核的成年陪玩经营服务并获得透明结算。当前项目是本地测试产品，尚不能认定为生产上线完成。**

本文件整理现有需求，不授权新增业务开发。首页五入口已按本轮要求在 Web 用户端实施；其他问题在文内列为待完成。本次没有推送 GitHub、部署、修改数据库或接入付费渠道。

后续上传说明：用户随后明确要求上传 GitHub，本文件与首页改动一同纳入提交。文内“没有推送”是最初本地交付时的历史状态；没有新增部署或业务变更。链接到 `.local/`、`output/`、历史交接和未跟踪表格的部分资料仍为本机证据，不保证在 GitHub 网页上可打开。

### 1.2 完成状态定义

## 2. 产品范围与业务边界

### 2.1 首期范围

中国市场、单游戏《和平精英》、个人陪玩 C2C 交易。买家与陪玩共用账号，用户可以先购买服务，再申请陪玩身份。管理员认证、权限与操作平台独立。

包括：账号与协议、发现与搜索、陪玩/服务详情、收藏、声音名片、预约订单、测试支付、履约、退款投诉评价、文字消息、客服、站内通知、账户安全、陪玩申请、服务经营、收益、收款账户和测试提现。

商业资料要求服务为合规陪伴/组队/技术指导，禁止代练、代登、外挂、账号交易、色情、赌博和诈骗。现有“上分”等测试素材不能被解释为允许代登或包赢，需要后续统一商品内容标准和审核文案。

### 2.2 本轮新增首页入口的边界

| 顺序 | 四字名称 | 当前行为 | 业务状态 |
| --- | --- | --- | --- |
| 1 | 快速匹配 | 提示“功能筹备中” | 未开发匹配算法、排队或自动派单 |
| 2 | 领券中心 | 打开现有优惠券页面 | 0 张可用；领取、发券、核销、抵扣未开放 |
| 3 | 软件规则 | 打开现有平台规则与售后页面 | 静态规则说明已有，不等于资质认证或正式法律文本已发布 |
| 4 | 幸运转盘 | 提示“活动暂未开放” | 未开发抽奖、概率、奖池、次数、免单、后台发奖 |
| 5 | 官方通知 | 打开现有系统通知列表及详情 | 复用真实通知 API，不新增运营广播发布后台 |

只在推荐首页 Banner 下、热门陪玩上方一行五等分。入口正常显示，不虚构可领券数、中奖结果、未读红点。首页进入规则/优惠券返回首页；首页进入通知后，详情返回列表、列表返回首页；其他入口保留原返回关系。

### 2.3 本期不做与需要单独立项的内容

- 连续签到 30 天、50 元以内免单：曾讨论，后来最终五入口未包含签到，本轮不做。
- 快速匹配业务、转盘发奖、优惠券营销：本轮只做入口与真实未开放状态。
- 买家钱包/充值、银行卡、直播、语音房、实时语音/视频通话、多游戏：不在首期现有范围。
- 平台表情真实发送、聊天图片、聊天语音、自研 IM：历史扩展方向；现有表情 UI 是本地演示，仍需单独完成协议、存储、审核、收发及离线恢复。声音名片不等于语音消息。
- 真短信、真支付退款打款、生产云存储、系统推送、签名上架：生产发布工作，不得以本地 Mock 通过替代。

## 3. 角色、身份与权限

| 角色/状态 | 可执行行为 | 边界 |
| --- | --- | --- |
| 游客 | 浏览允许公开的陪玩、服务、规则 | 收藏、咨询、下单、私人通知等需登录；返回地址限站内 |
| 普通买家 | 购买、收藏、咨询、售后、评价、管理本人资料 | 不能发布服务，不能看其他人的订单、证据、实名、收款资料 |
| 陪玩申请人 | 填草稿、提交、查看审核、按要求补资料 | 审核未通过不能经营 |
| 已通过陪玩 | 管理本人主页/服务、接单履约、处理售后、查看收益提现 | 仍受服务审核、预约、风控、权限和版本校验 |
| 暂停/封禁陪玩 | 查看原因，按规则处理既有订单和历史记录 | 新接单和经营受限制；历史只读及既有履约权限须逐项落实 |
| 禁用/注销用户 | 根据状态展示受限或会话失效 | 不得仅隐藏按钮而继续允许 API 写入 |
| 管理员/客服/财务 | 按独立权限审核、处理工单和资金操作 | 不是用户端角色切换；MFA、资源权限、理由和审计独立检查 |

**成年准入需求**：陪玩年满 18 周岁且完成有效实名核验，服务端再次判断。当前入驻校验实名 VERIFIED，但缺可信成年结果及年龄准入闭环，列为上线前 P0。买家年龄、未成年人使用/消费规则需要另行冻结，不能把“陪玩 18+”自动扩展为已确定的买家策略。

陪玩中心最终入口放“设置”，不是买家底栏第五个 Tab，也不是中央发布加号。经营界面称“陪玩”，不用“店铺”。

## 4. 信息架构和导航

| 入口 | 核心页面 | 主要去向 |
| --- | --- | --- |
| 首页 | 推荐/陪玩/服务、搜索、Banner、五入口 | 陪玩主页、服务详情、搜索结果、规则、通知、优惠券 |
| 订单 | 买家订单列表、订单详情、支付/售后/评价状态 | 支付、联系陪玩、退款投诉、确认完成、评价 |
| 消息 | 系统通知、平台客服、最近会话 | 通知详情、客服工单、文字聊天 |
| 我的 | 头像昵称用户号、收藏、优惠券、资料与设置 | 编辑资料、隐私安全、规则、设置 |
| 设置 | 协议、安全、退出、陪玩申请/中心 | 入驻、审核状态、经营中心 |
| 陪玩中心 | 概览/服务/订单/收益四栏 | 主页、发布审核、履约、退款、账户、提现 |

主路径：发现 → 陪玩/服务 → 规格 → 预约 → 订单预览 → 创建订单 → 支付 → 陪玩接单 → 开始服务 → 完成服务 → 买家确认/规则允许的自动确认 → 评价 → 结算 → 提现。

售后从真实订单进入，关联订单、支付、退款、投诉、证据和处理记录。通知跳转必须携带实际目标 ID，再由服务端鉴权，不得打开“上次选中的订单”。

Web 为 `app/page.tsx` 的 PageId 状态导航，原生 App 为 `apps/mobile/app` 的 Expo Router 路由。桌面左侧六屏和“全部 MVP 页面”是设计检查入口，不是正式业务权限。两端必须独立验收。

## 6. 账号、协议和个人资料

### 6.1 登录与会话

手机号验证码登录，首次成功自动创建账号，再完善资料。验证码获取、有效期、发送间隔、错误次数由服务端控制；开发码仅用于本地测试。游客触发受限操作后登录，成功回到原业务路径；不无条件执行付款等高风险动作。

Web 使用 Cookie Session，原生 access token 在内存、refresh token 在安全存储。401 最多刷新重试一次；凭证失效、禁用、退出清理用户态和敏感缓存。临时网络失败不能直接等同账号注销。

昵称长度现有 PRD 写 2–20，部分实现为最大 16，需统一，不能同时对外承诺两个上限。新建表单不得预填假昵称、手机号或备注；编辑需区分未修改与显式清空。

### 6.2 协议

登录、支付、聊天、入驻、实名、声音公开上传、投诉各有确认场景。逐份展示版本与正文，不默认同意；加载失败禁止依赖该同意的动作。保存版本、场景、确认方式和时间，历史记录不可篡改。

当前存在协议中心/接受记录模型，但聊天与投诉场景业务门禁尚未完整落实。在线确认记录不称为第三方电子签约。“软件规则”现为静态说明页；正式版本化协议与法律文案另有发布流程，需要内容同步。

### 6.3 个人资料与账户生命周期

| 功能 | 需求与业务规则 | 当前主要边界 |
| --- | --- | --- |
| 编辑资料 | 头像、昵称、简介；版本冲突刷新并保留草稿 | Web 头像仍有演示；原生简介字段与实际输入区需对齐 |
| 公开主页 | 仅公开头像昵称、用户号、允许公开信息 | Web 有固定样例；不得暴露手机号、实名、订单、账户 |
| 实名认证 | 明确状态、单独确认、提交敏感信息后只回显脱敏值 | 当前人工审核，不是第三方真人核验；成年判断未补齐 |
| 隐私设置 | 在线状态、推荐偏好、公开主页；失败回滚 | 保存开关不等于复杂推荐算法已经使用该偏好 |
| 手机换绑 | 建申请→验旧号→验新号→完成→撤销旧会话并重登 | 后端和原生页面已存在；原生常规手机号入口仍跳实名页 |
| 数据导出 | 任务创建、生成、查询、受控下载、过期清理 | 当前导出账号/资料/隐私/协议子集，不是完整订单聊天财务副本；原生下载后缺打开/分享交付 |
| 注销 | 先资格检查、二次确认、等待期可撤销、到期重检后完成 | 原生二次确认未完整；注销主要变更状态和撤会话，不代表立刻物理删除全部交易记录 |

注销阻塞至少考虑进行中订单、退款投诉、提现、余额/欠款、相关审核任务。实际阻塞以服务端资格结果为准。等待期读取配置，不把测试期限写成正式规则。导出对象过期时间与短时下载链接有效期是不同概念。

## 7. 发现、陪玩、服务与收藏

### 7.1 首页与搜索

推荐区读取真实可公开陪玩和在售服务；陪玩频道支持综合/好评/销量，服务频道支持综合/销量/价格。在线状态、评分、销量和价格来自业务事实，不虚构人气。

搜索有陪玩/服务类型切换，关键词清空、提交、结果/空/失败状态；热词为真实可读 2–4 字业务词。已删除的声音偏好、按玩法找人过滤器不自动恢复。推荐排序不称为 AI 匹配。

目标是服务端搜索排序和分页；当前 Web 搜索对已加载集合过滤，结果页排序按钮只改状态、未排序 matching 结果；不能写成全库检索已完成。首页频道已有本地排序也不能等同全库排名。

### 7.2 陪玩主页

公开资料包含头像/封面、昵称、在线状态、段位/能力资料、标签、声音名片、服务、真实评分评价及完成订单摘要。段位/KD 自填与平台审核应明确，未接官方战绩 API，不能标“官方战绩认证”。

咨询进入该陪玩会话；收藏成功同步状态，失败回滚；声音通过短时授权地址试听，不将私有地址长期存储。点击服务进入所属真实服务详情。

### 7.3 服务与购买资格

服务包含封面、完整标题、说明、SKU、计费单位、时长、价格、预约说明、所属陪玩和评价。服务下架/审核中/拒绝、陪玩暂停/封禁、SKU 无效、时段失效、购买本人服务等要显示真实不可购原因并阻止提交。

收藏分陪玩和服务两类，重复操作不得重复建记录。已失效目标允许显示原因和取消收藏；不得拿固定样例替代失效目标。

## 8. 预约、订单与支付

### 8.1 下单流程

1. 买家选择真实有效 SKU，读取可预约日期/时段。
2. 客户端排除过期和已占用时段，提交时仍由服务端做最终冲突判定。
3. 调用订单预览重算价格、数量、服务时间、平台费及应付；本期优惠为 0。
4. 买家确认当前协议和订单内容，再带稳定 `Idempotency-Key` 创建订单。
5. 服务端在事务中验证角色、服务、SKU、价格、时段和业务配置，创建订单/预约占用与超时任务。
6. 再进入支付；超时或未知结果先查订单，不能重复创建另一个订单冒充重试。

当前后端为单 SKU×数量模型；原生结账数量固定 1，若要开放加减数量须补 UI 和验收。重要快照包括服务/陪玩/SKU说明与图片、单价、时长、佣金、协议版本，后续修改服务不能改变旧订单事实。

### 8.2 金额与佣金

金额以整数分传输，API 为十进制字符串，客户端使用 BigInt/定点运算。显示两位小数。

```text
商品金额 = SKU单价（分）×数量
优惠金额 = 0（当前版本）
应付金额 = 商品金额 - 优惠金额
平台费 = floor(商品金额 × 佣金bps / 10000)
陪玩收入 = 商品金额 - 平台费
```

商业目标佣金 10%，下单读取有效配置并保存快照。源码测试种子为 1000bps，不能证明当前运行库或正式运营已固定该值。25 元是商业计划的目标客单价，不是所有 SKU 的统一价格；在 10%示例中平台费 2.50 元、陪玩收入 22.50 元，尚未扣其他成本。退款会影响实际收入及账务。

### 8.3 支付

买家仅见微信、支付宝测试渠道，无银行卡/余额支付。需求是不默认选择渠道，未确认协议不可支付。本地必须写明不会真实扣款。

支付创建幂等、回调去重、金额/单号校验；客户端成功页以服务端事实为准。处理中应有限退避查询，前台恢复重查；失败、主动取消、订单关闭、查询超时分开展示。结果未知不能直接判支付失败或再次扣款。

原生有轮询/恢复实现但默认选择微信与需求冲突；Web 某些目录状态页使用定时跳转，不能当真实支付查询。真实支付 SDK、渠道验签、查单对账与资金恢复仍未接通。

### 8.4 订单状态与动作

| 服务端订单状态 | 含义 | 买家主要动作 | 陪玩主要动作 |
| --- | --- | --- | --- |
| PENDING_PAYMENT | 待付款 | 条件允许时支付/取消 | 无履约动作 |
| PENDING_ACCEPT | 已支付待接单 | 联系、按资格售后 | 接单/拒单 |
| ACCEPTED | 已接单待开始 | 查看预约、联系、按资格售后 | 到服务开始时间后才能开始 |
| IN_SERVICE | 服务中 | 联系、申请售后 | 完成服务 |
| PENDING_BUYER_CONFIRM | 待买家确认 | 确认完成、按资格售后 | 查看等待状态 |
| COMPLETED | 已完成 | 一次评价/查看评价、复购、按资格售后 | 查看收入和记录 |
| CANCELLED | 买家取消等取消结果 | 查看原因、重新选服务 | 查看记录 |
| CLOSED | 超时等关闭 | 查看原因；若已付款仍需明确退款处理 | 查看记录 |
| SELLER_REJECTED | 陪玩拒单 | 查看原因和售后处理 | 查看记录 |

动作以 `available_actions` / `seller_available_actions` 与服务端校验为准，状态变更使用 version/CAS。重复点击、旧页面提交返回冲突时先刷新，不覆盖新事实。

订单状态、支付状态、售后状态分别保存：售后为 NONE/IN_PROGRESS/RESOLVED；退款完成不能简单伪造一个数据库不存在的订单 REFUNDED 状态。待评价/已评价也是 COMPLETED 加评价事实的界面映射。

支付状态为 CREATED、PAYING、PAID、FAILED、CLOSED、REFUNDING、PARTIALLY_REFUNDED、REFUNDED。用户取消支付的 UI 状态不能与订单已取消混为一谈。

### 8.5 超时和争议

未付超时关闭订单/支付并释放预约；接单超时关闭并释放预约；待确认到期可触发完成和记账。但**当前拒单/接单超时未完整创建退款或人工处理工单**，关闭不能显示成“钱已退回”。

商业 V5.1 要求争议冻结结算，当前自动确认/收入解锁流程未形成完整争议冻结门禁。修复应建立人工待办、通知和冻结/恢复规则；不能因为原有自动任务存在就视为争议时也可以自动结算。

## 9. 退款、投诉、申诉与评价

### 9.1 最终经营目标与当前实现差异

较新商业计划要求前期全部退款和争议人工审核：关联订单 → 保全/暂停争议结算 → 双方举证 → 人工裁决 → 执行结果 → 申诉异人复核。

当前已有买家申请、陪玩同意/拒绝、平台介入、渠道回调和投诉记录，但陪玩同意退款可直接进入渠道执行；完整双方举证、申诉异人复核尚未完成。PRD 保留人工售后目标，把差异列为 P0，不将旧实现写成最终运营制度。

### 9.2 退款规则

- 根据真实订单、已付/已退/处理中金额预览可退上限；累计原路退款不超过实付。
- 支持历史多次部分退款，同时最多一个有效退款申请；并发以数据库约束和事务为准。
- 买家填写原因、金额和说明；提交携带幂等键。处理中不能反复创建相同退款。
- 陪玩答复及平台结论需记录原因、角色、时间和版本；拒绝应有可理解的后续路径。
- 渠道确认才显示退款完成；不以动画、陪玩同意或客服口头答复当到账。
- 撤销退款是原 PRD 的条件需求，当前不能仅因存在 CANCELLED 枚举便认定已有用户端撤销接口。

退款状态：REQUESTED → SELLER_APPROVED / SELLER_REJECTED / NEGOTIATING / PLATFORM_REVIEW → REFUND_PROCESSING → REFUNDED；REJECTED、CANCELLED 为其他终态。实际允许迁移需由服务端明确，枚举列表不是任意互跳许可。

### 9.3 投诉与证据

当前基本流程：关联对象/订单 → 问题类型与描述 → 私有证据上传、校验/审核 → 提交 → 处理日志 → 需要补证 → 补充 → 完成/关闭。

初次表单最多 6 份证据；后端追加与累计约束另行控制，数据库累计上限 20，不把累计上限当首次可选数量。当前 API 验证本人归属、正确用途、PRIVATE、VERIFIED、APPROVED。文件存在或上传进度 100%不等于可提交证据。

状态：SUBMITTED、ACCEPTED、PROCESSING、NEED_MORE_EVIDENCE、COMPLETED、CLOSED。证据不直接公开给交易对方；目标双方举证应分别授权、分别存档，避免泄露对方私有文件。

Web 当前投诉提交 `file_ids: []`，上传仍有提示演示；原生已有真实首次上传，补证详情未接通。商业计划提到录屏/对局等证据，不表示当前所有格式已可上传。界面“24 小时处理”“12 小时补证”等现有样例不能视为已确认客服 SLA。

### 9.4 重大违规三倍保障（经营方向，未上线）

只有严格人工核实、符合正式规则的重大违规才适用。商业 V5.1 的“三倍”为买家最终总额包含原退款：实付25元，原退款25元＋额外50元＝75元。普通迟到或主观不满意不自动适用。

额外部分应是公司自有准备金的独立赔付业务，与原订单退款、陪玩欠款分别建账，配套双人审批、额度预算、逐笔台账、反骗赔和追偿。当前未形成该系统；观察期、保障限额、证据标准、预算和正式公示待确定，不能把退款 API 上限直接改成三倍，也不能对外展示无条件已生效承诺。

### 9.5 评价

仅真实已完成且未评价订单可以提交一次 1–5 星评价，文字和匿名按规则提供。匿名不能暴露买家真实资料；公开列表只读允许公开的评价。状态 PENDING/PUBLIC/HIDDEN，治理隐藏/恢复影响聚合评分。用户端不能伪造二次评价或任意修改已提交记录。

## 10. 消息、官方通知与客服

### 10.1 文字会话

会话分咨询、订单、客服；服务端校验成员与资源归属。消息目前只支持 TEXT/SYSTEM，文字上限按当前接口为 500 字。发送使用稳定 client_message_id，重试同一意图不得换 ID 造成重复气泡；已读按真实序号更新。

目标要求加载历史、上翻保持位置、失败原位重试、前台接收同步、后台暂停、恢复补拉。原生已有前台 5 秒 HTTP 轮询；Web 当前主要初次读取和发送，接收轮询/可靠恢复仍需补齐。首期文字 MVP 不以 WebSocket 为唯一合格方案。

表情为独立内存演示：不写消息表、不影响未读、不代表对方收到，离页后消失。真实表情、图片、语音消息需新增服务端契约、文件用途/权限、内容审核、发送持久化和收件渲染。不得把表情 ID 当文字消息偷偷发送以宣称完成。

### 10.2 官方通知

本轮“官方通知”复用既有系统通知，分类仍为全部/订单/账户/平台，不另造只含营销公告的新列表。列表、详情、标已读、未读数应来自 API。

首页轮播安全公告与通知收件箱是两套内容：前者当前前端静态，后者持久化且鉴权。通用业务 Outbox 的 worker 当前使用 LoggingPublisher，不能推断所有订单/退款事件均已分发成站内通知。系统 APNs/FCM 推送仍未接入。

Web 通知详情“查看订单”尚未按 related_id 装载目标订单，需修复后才能认定业务深链完成。本次只验证列表/详情/返回路径，未把关联业务跳转列为通过。

### 10.3 平台客服

工单关联订单/退款/投诉或普通问题；状态 WAITING、SERVING、TRANSFERRED、CLOSED。支持人工接入、文字回复、转交、关闭及按规则重开。失败不能重复建多个工单。坐席在线、排队时长和首次响应必须有事实或明确预估依据，现有静态文案不作运营承诺。

## 11. 陪玩入驻、资料与服务经营

### 11.1 入驻

前置登录、协议、有效实名与成年准入。资料包括昵称、介绍、段位/KD/经验、模式标签、头像、封面、声音名片。头像和当前最终设计封面采用 1:1，原生某些封面 16:9 与此不一致，需修正。

申请状态：DRAFT → SUBMITTED → UNDER_REVIEW → APPROVED / REJECTED / NEEDS_SUPPLEMENT；补件后重新提交。陪玩身份状态另有 DRAFT/PENDING_REVIEW/APPROVED/REJECTED/SUSPENDED/BANNED，不将身份治理与单次申请审核混合。

公开资料修改生成待审草稿，审核期间保留上次通过版本。接单开关独立校验与保存，不能绕过审核。Web 部分申请状态仍是目录演示，不以路由名推断真实审核通过。

### 11.2 服务经营

可创建草稿、封面/图片、标题、说明、SKU、时长、计费单位与价格；至少一个有效 SKU 方可提审。审核通过才公开出售；下架、删除和改价不得改写历史订单快照。

服务状态：DRAFT、PENDING_REVIEW、ON_SALE、REVIEW_REJECTED、OFF_SALE、ADMIN_OFF_SALE、DELETED。前台管理四入口为出售中/审核中/已下架/草稿箱；驳回原因和平台下架需在对应记录中明确，不用随机示例替代。

Web 创建/提审已有 API，编辑、删除、审核意见仍存在静态与 Toast 演示；原生创建/编辑已有 API，但创建 SKU 时长固定 60 分钟、服务时间说明等字段未完整开放。必须区分“后端支持”与“用户能在页面设置”。

### 11.3 履约

陪玩查看购买方、服务快照、数量、预约时间和备注；接单/拒单/开始/完成均留痕并防并发重复。开始不得早于服务端预约开始时间；完成后等待买家确认，不能立即宣称已经提现到账。

暂停身份后的既有订单、售后、收益查询与提现限制应精确区分，不能用一个全局页面拦截导致历史处理不可达。

## 12. 收益、结算与提现

### 12.1 账务逻辑

订单完成后生成唯一收益和复式账务，经历待结算→可用→提现锁定→已提现；退款可能导致冲正，已提现部分不足形成欠款并按规则抵扣后续收益。已入账记录不可直接覆盖，修正应新增可审计冲正。

商业目标为完成后经过公开观察期、无争议再结算；当前测试种子把结算延迟设为 0，仅为本地加速。争议冻结/恢复和追偿须与人工售后同步落实。

### 12.2 收益展示

分别展示可提现、待结算、锁定、已提现、欠款/风险。今日/昨日/本周/本月/本年/累计区间统计需要服务端完整聚合，不能把当前加载的 20 条记录求和作为完整月收入。当前原生存在已加载页合计缺口；余额摘要与区间统计是两种数据口径，不得混为同一错误。

区间日界线、时区、按完成/入账/支付日期统计需统一；当前部分后台报表用 UTC，客户端按本地日期筛选。面向用户的最终业务时区与统计口径待冻结后两端一致。

### 12.3 收款与提现

仅微信/支付宝账户，显示脱敏摘要、验证与默认状态；正在提现使用的账户不能删除。录入→核验→设置默认，版本冲突读取新状态。

提现：选账户→输入金额→服务端预览费率与到账金额→二次确认→幂等申请→初审→不同管理员复核→渠道处理中→回调结果。锁定可用收益防止重复提现，失败/拒绝按状态释放，不能重复记账。

真实数据库状态：CREATED、RISK_REVIEW、APPROVED、PAYOUT_PROCESSING、COMPLETED、REJECTED、FAILED、CLOSED。文案可以为“申请中/审核中/处理中/成功”等，但不得用文案替代枚举或臆造可撤销入口。当前复核阶段缺独立驳回分支，需补齐规则和实现。

提现上下限、费率及到账预估读取服务端政策。本地种子 1%手续费、最低 1 分、最高 100 万分仅用于测试，不是正式收费承诺。当前账户核验/打款仍 Mock。Web 提现详情取列表第一条，未贯通选中 ID，必须修复。

## 13. 文件、声音与系统权限

统一链路：读策略→按需申请权限→选择/裁剪/录制→计算 SHA-256→预签名上传隔离区→complete 服务端校验→审核→业务绑定→受控访问/清理。

校验内容含用途、归属、大小、真实 MIME、摘要、图片尺寸/音频时长，不能只信文件扩展名。上传未完成/审核未通过不得伪造 file_id 或显示绑定成功；替换失败保留旧文件。

公开图片、签名声音与私有证据/导出分开授权。当前后端/原生已有本地 MinIO 链路，Web 多处还停留在演示。未来 OSS 仅适配边界，尚未证实生产接入。

声音名片为 10–30 秒，录制、试听、重录、上传、审核状态明确，公开试听有独立确认。麦克风/相机/相册在用到时申请，拒绝后提供可理解恢复路径，不在启动时索取所有权限。

已有 iOS 模拟器与 Android 模拟器/实机声音核心链路的历史报告；本次未重跑。iPhone 真机、来电中断、锁屏、蓝牙、权限拒绝、弱网恢复和多机型完整矩阵仍需独立证据。

| 会话/消息/通知/工单 | 成员、消息序号、客户端 ID、已读、关联资源 | `chat-support-notification.*` |
| 收益/账本/提现/欠款 | 分录、锁定分配、冲正、复核人、渠道事实 | `finance.*`、`finance-ledger.ts` |

API 以 `/api/v1` 为用户前缀；后台 `/admin-api/v1`；回调不等于普通用户可调用的成功按钮。关键端点族包括 `/auth`、`/me`、`/policies`、`/companions`、`/services`、`/favorites`、`/orders`、`/payments`、`/refunds`、`/complaints`、`/reviews`、`/conversations`、`/support-cases`、`/notifications`、`/seller`、`/files`。

核心原则：写入事务、金额整数分、创建幂等、更新 CAS、签名 Cursor、成员/归属授权、历史快照、审计留痕。没有优惠券、转盘和真实表情消息链路，不能因有入口就推定存在对应后端。

当前源码数据库为 70 表、68 枚举、10 条迁移的审阅基线，相关源码哈希未变；本轮未查询运行库迁移状态。模板 D1 不是业务主数据库。

## 15. 异常、适配与质量要求

| 场景 | 应有行为 |
| --- | --- |
| 加载/空/失败 | 分开显示，保留同尺寸图片占位；失败有重试，不填假数据 |
| 离线/恢复 | 保留可读内容；高风险写操作禁止盲目重发；恢复后查询事实 |
| 401/403/404 | 有限刷新或登录；拒绝越权；资源不存在有返回路径 |
| 409 | 明确状态已变化，读取最新 version，保留可恢复草稿 |
| 429 | 显示服务端可用重试时间，不能不断自动重试 |
| 支付/退款/提现超时 | 先查询真实状态，区分未知与确定失败 |
| 重复点击 | busy＋幂等，不能只靠前端禁用保证唯一 |
| 离页/切后台 | 取消无关请求/播放，回前台刷新关键订单与消息 |
| 敏感信息 | 手机号/证件/收款账户脱敏，不记录令牌、验证码、预签名地址 |
| 触控与键盘 | 主要点击区至少44×44；键盘不挡提交；安全区不重复计算 |
| 适配 | 全产品目标360–430px、小屏/大字体/横屏可返回；首页本轮重点375/390/430px |
| 动效 | 尊重减少动态效果，优先transform/opacity，离屏停播；不重新引入全页极光特效 |

旧 PRD 的 200%系统字体、读屏、对比度、真机键盘等要求仍是验收目标，本轮仅五入口浏览器验证不能替代这些检查。

## 18. 指标与验收

产品指标建议沿用商业资料：有效订单、接单耗时、完成/取消/售后率、30日复购、真实结算人数、投诉复诉/错误退款、每单客服成本与贡献利润。目标 GMV/客单/佣金不能当已实现业绩。

关键事件覆盖发现→详情→预览→下单→支付→履约→售后→复购，业务成功必须有服务端结果。第三方埋点平台尚未接入；不采集短信码、证件、收款账户、聊天/投诉正文到通用分析事件。

完整验收至少覆盖：

1. 新用户登录、协议拒绝/失败、游客回跳与会话失效。
2. 搜索/收藏/试听、无结果、下架/暂停、本人服务不可购。
3. 并发预约冲突、价格变化、重复下单、支付成功/失败/取消/未知恢复。
4. 双方接单履约、提前开始阻止、确认完成、拒单/超时退款衔接。
5. 全/部分退款、双向证据、平台介入、争议冻结、申诉、评价唯一。
6. 会话越权、重复消息、收发恢复、通知关联正确、客服重开。
7. 入驻/补件/审核、资料旧版保留、服务编辑/审核/下架真实生效。
8. 收益跨页汇总、冲正/欠款、提现双审异人、失败释放和幂等回调。
9. 换绑、导出、注销阻塞/撤销；文件归属与私有访问。
10. Web及iOS/Android独立的小屏、200%字体、键盘、安全区、权限、前后台、弱网验收。

一个功能只有入口可达、真实事实/写入、权限正确、状态完整、异常可恢复、适配可用且证据齐全，才可标记完成。历史自动化报告与静态源码检查不能替代本轮端到端验收。
