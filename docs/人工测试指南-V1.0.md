# 熊崽电竞人工测试指南 V1.0

更新日期：2026-08-26

## 1. 结论与边界

本地人工测试前自动化门槛已通过，可以开始人工测试。测试只允许使用本机 PostgreSQL 开发库 `xiongzai_api_dev`、本机 MinIO 和开发/Mock Provider。禁止替换为生产连接串，禁止接入真实短信、支付、退款或打款渠道。

- 收款账户仅支持 `WECHAT`、`ALIPAY`，不支持 `BANK`。
- 支付客户端渠道仅支持 `WECHAT_APP`、`ALIPAY_APP`；开发环境由 Mock Provider 确认结果。
- 保留 10–30 秒声音名片，不包含实时语音、RTC 或电话功能。
- 测试库 `xiongzai_database_test` 只供自动化测试，人工测试数据只能写入 `xiongzai_api_dev`。
- `.env.backend.local` 和 `.env.manual-test.local` 均为 Git 忽略文件，权限应为 `0600`。不要复制其中的密码、Token 或密钥到聊天、工单或截图。

## 3. 启动步骤

在 `/Applications/c2c游戏服务软件` 执行。每个长时间运行的命令放在单独终端。

### 3.1 确认基础服务

本地 PostgreSQL 16 和 MinIO 已安装在项目 `.local` 目录。若进程已运行，不要重复启动。

```bash
lsof -nP -iTCP:5432 -sTCP:LISTEN
lsof -nP -iTCP:9000 -sTCP:LISTEN
```

PostgreSQL 未运行时：

```bash
.local/postgres16/bin/pg_ctl -D .local/postgres-data -l .local/postgres.log start
```

MinIO 未运行时：

```bash
pnpm storage:local:start
```

配置并只读验证本地存储：

```bash
pnpm storage:local:configure
pnpm storage:local:verify
```

### 3.2 迁移和测试数据

```bash
pnpm db:migrate
pnpm db:migration:status
pnpm manual-test:seed
```

`manual-test:seed` 可以重复执行；它会恢复固定测试账号、陪玩、服务、SKU、时段、收款账户、声音名片、管理员权限和平台配置，不会重复创建这些夹具。订单、账务、审计等不可变历史不会被物理删除。

### 3.3 启动 API、Worker、Scheduler 和 Web

终端 A：

```bash
node --env-file=.env.backend.local apps/api/dist/main.js
```

终端 B：

```bash
node --env-file=.env.backend.local apps/worker/dist/main.js
```

终端 C：

```bash
node --env-file=.env.backend.local apps/scheduler/dist/main.js
```

终端 D：

```bash
pnpm dev
```

启动前如源码刚有更新，先执行：

```bash
pnpm backend:build
pnpm build
```

## 5. 测试数据说明

Seed 会准备：

- 1 个普通买家、1 个已通过实名且可接单的陪玩、1 个待审核陪玩；
- 1 个已通过审核且上架的服务；
- 2 个有效 SKU：60 分钟 2500 分、120 分钟 4500 分；
- 未来 30 天开放预约时段；
- 微信、支付宝测试收款账户各 1 个，不存在银行卡账户；
- 1 个 15 秒 `audio/mpeg` 声音名片，文件状态 `VERIFIED + APPROVED + SIGNED`，已绑定到陪玩；
- 1 个启用 MFA、拥有 42 项本地验收权限的管理员；
- 订单、结算、提现需要的 8 项活动平台配置。

## 6. 买家人工测试流程

1. 打开用户端，使用买家手机号和开发验证码登录。
   - 预期：登录成功；响应和页面只显示脱敏手机号，不显示 Token。
2. 首页查看“本地测试陪玩”和“本地测试｜和平精英陪玩”。
   - 预期：陪玩显示 1 项服务；服务卡卖家显示“本地测试陪玩”，价格为 `¥25.00 起`。
3. 进入陪玩主页播放声音名片。
   - 预期：通过受控短时地址播放 15 秒音频；没有实时通话入口。
4. 进入服务详情，分别检查两个 SKU 和可预约时段。
   - 预期：金额为整数分换算结果；只显示开放时段。
5. 收藏服务，再进入“我的收藏”。
   - 预期：只出现一次；取消后消失；接口失败时不回退演示数据。
6. 选择 SKU、预约时间并创建订单。
   - 预期：订单快照、金额和预约锁定成功，优惠金额固定为 0。
7. 选择微信或支付宝测试支付。
   - 预期：UI 明确显示 Mock Provider；不发生真实扣款；支付成功后订单进入待接单。
8. 进入订单聊天发送文字消息。
   - 预期：消息只提交一次，刷新后仍存在。
9. 等陪玩完成服务后确认完成并评价。
   - 预期：订单完成；同一订单只能评价一次，评价不可编辑。
10. 从已支付订单发起部分退款、投诉和客服工单。
    - 预期：累计退款不超过实付；证据为私有文件；工单保留状态日志。

## 7. 陪玩人工测试流程

1. 退出买家并使用已通过陪玩手机号登录。
   - 预期：可以进入陪玩中心，待审核账号不能进入已通过陪玩功能。
2. 打开服务和可用时段。
   - 预期：显示已上架服务、两个 SKU 和开放时段。
3. 在订单列表接单，进入聊天，然后按服务时间开始并标记完成。
   - 预期：只显示服务端允许的动作；非法状态跳转被拒绝；状态版本发生冲突时要求刷新。
4. 查看收益。
   - 预期：金额按整数分展示；订单完成后先待结算，再变为可用。
5. 查看或配置微信、支付宝收款账户。
   - 预期：账号只显示脱敏值；没有银行卡选项；同类型默认账户唯一。
6. 发起 Mock 提现。
   - 预期：不会真实打款；收益按 FIFO 锁定；重复点击不创建第二笔提现。

## 8. 管理员人工测试流程

1. 打开 `/admin`，输入本地管理员账号、密码和动态 TOTP。
   - 预期：密码错误和 TOTP 错误均被拒绝；成功后使用 HttpOnly Cookie，不写浏览器本地存储。
2. 在实名认证、陪玩审核、服务审核中检查待办和版本字段。
   - 预期：通过/驳回/补资料都需要权限；历史快照不被覆盖；操作写管理员审计。
3. 查看订单、支付、退款、投诉和客服。
   - 预期：用户端与后台订单状态和金额一致；Mock 支付只读；客服接入、回复、转交、关闭保留日志。
4. 进行聊天取证。
   - 预期：不填写业务理由时拒绝；填写理由后写审计记录。
5. 查看提现、账务和对账。
   - 预期：借贷平衡；提现账号仅显示脱敏微信/支付宝；差异处理有审计。
6. 检查风险、安全日志、管理员操作日志和平台配置。
   - 预期：RBAC 限制有效；危险操作要求二次确认和业务理由；配置新增版本而非覆盖历史。

## 9. 重新 Seed 与数据清理

恢复固定主数据：

```bash
pnpm manual-test:seed
```

该命令不清除订单、支付、退款、账务和审计历史，因为这些数据按设计不可变。需要完全干净的人工测试环境时，应停止 API、Worker 和 Scheduler，备份需要保留的本地数据，然后重新创建**仅限本机的** `xiongzai_api_dev`；不要对生产库或 `xiongzai_database_test` 执行清理。当前版本没有提供一键删除交易历史的脚本，以避免误删。

## 10. 已知问题与第三方渠道

阻断问题：无。

非阻断问题：

- ESLint 为现有 `<img>` 使用和 Expo 生成类型文件报告 59 条性能/生成文件警告，0 个错误，不影响当前人工测试。
- 页面目录中的少量“状态矩阵/异常状态”页面仍是视觉与交互演示；核心登录、发现、收藏、订单、支付、聊天、售后、收益和提现页面不会用这些演示记录替代 API 失败或空数据。
- 原生 App 已通过类型和单元测试，但本轮访问地址验收针对 Web 用户端；iOS/Android 实机继续按既有原生验收文档执行。

尚未接入的真实第三方渠道：真实短信、微信支付、支付宝支付、渠道退款、微信/支付宝真实打款、生产对象存储、Push 通知。声音名片为文件上传和受控播放，不包含实时语音通话。
