## 5. 删除流程审计结果

旧流程会先更新文件记录，再直接尝试删除对象；对象存储临时失败时缺少持久化重试入口。新流程在同一数据库事务中锁定本人文件、检查审核状态及有效引用、写入软删除状态，并以唯一 `job_key` 创建删除任务；事务成功后尝试立即执行，失败则保留任务供 Scheduler 重试。客户端不能提交 Bucket 或对象键。

## 6. 删除重试实现

新增 `FILE_OBJECT_DELETE`。任务只读取数据库记录中的精确 Bucket/对象键；对象不存在按幂等成功，临时网络、超时和 5xx 可重试，权限、配置和非法位置进入明确错误分类。最大次数可配置，退避为确定性、带抖动、有限上限的指数退避。达到上限后状态为 `FAILED` 并保留安全错误分类。

## 7. 过期 PENDING 清理

超过 `FILE_UPLOAD_SESSION_TTL_SECONDS` 的隔离区 `PENDING` 记录会创建唯一 `FILE_UPLOAD_CLEANUP` 任务。执行时再次锁行和确认仍已过期，将状态安全标记为 `FAILED`，只删除该数据库记录对应的精确隔离对象；对象不存在也视为完成。

## 8. UPLOADED 未确认处理

采用“过期后安全失败并清理”规则：不会自动再次 PUT，也不会猜测客户端状态。超过会话有效期且仍未 `complete` 的 `UPLOADED` 记录进入同一精确清理任务，状态改为 `FAILED` 后删除对应隔离对象。新鲜 `UPLOADED`、`VERIFIED/PENDING` 和已审核绑定文件不受影响。

## 9. FAILED 清理

隔离区 `FAILED` 记录会幂等创建清理任务，并尽力删除其精确对象。删除失败遵守相同的有限重试与永久失败分类，不使用前缀、通配符或 Bucket 级删除。

## 10. REJECTED 保留策略

PRD 未明确永久删除期限，因此 `FILE_REJECTED_RETENTION_SECONDS` 默认 `0`，即关闭自动删除。只有未来明确配置正数并完成变更审批后，才会对超过保留期、仍处于 `VERIFIED/REJECTED` 且无有效引用的隔离对象执行精确清理。

## 11. file_usages 删除保护

删除 API 和后台清理执行阶段都会检查未软删除的 `file_usages`。存在有效引用时拒绝用户删除或使清理任务进入不可重试的安全失败，数据库关系与对象均保留。已审核通过文件还必须先由业务对象解绑。

## 12. 任务调度实现

复用 `scheduled_jobs` 和现有 Scheduler，注册：

- `FILE_OBJECT_DELETE`
- `FILE_UPLOAD_CLEANUP`
- `FILE_STALE_OBJECT_DELETE`

Scheduler 周期性扫描到期上传和未完成软删除，使用唯一任务键避免重复入队，并处理审核迁移后旧位置的精确删除。

## 13. 任务锁和并发结果

真实 PostgreSQL 测试确认 `FOR UPDATE SKIP LOCKED` 下两个 Worker 对同一任务只有一个成功领取；运行中任务不会再次领取；锁超过配置时限后可由新 Worker 恢复；成功任务不会再次执行。

## 14. 重试与永久失败结果

真实 PostgreSQL 与注入失败 Provider 验证：次数正确递增，下一执行时间在未来，临时错误可再次执行，永久错误或达到最大次数进入 `FAILED`，不会无限快速重试。事务回滚不会遗留半条任务。

## 15. 孤儿对象分类

实现四类安全分类：

- 数据库已软删除但对象仍存在
- 数据库任务最终失败且对象仍存在
- 存储中有对象但数据库无对应记录
- 数据库有记录但对象不存在
