# 熊崽电竞后端全面复核与加固报告 V1.0

复核日期：2026-08-20

## 1. 最终结论

现有开发与测试基线稳定，数据库、后端、用户端、管理后台和完整交易 E2E 均通过；本次确认并修复了 1 个 P0 和 2 个 P1 问题，没有修改数据库 Schema、已应用迁移、冻结 UI 或公共 HTTP 请求结构。

**最终结论：暂不可进入正式预发布环境。**

代码基线可以继续用于本地和隔离集成环境，但正式预发布仍依赖真实渠道沙箱适配、生产 Event Publisher、文件存储安全链路、部署安全配置和运维能力。上述事项明确不在本次允许范围内，因此没有伪造、购买或创建相关资源。

## 2. 问题分级

### P0

1. **退款和提现可能在权限、状态与 CAS 校验前产生外部渠道副作用（已修复）**
   - 根因：`sellerDecide`、`adminDecideRefund` 和 `approveWithdrawal` 在进入锁行事务前调用 Provider。
   - 影响：非归属卖家、过期版本或并发重复请求可能先触发退款/打款，随后才被数据库拒绝；数据库回滚无法撤销外部副作用。
   - 修复：将 Provider 调用移动到资源归属、状态、金额、风险和 `version` 校验之后，并保持 PostgreSQL 行锁直到渠道接受与本地状态、审计和 Outbox 同一事务完成；同时明确 Provider 必须按 `refundNo` / `withdrawalNo` 幂等。
   - 回归：新增非归属、过期版本和并发双请求测试，证明无效请求调用次数为 0，并发批准只调用渠道 1 次。

### P1

1. **真实 PayoutProvider 收到数据库密文，无法执行打款（已修复）**
   - 根因：`createPayout` 参数为 `accountTokenCiphertext`，Mock 未读取该字段，因此掩盖了真实适配器无法使用 AES 密文的问题。
   - 修复：数据库继续仅保存 AES-256-GCM 密文；批准打款时在受控服务路径即时解密，只把账户令牌传给注入的 PayoutProvider，不进入响应、审计快照或日志。
   - 回归：测试确认数据库保存值不是原始令牌，Provider 收到原始渠道令牌，且参数中不再出现密文字段。

2. **Cookie 鉴权写请求缺少来源校验（已修复）**
   - 根因：CORS 与 SameSite Cookie 已配置，但认证守卫没有落实架构文档要求的 Origin / Fetch Metadata 校验。
   - 修复：对使用 Cookie 鉴权的 `POST`、`PUT`、`PATCH`、`DELETE` 校验 `Origin` 和 `Sec-Fetch-Site`；跨站、不可信、`null` 来源返回 `AUTH_CSRF_REJECTED` 403。Bearer API 客户端不受该浏览器 CSRF 规则影响。
   - 回归：覆盖跨站拒绝、允许来源通过、Bearer 请求通过。

### P2 / 非阻断项

1. Lint 为 0 错误、72 个警告：主要是冻结 UI 中使用 `<img>`，另有 2 个 React Hook 依赖警告。本次按要求未改视觉实现。
2. Fastify 当前使用 `trustProxy: true`；正式部署前必须由网关拓扑确定可信代理跳数或地址，避免直接暴露时伪造客户端 IP。
3. 用户评价创建后当前直接进入 `PUBLIC`，后台支持隐藏/恢复，但正式环境仍应接内容审核或异步风控策略。
4. 后台登录故事区的 `99.98%`、`< 8 min` 属于设计展示文案，不是数据库实时指标；正式运营前应替换为真实指标或明确标注。
5. 当前为最小兼容修复，Provider 网络调用期间会占用数据库行锁。真实渠道接入后建议演进为带 `SUBMITTING` 状态、Outbox 命令和渠道幂等查询的可恢复 Saga，并设置严格超时。

## 4. API、错误码、配置和迁移变化

- 公共 HTTP URL、请求体和成功响应：无变化。
- 新增错误码：`AUTH_CSRF_REJECTED`，HTTP 403，仅用于 Cookie 鉴权跨站写请求。
- 内部应用工厂：`createApiApp` 增加可选 `paymentProvider`、`payoutProvider` 注入参数，兼容原调用。
- 内部 Provider 契约：
  - `PaymentProvider.createRefund` 明确要求按 `refundNo` 幂等。
  - `PayoutProvider.createPayout` 明确要求按 `withdrawalNo` 幂等。
  - PayoutProvider 参数由 `accountTokenCiphertext` 改为仅在内存中使用的 `accountToken`。
- 环境变量：无新增、无删除、无值变更。
- 数据库 Schema、Enum、索引、约束和迁移：无变化，无新增迁移。

## 8. 尚未解决的风险

1. 真实短信、支付、退款和打款 Provider 尚未接入与签约；没有渠道沙箱演练、超时/未知结果查询、密钥轮换和正式对账文件验证。
2. Worker 只有 `log` Publisher，生产配置会主动拒绝启动；需要真实事件基础设施和失败告警。
3. 文件上传仍需对象存储、私有 Bucket、短时签名 URL、CDN、恶意文件扫描和证据访问策略。
4. 正式域名、TLS、Cookie Domain、CORS、CSP、WAF、限流、可信代理和负载均衡配置尚未验证。
5. Secret Manager、备份、PITR、恢复演练、监控指标、告警、日志归档和审计留存尚未落地。
6. 尚未用生产等量级脱敏数据完成压力测试、慢查询验收、容量估算和故障演练。
7. 评价内容审核、UI Lint 警告和 Provider Saga 化属于后续加固项。
