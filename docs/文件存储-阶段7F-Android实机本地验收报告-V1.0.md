# 文件存储阶段 7F：Android 实机本地验收报告 V1.0

## 1. 验收结论

阶段 7F 已完成 Android 实机上的声音名片核心本地全链路验收。Android Debug 应用能够通过无线调试连接本机开发服务，使用真实麦克风录制非真实用户的测试内容，并完成本地播放、文件上传、服务端校验、管理员受控预览与审核、隔离区到私有 Bucket 的晋升、业务绑定和审核后受控播放。

本阶段未连接阿里云或 Cloudflare，未创建云资源，未购买服务，费用为 0。正式环境的阿里云 OSS 联调仍未开始，也没有伪造任何云端验证结果。

## 2. 本地环境状态

- Android 实机：Android API 36、ARM64，已通过无线 ADB 完成 Debug APK 安装和运行验证。
- ADB 端口转发：仅使用本阶段授权的 `3002`、`8081`、`9000` 三个本机端口。
- MinIO API：监听 `127.0.0.1:9000` 和 `[::1]:9000`，健康检查返回 HTTP 200。
- MinIO Console：仅监听 `127.0.0.1:9001`。
- API、Metro 和 MinIO 未开放到局域网或公网。
- 三个开发 Bucket 继续保持用途隔离：quarantine、public、private；匿名访问关闭，quarantine 使用本地开发 CORS。

### 3.2 录音与本地播放

- 用户已在实机上亲自允许麦克风权限。
- 使用真实麦克风录制了一段约 28.9 秒的 M4A 测试声音；录音内容不属于真实用户资料。
- 录音时长预检通过，能够在上传前本地播放。
- 播放、暂停和停止行为通过；暂停时播放位置保持，停止后播放状态复位。
- 页面与资源生命周期清理通过，验收结束后应用音频缓存计数为 0。

### 3.3 上传、恢复与服务端校验

- 上传申请成功，客户端未自行设置 Bucket 或对象键。
- 预签名 PUT 上传成功。
- PUT 成功后的 complete 流程通过。
- 恢复路径通过：只重试 complete，没有重复执行 PUT。
- 服务端 HEAD、大小、SHA-256、真实 MIME 和真实音频时长校验通过。
- 服务端将真实解析时长作为最终依据，未信任客户端时长作为审核结论。

### 3.4 管理员审核与对象晋升

- 文件进入待审核状态后，管理员详情读取通过。
- 管理员同源二进制预览通过，包括范围请求。
- 管理员审核通过后，文件从 quarantine 精确复制到 private Bucket。
- 审核操作及受控预览保留管理员操作日志。
- 文件所有者、用途、私有状态和审核结果均由服务端数据决定。

### 3.5 审核后受控播放与业务绑定

- 审核后通过短时签名地址完成原生播放，完整播放时长约 28.9 秒。
- 已验证短时地址清除或失效后重新申请，不永久保存签名地址。
- 声音名片与当前业务记录的绑定通过，数据库记录与对象存储状态一致。
- 未生成公开永久 URL，私有声音不能通过公开枚举访问。

## 4. 本阶段问题与修复

### 4.1 ISO BMFF/M4A 服务端解析

真实 Android 录音暴露了 ISO BMFF 原子尺寸兼容边界。已在文件检查器中支持扩展尺寸原子和延伸到父容器结尾的零尺寸原子，并增加单元回归，避免合法 M4A 被错误拒绝，同时继续拒绝伪装视频或非法结构。

### 4.2 原生录音生命周期

已完善原生声音领域状态、录音面板和相关静态测试，覆盖录音状态同步、结束与资源释放路径，保持 Web 端既有能力不变。

### 4.3 管理员预览回归复核

首次回归使用旧构建产物时出现二进制流块类型异常。重新构建 API 后，当前源码实现及模拟存储返回的 Buffer/Uint8Array 流均正常；目标预览测试和完整集成套件均通过，因此未为该现象引入额外业务改动。
