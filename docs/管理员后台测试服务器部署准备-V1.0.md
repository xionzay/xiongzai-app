# 熊崽电竞管理员后台测试服务器部署准备 V1.0

## 1. 当前结论

代码仓库已具备本地生产构建、配置防误用、生产前端真实 Chrome 回归、API 健康/就绪检查、只读迁移检查、任务可靠性测试、敏感日志扫描及串行 `pnpm admin:preprod`。本阶段没有部署任何外部服务器，也没有创建云数据库、Bucket、Redis、证书、DNS 或真实 Provider 资源。

当前尚不具备实际部署测试服务器的完整外部条件：缺少已授权的服务器与网络参数、测试域名/TLS、可信代理 CIDR、隔离 PostgreSQL、对象存储、Secret Manager、真实短信/支付/打款适配器、事件发布适配器、日志监控接收端和备份恢复指标。`.openai/hosting.json` 仅保留现有前端 Sites 项目标识，D1/R2 均未配置；后台 API 仍使用独立 PostgreSQL 和对象存储，不自动改造为 D1/R2，也不自动发布。

## 2. 本地预发布

```bash
pnpm admin:preprod
```

命令需要本机 Node/pnpm、Google Chrome、回环 PostgreSQL、回环 MinIO，以及被 Git 忽略的 `.env.backend.local` 和 `.env.minio.local`。缺少依赖直接非零；命令不会自动部署、创建数据库/Bucket、执行目标数据库迁移或连接外部服务。

生产构建产物的本地入口：

```bash
pnpm build
pnpm start
pnpm run backend:build
pnpm --filter @xiongzai/api start
```

`pnpm start` 运行 `vinext build` 产物。API 的 staging/production 入口只有在真实 Provider 已注入且所有保护配置有效时才允许启动；本地验收用隔离测试模式验证编译产物本身，不把 Mock 描述为受保护环境验收。

## 3. 必要配置键

公共运行配置至少包括：`DEPLOYMENT_ENV`、`DATABASE_URL`、连接池参数、`API_HOST`、`API_PORT`、`API_BODY_LIMIT_BYTES`、`API_CORS_ORIGINS`、`API_TRUSTED_PROXY_CIDRS`、Token issuer/audience、用户/管理员/内部 Token 签名 Secret、游标签名 Secret、PII 加密/HMAC/Auth HMAC 密钥、Cookie TTL、对象存储 Provider/Endpoint/Region/Access Key/三个互异 Bucket、文件 TTL/限额、Worker/Scheduler ID/批量/轮询、`OUTBOX_MAX_ATTEMPTS` 和真实事件发布配置。

资金及短信配置必须明确为真实注入模式：`SMS_PROVIDER_MODE`、`PAYMENT_PROVIDER_MODE`、`PAYOUT_PROVIDER_MODE`、支付/打款回调签名 Secret。staging/production 禁止 Mock、控制台验证码、默认值、示例 Secret、HTTP/回环外部地址和全网可信代理。真实值只能进入部署平台的 Secret Manager，不得提交仓库、进入命令历史或日志。

## 4. 反向代理契约

- 对外只开放 HTTPS；HTTP 永久跳转 HTTPS，证书链、续期和 HSTS 由运维审批。
- 代理到 API 时保留 Host 与请求协议，覆盖而不是追加不可信 `X-Forwarded-For`。`API_TRUSTED_PROXY_CIDRS` 只列实际代理网段，不使用 `0.0.0.0/0`、`::/0`、`*` 或布尔信任。
- CORS 只列精确 HTTPS 管理域名并允许凭据，不使用 `*`。staging/production Cookie 必须同时出现 `Secure; HttpOnly; SameSite=Strict`。
- 管理 API 禁止公共缓存；代理不得覆盖 `no-store`。为 JSON 设置与 `API_BODY_LIMIT_BYTES` 一致或更小的请求体限制，并对登录/MFA、搜索、危险写操作和文件预览设置分层限速。
- request ID/trace ID 只接受安全格式；代理可生成并覆盖外来值。日志必须能按服务、时间、route、status、duration、request ID、trace ID 和脱敏 actor 定位。
- 管理员文件预览关闭代理缓冲和缓存，支持 200/206/416，保留 `Range`、`Content-Range`、`Accept-Ranges`、`no-store`、`nosniff` 与安全 `Content-Disposition`。客户端断开要传递关闭，上传/预览/上游读取均配置有限超时。

## 5. 健康与就绪

- `GET /health/live`：进程存活，不固定宣称数据库或对象存储正常。
- `GET /health/ready`：检查数据库；已配置对象存储时执行最小只读列表检查。失败返回非 2xx 的统一安全错误。
- 负载均衡只把 ready 成功的实例加入流量。启动失败必须非零，滚动发布必须等待 ready，停止时先摘流量再允许活动请求结束并关闭数据库连接/流。

## 6. 多实例和容量边界

文件预览默认每实例 4 路；N 个实例理论上最多同时接受 `4 × N` 路，不是全局配额。当前不接 Redis 或共享缓存。测试验证流式、范围校验、超时、断连和租约释放，但短时间本地堆内存数据不能推导生产 QPS、带宽或实例规格。测试服务器需另行记录 CPU、RSS、Event Loop 延迟、数据库连接、对象存储延迟、慢客户端与 429 比例。
