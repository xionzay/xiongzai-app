# 文件存储阶段 1：Cloudflare R2 接入前审计报告

> 历史说明：本报告记录阶段 1 当时的 R2 审计结论。2026-08-21 已决定停止 R2 接入；当前目标改为“本地开发使用 MinIO，未来云存储使用阿里云 OSS”。本报告不再作为阶段 2 的资源创建清单。

审计日期：2026-08-21

## 1. 结论

本地文件存储代码已经具备与 Cloudflare R2 进行开发环境真实联调的技术准备，但尚未达到生产上线条件，也不能判定为“完整符合 PRD”。已完成短时预签名 PUT/GET、服务端重新读取、SHA-256、大小、真实 MIME、图片尺寸、音频时长、所有权、用途隔离、管理员 MFA/RBAC/审计，以及公开/隔离/私有三 Bucket 路由。

尚缺真实 R2 联调、恶意文件扫描/图片和音频内容安全 Provider、扫描独立状态、异步对象清理、CDN 派生图和真实 App 上传。因此本阶段停止在“本地准备完成”，未创建 Cloudflare 资源，未修改外部账号，未购买服务。

## 2. 已修复问题

| 级别 | 问题 | 修复 |
|---|---|---|
| 高 | 待审核公开图片原先直接上传公开 Bucket；启用公共域名后，上传者可根据 PUT URL 中的键绕过 API 访问 | 所有新上传统一进入隔离 Bucket；批准后服务端使用新对象键复制到公开/私有 Bucket |
| 高 | 技术架构要求 Public Media、Private Upload、Private Evidence 三类存储，代码只有两个 Bucket | 增加 `FILE_QUARANTINE_BUCKET`，并强制三个 Bucket 名互不相同 |
| 中 | R2 自定义域名绑定单个 Bucket，原 CDN URL 固定拼接 Bucket 名 | 增加 `FILE_PUBLIC_ASSET_PATH_MODE`；R2 使用 `key-only`，兼容网关可用 `bucket-and-key` |
| 中 | 任意带 `ftyp` 的 MP4 都会被识别为 M4A，视频可伪装为音频 | 解析 MP4 box，只接受含 `soun` handler 的音频轨并读取该轨 `mdhd` |
| 中 | MP3 总样本数除以最后一帧采样率，混合采样率文件时长可能错误 | 按帧累加 `samples/sampleRate` |
| 中 | 图片仅限制单边 20,000 像素，缺少总像素防护 | 增加 64,000,000 总像素上限 |
| 中 | 删除顺序与 PRD 相反；对象先删而数据库软删除失败会留下活记录指向缺失对象 | 改为先软删除记录，再尽力删除对象；失败留给后续清理 Worker |
| 中 | 对象响应流读取失败可能变成普通 500 | 映射为明确的 `FILE_STORAGE_READ_FAILED` 503 |
| 中 | 已批准文件可直接改为拒绝，但公开对象/CDN 无法与数据库原子撤回 | 审核结果改为最终状态；未来使用独立下架流程 |
| 低 | 商品模块保留一份已不用的公开文件 URL 拼接实现 | 删除重复实现，统一由 `FileStorageService` 输出访问 URL |

## 4. 校验、权限与密钥审计

- 服务端不信任客户端声明：重新下载受限大小的对象，检查实际字节数、对象 MIME、自定义元数据、内容 SHA-256、文件签名及媒体元数据。
- 图片支持 JPEG/PNG/WebP 尺寸检查；音频支持 MP3、ADTS AAC、带音频轨 M4A 时长检查；JSON 必须是有效 UTF-8 JSON。
- 用户只能读取/删除自己拥有的文件；业务绑定检查 owner、file type、`VERIFIED` 和需要时的 `APPROVED`。
- 管理文件接口要求 MFA 与 `file.read`、`file.manage`、`file.review` 权限，审核写管理员操作日志。
- `.env.backend.local` 被 Git 忽略且本机权限为 `0600`；R2 变量仅存在于后端配置，示例文件均为占位值。HTTP 请求日志不记录请求体、响应体或预签名 URL。
- Access Key 和 Secret 不会返回 App；App 只会收到短时预签名 URL及要求的上传头。

## 5. 环境分离

`NODE_ENV` 已区分 development/test/production，Bucket、Endpoint、Access Key、Secret、公开域名均由环境变量提供。建议每个环境拥有独立 Token 和三个独立 Bucket，禁止开发/测试复用生产凭证或生产对象。

建议命名：

| 环境 | 隔离 Bucket | 公开 Bucket | 私有 Bucket |
|---|---|---|---|
| dev | `xiongzai-dev-quarantine-media` | `xiongzai-dev-public-media` | `xiongzai-dev-private-media` |
| staging | `xiongzai-staging-quarantine-media` | `xiongzai-staging-public-media` | `xiongzai-staging-private-media` |
| production | `xiongzai-production-quarantine-media` | `xiongzai-production-public-media` | `xiongzai-production-private-media` |

阶段 2 只应创建 dev 资源；staging/production 需分别再次授权。

## 6. 下一阶段准确外部资源

开发环境真实联调最小清单：

1. 一个已启用 R2 的 Cloudflare 账号及确认后的数据管辖区；Bucket 创建后管辖区不能随意改变。
2. 三个 dev Bucket：quarantine、public、private；只有 public 可绑定公共自定义域名。
3. 一个只对上述三个 dev Bucket授予 Object Read & Write 的 R2 API Token；记录 Access Key ID 和 Secret Access Key 到后端 Secret Manager，不写入仓库或 App。
4. quarantine Bucket 的 CORS：精确允许受信任 Web Origin，方法 `PUT`，请求头 `content-type`、`x-amz-meta-sha256`、`x-amz-meta-size-bytes`。不得使用无条件通配 Origin 作为生产配置。
5. public Bucket 的开发自定义域名，例如 `assets-dev.<已控制域名>`；`PUBLIC_ASSET_BASE_URL` 指向该域名，`FILE_PUBLIC_ASSET_PATH_MODE=key-only`。`r2.dev` 只可临时开发验证，不作为生产交付域名。
6. quarantine 的过期清理规则及 private 的证据保留规则；具体天数需产品、法务和安全确认后配置。
7. 后端部署环境中的七项秘密/配置：Endpoint、Region=`auto`、Access Key ID、Secret Access Key、三个 Bucket 名；另加公开域名与路径模式。

生产前另需但不应在阶段 2 擅自购买：恶意文件扫描/图片与音频内容安全服务账号、API 凭证、回调验签 Secret、费用预算与 SLA；CDN 图片缩略图/WebP/AVIF 转换能力；对象失败率、容量、扫描队列和孤儿对象告警。

## 7. 仍未解决的差距

1. 没有真实 R2 请求结果、真实 CORS 预检、跨 Bucket CopyObject、公共域名/CDN缓存和密钥权限拒绝测试。
2. 没有付费恶意软件与图片/音频内容安全 Provider；格式检查和人工审核不能替代病毒扫描。
3. 数据库当前只有 `moderation_status`，设计文档提到的独立 `scan_status` 尚未落表，无法分别表达病毒扫描、自动内容审核与人工审核。
4. 没有异步删除重试、孤儿对象清理、审核提升补偿、指标和告警 Worker。
5. App 目前只有安全的本地预览/不可用提示，尚未接上传 API、SHA-256、进度、取消、重试和审核状态。
6. 公开图片仍无派生缩略图和格式转换；列表加载原图的生产性能要求未完成。
7. 上传小时限额基于数据库计数，不是跨实例强原子限流；生产需 Redis/网关限流补强。
