# 熊崽电竞用户端简版需求

V3.7 程序员简版    2026年10月4日

本期功能按下面清单开发，页面参考现有 UI。交易、售后、判责和资金统一执行 V3.1；V3.6 长版仅供查阅未变更的细节。

**平台定位：**做四个游戏相关的全类目商品与服务电商，参考拼多多的购物结构和闲鱼的交易模式。正常成交抽佣10%，前期只靠抽佣盈利，不做广告。

**四个游戏：**和平精英、三角洲行动、王者荣耀、无畏契约。每件商品选一个游戏，不强制再选商品类型。

**导航：**买家、卖家底栏都为“首页、订单、消息、我的”。买家首页顶部为“推荐、店铺、商品”。

**首页五入口：**快速匹配、领券中心、平台规则、意见反馈、官方通知，固定一行。匹配只选游戏，结果为明确提供陪玩的店铺。

| 谁用 | 页面 | 要做什么 |
| --- | --- | --- |
| 买家 | 首页和搜索 | 搜索店铺/商品、四游戏筛选、排序；推荐页有公告、五入口、热卖商品和热门店铺。 |

## 交易流程和订单操作

**正常流程：**付款成功→待服务→卖家开始→服务中→提交完成凭证→待收货→买家确认或合法自动确认→交易终结并结算。评价独立进行。

**订单筛选：**全部、待付款、待服务、服务中、待收货、待评价、售后中、已完成。退款处理中归售后中；已退款/已关闭归已完成筛选，保留真实状态和操作资格。

**卡片规则：**主体点入详情，店铺名点入店铺；子按钮不误跳详情。最多三个直接按钮，其他放左侧“更多”；按钮按真实状态和权限显示。订单详情在同页分区展开凭证、售后和时间线。

| 订单状态 | 主要操作 从左到右 |
| --- | --- |
| 待付款 | 取消订单、联系商家、立即付款 |
| 待服务 | 申请退款、联系商家、催服务 |
| 服务中 | 申请售后、联系商家、催服务 |
| 待收货 | 申请售后、查看凭证、确认收货；更多：联系商家、延长收货 |
| 待评价 | 联系商家、去评价；更多：平台客服，有退款记录时查看退款 |
| 售后中 | 按案件阶段展示查看/回应方案、补证、介入或申诉；具体条件执行V3.1，不无条件开放修改或撤销。 |
| 已完成等 | 按真实资格展示平台客服、查看评价/退款；未评价且已过期不显示评价按钮。已退款始终显示已退款。 |

## 必须保留的业务规则

| 事项 | 规则 |
| --- | --- |
| 时间 | 完成时限从付款起计算，最长7天；正常验收72小时；每单最多延长一次24小时，补充履约共用次数；催服务每24小时一次。 |
| 售后 | 普通售后暂停普通确认收货；补充履约继续原案并保持冻结，其待验收阶段允许按规则确认。终结后特殊申诉由平台客服受理。 |
| 凭证和确认 | 完成凭证至少5图，付款≥200元另需连续录屏。取消、确认收货、撤销售后须二次确认；方案和裁决先看完整内容再回应，沉默不等于接受。 |
| 评价和资金 | 首次交易终结起7天内可评价，主动选星，文字/图片选填、可匿名，不自动好评。结算不等评价；提现受冻结及渠道状态约束。 |
| 退款和佣金 | 已发支付渠道才叫退款处理中；渠道成功才叫到账。正常成交10%佣金；发生实际订单退款，整单免佣，按V3.1结算。 |

## 开发顺序和完成标准

**顺序：**①账号、入驻、商品真实保存；②下单支付、订单、履约、售后、结算提现；③聊天、分享、反馈、匹配、优惠券及其余页面。以上均属本期。

**完成：**真实保存，买卖双方同步；权限、状态、截止时间和重复提交由后端校验。加载、空数据、失败重试要完整。分享读取最新商品，失效商品禁止购买；唤起微信/QQ不显示好友已收到。

**待确认配置：**待付款时限、优惠券承担与返券规则、上传限制、提现限额、目标终端及分享域名。全类目若包含账号交易或寄送实物，先确认准入与交付售后规则；其余配置查V3.6待确认表，不自行写死。
