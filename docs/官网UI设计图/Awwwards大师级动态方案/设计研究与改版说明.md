# 熊崽电竞｜Awwwards 方向动态官网与用户端 UI 改版说明

## 研究范围说明

Awwwards 历史案例数量极大，无法在一次设计任务中逐站穷尽。本轮选择了具有代表性的获奖站点与官方灵感分类，覆盖故事化滚动、3D 滚动、产品随滚动展开、角色动画、卡片揭示、移动端交互、可用性与性能等方向；提炼设计规律后再结合熊崽电竞品牌和本地用户端真实 UI 进行原创设计，不复制任何单个网站的布局、素材或动画。

## 从 Awwwards 提炼的核心规律

### 1. 视觉不是唯一标准

Awwwards 站点页面公开展示的评分维度为：设计 40%、可用性 30%、创意 20%、内容 10%。开发奖还关注语义与 SEO、动画与转场、无障碍、性能、响应式和标记质量。因此“大师级”不能只等于复杂 3D，也必须让导航、文字、按钮、政策入口和移动端体验清楚可用。

### 2. 滚动应该推动叙事

优秀案例常见的不是无目的漂浮，而是让滚动完成清晰的章节变化：使命出现、角色进入、产品展开、功能说明、信任与支持收束。熊崽电竞适合采用“使命—产品—保障”三幕结构。

### 3. 角色应承担交互职责

熊崽可以从首屏品牌角色，逐步变成滚动引导、产品讲解和客服助手。角色动作应保持克制、有因果关系，并为减少动态效果提供静态替代。

### 4. 创意必须建立在品牌策略上

不应为了像获奖网站而照搬宇宙、横向滚动、WebGL 或特殊光标。熊崽电竞独有的设计概念是：**熊崽带领用户从“发现一项能力”走到“完成一次价值记录”**。

### 5. 产品 UI 要成为内容本身

官网不能只摆一台模糊手机。应让买家首页、陪玩主页和服务详情成为滚动故事的三个真实章节，并保持原应用的信息结构、价格单位、服务状态和空状态可信。

## 本地用户端真实 UI 检查结果

本轮实际查看了 `http://localhost:3001/` 的买家首页、陪玩主页和服务详情。现有信息架构基本完整，包括搜索、推荐/陪玩/服务切换、热门陪玩、热门服务、陪玩资料、声音名片、服务规格、平台沟通、退款与介入等内容。

## 头像与商品封面系统

### 头像

- 使用同一套原创 3D 插画或编辑式人物头像，不混用写实照片、动漫截图和游戏角色。
- 人物应为虚构演示身份，不对应真实用户、明星或现有游戏角色。
- 统一正方形裁切，人物面部约占画面 55%–70%，光线方向和背景渐变保持一致。
- 首页卡片使用 1:1 头像；陪玩主页可以使用 4:5 主视觉，但头像本身保持一致。
- 演示环境可增加“演示资料”标识，正式上线后只展示审核通过的真实头像。

### 商品封面

- 不使用游戏角色、段位徽章、奖杯、官方地图或第三方商标。
- 使用原创耳机、语音波形、团队协作、时间段、模式标签等抽象视觉。
- 封面上不直接写保证性文案，例如“必上分”“稳赢”“最快接单”。
- 商品标题与封面共同表达：服务类型、模式和时长，避免只写情绪性口号。

## 官网滚动故事

### 0%｜首屏

- 使命：`让每个人都能创造价值`
- 熊崽执行呼吸、眨眼和一次挥手；不无限高频摆动。
- 手机模型保持 8° 倾斜，蓝紫玫红渐变作为主背景。
- 导航、了解产品、用户支持始终清楚可点击。

### 25%｜使命收束

- 使命缩小成顶部品牌标签。
- 熊崽以页面滚动速度的约 0.6 倍跟随，渐变由蓝紫过渡到粉橙。
- 不使用强制吸附，不劫持原生滚动。

### 50%｜产品展开

- 中间手机短暂固定，左右手机滑入，分别展示买家首页、陪玩主页和服务详情。
- 卡片以 80ms 间隔进入；标题和价格保持稳定可读。
- 手机内容使用真实 UI 字段，但演示昵称与封面使用公开版素材。

### 75%｜服务说明

- 展开平台文字沟通、退款与平台介入、规格和预约信息。
- 熊崽跳到手机边缘并指向当前说明，动作结束后保持静止。

### 100%｜用户支持

- 背景过渡为青色、薄荷色与暖白色，降低视觉强度。
- 熊崽缩小为客服助手。
- 服务协议、隐私政策、未成年人保护、联系我们等入口不依赖动画出现。

## 熊崽角色状态

```text
idleBreath → blinkWave → scrollFollow → jumpToPhone → pointProduct → supportAssistant
```

- 呼吸待机：3.2 秒循环，幅度很小。
- 眨眼挥手：页面首次进入触发一次；鼠标悬停最多再次触发一次。
- 跟随滚动：只改变位置和轻微倾斜，不持续旋转。
- 跳上手机：使用压缩、起跳、尾鳍跟随和落地回弹。
- 指向产品：由当前滚动章节触发。
- 客服助手：静止悬浮，只有用户悬停或聚焦时响应。

## 实现建议

- 熊崽角色：优先使用 Rive 状态机，让呼吸、眨眼、挥手、滚动跟随和客服状态可由页面事件控制。
- 页面滚动：使用 GSAP ScrollTrigger 处理章节进度、短暂固定、滚动联动和卡片进入；不要劫持浏览器原生滚动。
- 渐变与遮罩：大部分使用 CSS 渐变、`clip-path`、`transform` 和 `opacity`，WebGL 只保留给确实需要的门户或光带效果。
- 减少动态：遵循 `prefers-reduced-motion`，取消视差、缩放、旋转和固定滚动，只保留淡入与直接切换。
- 性能：角色和产品屏幕按章节延迟加载；图片固定尺寸并预留占位；移动端减少粒子、模糊和同时运动的图层。
- 可用性：鼠标、触屏和键盘都能完成导航；动画不能替代文字、按钮或状态提示。
