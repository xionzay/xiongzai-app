# 熊崽电竞聊天、客服和通知模块 V1.0

## 2026-10-25 独立反馈回复通知补充

意见反馈现由独立 `feedbacks` 模块处理，不创建客服会话、工单或冻结订单。官方回复原子产生一条 FEEDBACK 站内通知，正文不复制到通知和 Outbox。新客户端应使用扩展通知契约，列表/未读数/全部已读显式传 `include_feedback=true`；旧客户端默认行为保持兼容。接口、权限、幂等、数据库和接入方式见 [独立反馈与公共公告后端交接](独立反馈与公共公告后端交接-V1.0.md)。此补充不代表真实推送已接入；后续聊天媒体由其独立交付记录说明。

## 1. 实现范围

- 普通咨询、订单和客服三类一对一文字会话，共用 `conversations`、`conversation_members`、`messages`。
- 消息列表使用签名游标分页；发送方通过 `client_message_id` 幂等；成员通过消息序号维护已读位置和未读数。
- 客服工单支持创建、排队、接入、转交、回复、结束和用户重新打开，并记录优先级、队列、当前客服、首次响应时间和关闭时间。
- 站内通知写入 `notifications`，每次站内投递写入 `delivery_logs`；Inbox 消费使用事件 ID 幂等。
- 首期仅允许 `TEXT` 和 `SYSTEM`，不包含群聊、图片聊天、音视频和通话。

## 3. 管理端接口

| 方法 | 路径 | 权限 | 用途 |
|---|---|---|---|
| GET | `/admin-api/v1/support-cases` | `support.read` | 工单队列 |
| GET | `/admin-api/v1/support-cases/:caseId` | `support.read` | 工单与动作日志 |
| GET | `/admin-api/v1/support-cases/:caseId/messages` | `support.read` | 当前接入客服查看消息 |
| POST | `/admin-api/v1/support-cases/:caseId/receive` | `support.manage` | CAS 接入工单 |
| POST | `/admin-api/v1/support-cases/:caseId/transfer` | `support.manage` | CAS 转交并释放当前客服 |
| POST | `/admin-api/v1/support-cases/:caseId/reply` | `support.reply` | 幂等回复并记录首次响应 |
| POST | `/admin-api/v1/support-cases/:caseId/close` | `support.manage` | CAS 结束工单 |

管理接口同时要求有效管理员会话和 MFA。管理员不是当前接入客服时不能读取客服消息；订单聊天取证缺少非空业务理由时在参数校验阶段拒绝，成功读取前先在同一事务写入 `admin_operation_logs`。

## 4. 状态与事务边界

客服状态流为：

`WAITING/TRANSFERRED → SERVING → TRANSFERRED/CLOSED`，用户可执行 `CLOSED → WAITING`。

- 接入、转交、回复、结束和重新打开均锁定工单行；接入、转交、结束使用状态与 `version` Compare-And-Set。
- 每个客服动作与 `support_case_logs`、系统消息、管理员审计和所需 Outbox 事件在同一数据库事务提交。
- 首次管理员回复只设置一次 `first_response_at`；结束设置 `closed_at`；重新打开清空关闭字段。
- 同一管理员的 `client_message_id` 全局唯一。完全相同的重复请求返回原消息，不重复增加工单版本、通知、动作日志或审计日志。
- 会话行锁负责分配连续 `sequence_no`；数据库唯一约束作为消息幂等和订单会话唯一性的最终防线。
- 发送消息同时更新会话摘要、成员未读数、站内通知和 Outbox；任一步失败则整体回滚。

## 5. UI 接入

- 用户端消息列表、会话消息与已读、客服工单和通知列表/详情均使用真实 API；无数据时显示空态。
- 管理后台客服三栏工作台保留原视觉，队列、接入、回复、转交和结束改用真实管理接口。
- 金额仍以整数分字符串传输，展示使用字符串格式化，不在本模块引入浮点金额运算。
