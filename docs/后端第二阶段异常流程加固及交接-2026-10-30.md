## 2. 已确认缺陷与修复

### P1：复核阶段无法安全拒绝

原初审 reject 仅允许 CREATED，RISK_REVIEW 没有对应复核拒绝操作。新增 final-reject，复用既有拒绝事务而不新建提款或银行卡能力。要求复核人与初审不同，MFA 和 withdrawal.review.final；初审 reject 保持原阶段与权限。

提现及收益分配按 id + status + version 更新并递增 version；分录、资金释放、不可变日志、审计和 Outbox 同事务。分配不存在或锁定金额不足时整体失败，不能跳过后继续记账。已打款处理中或完成不可驳回释放。相同复核人相同版本重放只返回既有结果。

### P1：旧任务执行者可覆盖接管者

原 complete/fail 仅凭任务 ID 更新；两实例接管后旧执行者仍可将任务完成或回退。PostgreSQL 回归先复现失败，再增加 RUNNING/PROCESSING + attempts 认领代次条件。每次 claim 原子递增 attempts，不重置。完成／失败返回是否仍持有认领；失去认领不记录虚假成功或失败。

API FileLifecycleService 原先只附加 workerId，重复使用固定名称仍存在同类窗口；现在同时匹配认领代次。业务执行仍须幂等，不能将租约声称为“副作用绝对一次”。

租约在最后一次执行过期时显式 FAILED，错误类别 lease_expired_attempts_exhausted。Scheduler 不超过 max_attempts 再次领取，Worker 不永久停在 PROCESSING。此状态供人工诊断，并非自动解锁业务资金或重置执行次数。

### P1：渠道自由文本可进入持久记录和响应

原 payout failure_reason 被原样保存到 rejectReason 和 withdrawalLogs，可能包含账号、Token 或供应商内部信息。改用固定“渠道明确返回打款失败”。Inbox 只保存请求摘要。测试用合成敏感标记验证回调响应、用户详情与数据库日志不包含该标记，不展示真实凭据。

### P2：同一打款结果换事件 ID 重发被拒绝

原 Inbox 只按事件 ID 去重，已完成提现换事件 ID 会返回状态错误。现在先验证业务编号及金额，再识别相同终态，完成新 Inbox 记录并返回 duplicate=true。不同终态仍明确拒绝，不自动修改历史事实。并发不同事件只产生一次完成或释放分录。

### P2：协议生效边界混用时间精度

全量测试捕获新协议刚发布仍被忽略；筛选用 JS 毫秒 Date，数据库有效时间有微秒精度，且两端时钟可能有差异。当前版本列表、详情和场景必需协议统一使用数据库 statement_timestamp()。定向测试固定落后的 JS 时钟，旧编译实现失败、新实现通过；未来生效版本仍不可接受。不是弱化实名协议门禁或增加等待来掩盖问题。

## 3. API、契约、错误及配置变化

新增：

`POST /admin-api/v1/withdrawals/:id/final-reject`

合成请求示例，version 必须使用当前服务端值：

```json
{"version":1,"reason":"本地测试复核：申请材料不满足要求"}
```

成功仍返回既有 withdrawalView 全量结构；关键字段示意：

```json
{"id":"11111111-1111-4111-8111-111111111111","status":"REJECTED","version":2,"amount_cent":"5000","actual_amount_cent":"4950"}
```

该示例仅摘取关键字段，不是新增精简响应格式。相同操作重放不再次释放。不存在 404；权限不足 403；状态／版本不符合 409 RESOURCE_VERSION_CONFLICT；同人初审复核 409 WITHDRAWAL_DUAL_CONTROL_REQUIRED；异常收益分配 409 WITHDRAWAL_ALLOCATION_INVALID。统一错误 JSON 外形不变。

共享状态机新增 RISK_REVIEW → REJECTED，动作 INDEPENDENT_ADMIN_FINAL_REJECT。Scheduler/Worker 内部 Repository 完成／失败签名需要认领 attempts 并返回 boolean，不是公共 HTTP 契约变更。

现有提现回调路径、签名方式和请求字段不变；failure_reason 仍可接收用于签名验证，但不原样持久化。重复终态由 409 调整为成功 duplicate=true，属于兼容性加固。矛盾结果仍拒绝并留待对账。

数据库 Schema、迁移、配置键新增：**无**。没有创建新的真实渠道。Web Cookie、App Bearer、Session、后台 MFA/RBAC 保留。

## 7. 客户端／运维交接

后台可以在 RISK_REVIEW 仅向具备复核权限且非初审人的管理员提供“复核拒绝”，传最新 version 和原因；冲突重新读取，不强制覆盖。用户端/App 沿用 REJECTED、FAILED、COMPLETED 展示，不从按钮点击推算余额。等待渠道结果时仍显示处理中，不因超时假失败或创建第二笔付款。

调度器完成失败的内部接口已改，定制 Repository 必须传回 claim 的 attempts 并处理 false。FAILED/lease_expired_attempts_exhausted 需要人工查原业务事实后处理，禁止直接清零 attempts 重跑未知资金任务。

用户端/App/后台不得提前接入尚不存在的协商、补充履约、二级申诉或评价图片写接口。临时规则授权不等于这些接口可用。仍需后续浏览器三端、真机与 Keychain 人工验收。
