# 熊崽电竞文件存储 V1.0

## 1. 本阶段结果

当前已经在既有 `files`、`file_usages`、`scheduled_jobs` 数据模型上完成可运行的文件上传后端闭环、用户端 App 的 `USER_AVATAR`、`SELLER_AVATAR`、`SELLER_COVER`、`PRODUCT_IMAGE`、`COMPLAINT_EVIDENCE` 与 `VOICE_SAMPLE` 本地接入，以及管理员后台文件管理和人工审核模块。客户端读取真实二进制、校验服务端策略、计算 SHA-256，申请短时上传凭证后将字节直传隔离 Bucket，再请求服务端重新读取对象并核验大小、SHA-256、真实 MIME 和媒体元数据。`VOICE_SAMPLE` 额外要求真实音频轨与 10–30 秒服务端时长。校验通过后文件进入人工审核；具有 `file.read`、`file.review` 权限且完成 MFA 的管理员通过同源管理 API 预览真实图片/音频，浏览器不再取得对象键或完整预签名 URL。审核通过后，公开图片由服务端复制到公开 Bucket，投诉证据和声音名片复制到私有 Bucket；业务接口再次校验所有权、用途、状态和可见性后才建立 `file_usages`，并使用现有版本号/CAS 防止并发覆盖。文件生命周期已复用现有调度器实现精确删除重试、过期上传清理、旧位置清理和默认只读的孤儿对象审计。

当前对象存储目标为：本地开发使用仅监听回环地址的 MinIO，未来云存储使用阿里云 OSS。Cloudflare R2 已停止采用，不再创建或接入 R2 资源。业务层通过统一的 `ObjectStorageProvider` 接口调用上传签名、HEAD、读取、下载签名、复制和删除；MinIO 使用 S3 Signature V4，阿里云 OSS 保留独立 SDK 适配边界，不复用 MinIO 签名实现。本阶段不创建阿里云资源，当前不使用 CDN、不购买恶意文件扫描服务，也不声称真实 OSS 联调成功。

## 2. 文件策略

| 用途 | 格式 | 上限 | 可见性 |
|---|---|---:|---|
| USER_AVATAR、SELLER_AVATAR | JPEG、PNG、WebP | 5 MiB | PUBLIC |
| SELLER_COVER、PRODUCT_IMAGE | JPEG、PNG、WebP | 10 MiB | PUBLIC |
| VOICE_SAMPLE | AAC、M4A、MP3，10–30 秒 | 10 MiB | SIGNED |
| COMPLAINT_EVIDENCE | JPEG、PNG、WebP | 10 MiB | PRIVATE |
| ADMIN_EVIDENCE | JPEG、PNG、WebP、PDF | 20 MiB | PRIVATE |
| PAYMENT_PAYLOAD | JSON、文本 | 1 MiB | PRIVATE，仅服务身份预留 |

客户端应通过 `GET /api/v1/files/policies` 获取用户可用限制，不应硬编码。

需求文字中的“卖家图集/SELLER_GALLERY”在当前 V1 数据库、服务端策略、移动端和管理员后台中的冻结规范值为 `SELLER_COVER`。它用于卖家资料封面/展示图片；本地总验收没有新增第二个同义枚举，以避免破坏既有数据库约束、API 客户端和审核数据。若未来需要真正的多图卖家图集，应按新业务版本单独设计数量、排序和迁移规则。

## 3. API

### 3.1 用户接口

- `GET /api/v1/files/policies`：公开读取上传策略。
- `POST /api/v1/files/uploads`：申请上传 URL。请求包含 `file_type`、`mime_type`、`size_bytes`、64 位小写十六进制 `sha256`。
- `POST /api/v1/files/:fileId/complete`：上传完成后触发服务端完整性与媒体校验。
- `GET /api/v1/me/files`：当前用户按用途、上传状态和审核状态分页读取自己的安全文件视图，用于恢复待确认、待审、已通过、已拒绝或失败的上传任务。
- `GET /api/v1/files/:fileId/access`：文件所有者获取短时访问 URL。
- `DELETE /api/v1/files/:fileId`：删除尚未审核通过且未被业务引用的文件。
- `GET /api/v1/files/:fileId`：公开读取已验证、审核通过且非私有的文件。
- `GET /api/v1/companions/:sellerId/voice`：从当前已通过的陪玩资料和活动 `file_usages` 定位当前声音名片，只返回短时签名播放权。

申请接口返回 `PUT` URL、到期时间和必须随上传发送的请求头。客户端必须原样发送 `content-type`、`x-amz-meta-sha256` 和 `x-amz-meta-size-bytes`。

### 3.2 Bucket 路由

| Bucket | 内容 | 匿名访问 |
|---|---|---|
| `FILE_QUARANTINE_BUCKET` | 所有新上传及审核拒绝文件 | 禁止 |
| `FILE_PUBLIC_BUCKET` | 审核通过的 `PUBLIC` 文件 | 禁止匿名访问；当前使用短时签名 GET，未来显式配置域名/CDN 后才能改用公开资源地址 |
| `FILE_PRIVATE_BUCKET` | 审核通过的 `SIGNED`、`PRIVATE` 文件 | 禁止，仅短时签名 GET |

客户端永远只获得隔离 Bucket 的短时 PUT URL，不获得 MinIO/OSS Access Key、Secret、Bucket 管理权限或数据库中的 `object_key`。公开提升使用新的不可预测对象键，避免上传者根据待审键猜出公开地址。

### 3.3 管理接口

- `GET /admin-api/v1/files`：按上传状态、审核状态筛选文件，并返回签名游标分页 `{ items, next_cursor }`。
- `POST /admin-api/v1/files/uploads`：上传管理员证据。
- `POST /admin-api/v1/files/:fileId/complete`：确认管理员上传。
- `GET /admin-api/v1/files/:fileId/access`：只返回安全文件元数据，保留路径兼容但不再返回审核预签名 URL。
- `GET /admin-api/v1/files/:fileId/preview`：由管理 API 读取对象并以同源二进制响应返回；不接受 Bucket 或对象键参数。
- `POST /admin-api/v1/files/:fileId/moderation`：批准或拒绝文件；操作写入 `admin_operation_logs`。

对应权限为 `file.read`、`file.manage`、`file.review`，并要求管理员 MFA。已有管理员角色需由授权管理员显式补授这些权限；本地新建管理员脚本已包含它们。

### 3.4 管理员后台文件模块

管理员后台主导航包含“文件管理”入口和真实待审核数量。模块只使用现有管理 API，不在前端伪造审核数据，也不显示 Bucket、`object_key` 或存储密钥。当前能力包括：

- 按真实 `upload_status`、`moderation_status` 在服务端筛选文件，默认每页 20 条并按签名游标追加加载；下一页失败时保留已加载记录。列表展示所有者、用途、MIME、大小、图片尺寸/音频时长、上传状态、审核状态、访问级别及时间。
- 打开详情时调用 `GET /admin-api/v1/files/:fileId/preview`，共享 `admin-api.ts` 以 `credentials: include` 取得同源 Blob；图片使用图片元素，音频使用原生 `<audio controls>` 且禁止显式下载控件。Blob URL 只存在于当前页面内存，切换文件、关闭详情或卸载组件时立即撤销，不写入路由、日志、localStorage、sessionStorage 或数据库。
- 只有 `VERIFIED + PENDING` 文件显示审核按钮。通过和驳回均要求填写 2–1000 字符原因，提交中禁用重复点击，结果写入 `admin_operation_logs`。
- 重复或并发审核返回 `RESOURCE_VERSION_CONFLICT`；页面提示文件已被其他管理员处理并刷新真实状态，不覆盖先成功的结果。
- `file.read` 控制列表与详情，`file.review` 控制审核，`admin_log.read` 控制审核日志；Cookie Session、MFA、CSRF Origin 校验及原有 RBAC 边界保持不变。
- 文件审核日志使用 `target_id` 在服务端查询操作日志，不再把整张操作日志读取到浏览器后过滤。

Playwright 真实后端 E2E 使用随机临时管理员、真实 TOTP、隔离 PostgreSQL Schema 和本地 MinIO 合成对象，已覆盖登录后的文件详情、同源预览、响应头、Blob 生命周期、审核成功与真实审计。错误状态的浏览器拦截用例与真实后端链路在测试名称和报告中明确分开；SSR/源码契约测试也不被描述为浏览器 E2E。

### 3.4.1 管理员预览代理安全边界

- 预览要求有效管理员 Session、已完成 MFA，并同时具备 `file.read` 与审核附加权限 `file.review`。只有 `VERIFIED` 且审核状态为 `PENDING` 或 `APPROVED` 的安全 MIME 可以读取；未验证隔离对象、失败、驳回、软删除、未知 MIME 和超过 20 MiB 的对象均安全拒绝。`VERIFIED/PENDING` 仍位于 quarantine，但这是人工审核必须查看的唯一隔离状态。
- 服务端仅用数据库文件 ID 定位存储位置；查询字符串中的 `object_key` 等字段不会参与查找。响应不包含 Bucket、对象键、存储 Endpoint 或预签名 URL。
- 允许的响应 MIME 为 JPEG、PNG、WebP、MP3、AAC 与 M4A。响应使用 `Cache-Control: no-store, private`、`X-Content-Type-Options: nosniff`、`Cross-Origin-Resource-Policy: same-origin`、受控 `Content-Disposition` 与严格 CSP；音频支持单段 `Range`，非法或越界范围返回 416。
- 管理员预览已经使用 `ObjectStorageProvider.readObjectStream` 真正流式读取，不再把最多 20 MiB 的对象先聚合成服务端 Buffer。MinIO GET 的 Web Stream 转换为 Node Stream，并通过 `pipeline` 和字节上限 Transform 传给 Fastify，具备背压；Range 直接向对象存储请求唯一单段并校验 `206`、`Content-Length`、`Content-Range` 与数据库声明总大小。严格 5 秒超时会覆盖正文消费，响应中断会销毁源流。
- `PreviewConcurrencyLimiter` 是可替换接口；默认 `InMemoryPreviewConcurrencyLimiter(4)` 只限制单 API 进程，不伪装成跨实例限流，也未连接 Redis。租约绑定流的 `end/close/error`，存储读取失败、响应失败和客户端断连均释放。多实例全局配额仍需未来经架构审批的共享限流实现。
- 每个成功预览写入真实 `FILE_PREVIEWED` 管理员审计，包含管理员、文件、时间、IP、request ID 与 trace ID，但不保存 Cookie、Token、请求头、二进制、Bucket 或对象键。对象存储原始异常由统一错误层归一化，不返回浏览器。

### 3.5 用户端 App 的通用图片上传与任务恢复契约

`USER_AVATAR`、`SELLER_AVATAR`、`SELLER_COVER`、`PRODUCT_IMAGE` 与 `COMPLAINT_EVIDENCE` 共用同一上传领域流程和图片槽位组件。页面按用途读取服务端策略，不把大小、MIME、Bucket 或对象键硬编码到业务页面。完整顺序为：

1. 相册或相机权限通过后按用途选择裁剪比例；头像推荐 1:1，封面、商品图和证据不强制沿用头像比例。系统选择器关闭 Base64 与 EXIF 返回。
2. App 读取裁剪后的真实字节，拒绝空文件、未知 MIME、超出策略大小或策略未开放。
3. App 对原始字节计算 64 位小写十六进制 SHA-256，再用登录 Bearer 调用 `POST /files/uploads`。
4. App 使用原始 `fetch` 对服务端返回的短时 URL 执行 `PUT`，请求体为同一份字节，只发送服务端指定请求头；该请求不得经过 API 客户端、不得携带登录 Bearer。
5. PUT 成功后用登录 Bearer 调用 `POST /files/:fileId/complete`。若确认暂时失败，保留已上传的文件记录并只重试 `complete`，不得自动重复 PUT；PUT 尚未成功时失败才尽力删除待上传记录。
6. 页面重开时调用 `GET /api/v1/me/files` 恢复服务端事实：`PENDING` 可删除重选，`UPLOADED` 只重试确认，`VERIFIED/PENDING` 等待审核，`APPROVED` 进入绑定，`REJECTED` 或 `FAILED` 可删除重选；`DELETED` 不恢复。
7. 审核前保留原业务图片；只有满足业务要求的文件才能绑定。正式展示始终读取服务端文件，不把本地 URI 当作正式 URL。

移动端区分选择、读取、哈希、申请、上传、确认、待审核、已通过、已拒绝、绑定、已绑定、删除、取消和失败阶段，并把用户取消、权限拒绝、空文件、MIME、大小、上传、确认、审核和版本冲突错误映射为安全提示。卸载页面会取消仍在进行的读取/网络请求并阻止卸载后的状态更新；同一上传槽位同一时刻只允许一个任务。预签名 URL 只在当前请求内短暂使用，不进入持久状态、日志或错误上报。

### 3.6 VOICE_SAMPLE 上传、绑定与受控播放

- 用户角色可上传 AAC、M4A（`audio/mp4`）和 MP3，最大 10 MiB。客户端的 MIME、大小和时长检查只用于提前提示；服务端会重新计算 SHA-256、嗅探真实 MIME、确认存在音频轨并计算 10–30 秒时长。只有视频轨的 MP4 不会被当作 M4A 接受。
- 新上传进入 quarantine，通过后转入 private，仍保持 `SIGNED`；驳回保持在 quarantine。通用公共文件接口只接受 `PUBLIC`，因此不能用文件 ID 枚举声音名片。
- 陪玩资料绑定只接受本人所有、`VOICE_SAMPLE + SIGNED + VERIFIED + APPROVED` 的文件。服务端忽略客户端声明的时长，将已校验的 `files.duration_ms` 写入陪玩资料。替换时保留新的活动 `VOICE/SELLER` 引用，并软删除旧引用；未改变的引用不会被重复软删除/插入。
- 公开陪玩详情页仅在用户主动播放时请求受控接口。接口必须由当前已通过的陪玩资料关系定位活动声音文件，不接受 Bucket 或对象键，不返回存储内部信息；短时 URL 只保存在页面内存中，到期、切换资料或卸载后清除。
- Web 已使用浏览器文件选择器和原生音频元数据/播放能力接入。React Native 已通过 Expo SDK 57 兼容的 `expo-document-picker`、`expo-audio` 和 `expo-file-system` 接入 iOS/Android 文件选择、录音、播放、缓存读取与清理。iOS Simulator、Android Emulator 和一台 Android 实机的核心链路均已真实验证；没有连接真实 iPhone，Android 的后台、锁屏、蓝牙、来电打断及多厂商兼容矩阵仍明确保留为人工验收项。

### 3.7 文件用途与业务绑定

- `USER_AVATAR` 只有文件所有者可绑定到自己的用户资料；必须为 `VERIFIED + APPROVED + PUBLIC`，并使用用户和资料版本号完成 CAS 更新。
- `SELLER_AVATAR`、`SELLER_COVER` 只有卖家资料所有者可修改；审核前保留旧图，审核通过后才替换对应 `file_usage`。
- `PRODUCT_IMAGE` 只有商品所属卖家可调整；最多 9 张、排序值不得重复，非空集合恰好一张主图。公开详情只返回已经通过文件约束的图片，移除图片只解绑对应业务引用。
- `COMPLAINT_EVIDENCE` 只允许投诉发起人提交自己的 `VERIFIED`、`PRIVATE`、正确用途文件；按现有 PRD 可在审核待处理时绑定。文件即使审核通过也不能通过公共文件接口读取。
- `VOICE_SAMPLE` 只允许陪玩资料所有者绑定当前已验证、已审核通过、受签名保护的声音文件；已绑定文件受 `file_usages` 删除保护。
- 所有绑定均再次校验所有权、用途、上传状态、审核要求和可见性。业务更新同步 `file_usages`；已有引用会阻止直接删除底层文件，对同一引用重复同步不会产生重复记录。

## 4. 状态与安全约束

1. 申请上传后写入 `PENDING`，对象键只包含状态前缀、用途、UTC 年月和 UUID，不使用原始文件名或个人信息；所有新文件进入隔离 Bucket。
2. 上传 URL 默认 10 分钟有效；上传任务默认 1 小时有效；每个用户每小时最多申请 20 个待上传任务。
3. 上传签名绑定 MIME、声明哈希和声明大小。确认时服务端先用 HEAD 核对对象大小、MIME 和元数据，再重新读取受限大小的对象，不能仅相信客户端或对象元数据。
4. 服务端重新计算 SHA-256，嗅探 JPEG/PNG/WebP/PDF/MP3/AAC/M4A/JSON 等真实格式，并解析图片尺寸或声音时长。
5. 校验失败写入 `FAILED` 并尽力删除对象；校验成功写入 `VERIFIED`，内容审核状态仍为 `PENDING`。
6. 公开业务模块仍要求 `VERIFIED + APPROVED + owner`，因此上传成功不等于可以绑定或公开展示。
7. 审核批准后，公开图片移入公开 Bucket；私有文件和受控声音移入私有 Bucket 并使用短时签名 GET URL。公开图片配置 CDN 后使用 CDN，否则回退为短时签名 URL。
8. 审核结果为最终状态；公开内容下架不能通过反向改写审核结果完成，必须使用后续独立下架流程，避免 CDN/对象删除与数据库状态不一致。
9. 删除在一个数据库事务中锁定文件、复核所有权、审核状态和有效 `file_usages`，写入 `DELETED/deleted_at` 并创建唯一删除任务；随后可立即领取执行。对象不存在视为幂等成功，临时错误按有限次数、带确定性抖动的指数退避重试，权限、配置和无效位置错误进入永久失败。任何任务都只使用数据库保存的精确 Bucket 与对象键。

### 4.1 文件生命周期可靠性

- 复用 `scheduled_jobs`，不创建第二套任务表。任务类型为 `FILE_OBJECT_DELETE`、`FILE_UPLOAD_CLEANUP` 和 `FILE_STALE_OBJECT_DELETE`，以唯一 `job_key` 保证重复入队幂等。
- 调度器通过 PostgreSQL `FOR UPDATE SKIP LOCKED` 领取任务；同一时刻只有一个工作器取得执行权。活动锁不会被重复领取，超过锁超时的 `RUNNING` 任务可以恢复；成功任务进入 `COMPLETED`，不可重试或达到上限的任务进入 `FAILED`。
- 默认最多重试 8 次。退避从约 2 秒开始，使用稳定任务 ID 计算 0.75–1.25 倍抖动，并限制到 5 分钟内；测试使用可控时钟，不依赖长时间 `sleep`。
- `PENDING` 或 `UPLOADED` 超过上传会话 TTL 后进入精确清理：先在事务中再次确认仍已过期、位于隔离 Bucket 且没有有效引用，再标记 `FAILED` 并删除该数据库记录对应的对象。`UPLOADED` 不会自动重复 PUT。
- `FAILED` 会进入隔离对象清理。`VERIFIED/PENDING` 不属于过期上传清理；`APPROVED` 且已绑定的文件不会被该任务删除。
- PRD 未定义 `REJECTED` 永久删除期限，因此 `FILE_REJECTED_RETENTION_SECONDS` 默认 `0`，表示关闭自动删除；只有未来明确配置正数并通过变更审批后才按保留期处理。
- 审核提升后如果旧隔离位置删除失败，数据库指针更新与旧位置删除任务在同一事务中建立；任务会验证旧位置不是当前文件位置后才执行，避免误删正式对象。
- `ObjectStorageProvider.listObjects` 是提供商无关、只读、分页且有数量上限的审计接口。孤儿分类包括：软删除记录仍有对象、失败任务仍有对象、存储有对象但数据库无记录、数据库有记录但对象缺失。
- 孤儿报告只返回计数、文件 ID 和 Bucket/对象键组合的 16 位哈希标识，不返回完整对象键、不读取内容。未知开发对象默认不删除；自动清理仅开放给严格匹配 `stage6-tests/<uuid>/<filename>` 的隔离 Bucket 测试对象。
- 本地指标复用 JSON 日志格式，记录待执行删除数、重试数、永久失败数、过期上传数、入队/成功/失败结果、耗时、任务 ID、任务类型、次数和固定错误分类；不记录完整对象键、预签名 URL、密钥、连接字符串或原始异常正文。

本地 MinIO 使用三个开发 Bucket：

- `xiongzai-dev-quarantine-media`
- `xiongzai-dev-public-media`
- `xiongzai-dev-private-media`

本地辅助命令：

```bash
pnpm storage:local:prepare
pnpm storage:local:start
pnpm storage:local:configure
pnpm storage:local:verify
```

`storage:local:start` 在前台运行 MinIO。正常停止方式是在启动它的终端按 `Ctrl+C`；如果启动终端已经丢失，应先用 `lsof -nP -iTCP:9000 -sTCP:LISTEN` 确认精确的 MinIO PID，再只停止该进程，禁止使用会误伤其他服务的宽泛进程终止命令。停止后可用同一条 `lsof` 命令确认端口已释放。

`storage:local:prepare` 只把随机本地密钥写入已被 `.gitignore` 排除且权限为 `0600` 的 `.env.minio.local` 与 `.env.backend.local`，不会打印 Secret。本地启动脚本使用开源 MinIO 二进制，无需 AIStor 许可证；`MINIO_LICENSE_PATH` 是旧配置项，现已忽略。启动和配置命令只有在用户明确授权安装/启动 MinIO 后执行。

AIStor 支持仅在隔离 Bucket 配置浏览器 CORS：Origin 精确限制为 `http://localhost:3001` 与 `http://127.0.0.1:3001`，方法为 `PUT`、`GET`、`HEAD`，请求头为 `content-type`、`x-amz-meta-sha256`、`x-amz-meta-size-bytes`。本地开源 MinIO 不支持 Bucket 级 CORS，配置脚本会跳过该步骤；浏览器跨源直传须另行配置并验证，原生 App 不依赖浏览器 CORS。三个 Bucket 均禁止匿名访问。`storage:local:verify` 使用唯一测试对象执行真实 PUT、GET、HEAD、读取、公开/私有复制和删除，并在成功或失败时通过 `finally` 清理测试对象；脚本还会断言删除结果，避免遗留验证对象。

### 6.1 第五阶段预发布稳定性结论

- 本地测试以 64 次连续 64 KiB Range 流验证响应不聚合完整文件，并记录进程堆内存差值；该数据只用于发现本地回归，不是生产容量结论。
- 对象存储正文读取有 250 ms 至 30 秒的有界超时，管理员预览当前使用 5 秒；存储超时、流错误、响应结束、响应关闭和客户端断连都会销毁流并释放 `PreviewConcurrencyLimiter` 租约。
- 20 MiB 最大值依据数据库声明的完整文件大小检查。Range 只降低当前响应字节数，不降低完整文件大小检查，因此连续 Range 不能读取本来超过上限的文件。
- 每个 API 进程默认最多 4 路，不存在“集群全局 4 路”的保证。两个实例可以同时接受 8 路；进程退出后内存租约随进程释放。若未来需要全局上限，必须经过架构审批实现可替换的共享 Limiter，并补充故障与降级策略，本阶段不接 Redis。
- 429 使用统一安全错误码 `FILE_PREVIEW_BUSY`。反向代理必须关闭管理员预览响应缓冲、保留 `Range/Content-Range`、允许流式背压、设置合理读取超时，并不得缓存 200/206/416 响应。
- `/health/ready` 对对象存储仅执行安全、最小、只读的限量列表，不上传探针对象、不创建 Bucket，也不把内部位置返回调用方。

本地网络边界：MinIO 只监听 Mac 回环地址。iOS 模拟器可直接使用 Mac 回环环境；Android 模拟器和已配对 Android 实机通过授权的 `adb reverse` 把设备侧 `127.0.0.1` 精确转发到 Mac 的 `3002`、`8081`、`9000`，因此不改写已签名 URL 的 Host，也不把 API、Metro 或 MinIO 开放到局域网或公网。未经单独授权，不得改为 LAN 监听、防火墙放行、真机开发域名或公网代理。

## 8. 本地接口冻结与完成边界

截至 2026-08-25，本地文件存储开发核心范围判定完成，冻结以下 V1 契约：

- 提供商配置值：`disabled`、`minio`、`aliyun-oss`；`injected` 仅供测试。开发环境使用 MinIO，未来正式环境使用阿里云 OSS 独立适配器；Cloudflare R2 不再采用。
- 三 Bucket 模型：所有新上传只进入 quarantine；审核通过的 `PUBLIC` 文件复制到 public；`SIGNED/PRIVATE` 文件复制到 private；拒绝文件不进入最终 Bucket。三个 Bucket 名分别由 `FILE_QUARANTINE_BUCKET`、`FILE_PUBLIC_BUCKET`、`FILE_PRIVATE_BUCKET` 配置并必须互不相同。
- 文件用途规范值：`USER_AVATAR`、`SELLER_AVATAR`、`SELLER_COVER`、`PRODUCT_IMAGE`、`VOICE_SAMPLE`、`COMPLAINT_EVIDENCE`、`ADMIN_EVIDENCE`、`PAYMENT_PAYLOAD`。本地用户端核心验收覆盖前六项；后两项已用合成无隐私样本完成专用服务端真实 MinIO 链路和身份隔离验收，但不属于当前用户端交付范围。
- 用户文件 API：策略、申请上传、complete、本人恢复列表、本人短时访问、删除、公共文件读取及陪玩声音受控播放；管理员文件 API：列表、管理员上传/complete、详情、同源预览和审核。路径、权限、请求/响应安全字段按第 3 节冻结。
- 客户端不能选择 Bucket 或对象键，不能持有存储密钥，不能永久保存预签名 URL。大小、SHA-256、真实 MIME、图片尺寸、音频轨与真实时长、所有权、用途、审核状态、可见性和业务绑定资格均由服务端最终裁决。
- 生命周期冻结为精确对象操作、有界重试、过期上传复核、业务引用保护和默认只读孤儿审计；禁止全 Bucket 清空或按宽泛相似前缀删除未知对象。
