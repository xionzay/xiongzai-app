## 5. 上传、审核与绑定链路

已确认的主链路为：

1. 已认证客户端按受支持业务类型申请短时预签名 PUT 地址。
2. 服务端生成 Bucket 和对象位置；客户端不能指定 Bucket 或永久对象位置。
3. 客户端只执行一次直传；上传取消会中止请求并清理本次产生的临时状态。
4. PUT 成功后调用 `complete`；如果 `complete` 暂时失败，只重试 `complete`，不会重复上传对象。
5. 服务端通过 HEAD/读取校验大小、SHA-256、真实 MIME、图片尺寸、音轨和音频真实时长。
6. 校验通过后进入待人工审核状态；校验失败不能进入绑定流程。
7. 管理员预览后通过或驳回；通过时从隔离 Bucket 复制到公开或私有 Bucket。
8. 只有已校验且审核通过的文件才能建立有效使用关系；替换和解绑会维护使用关系并进入安全清理流程。

重复 `complete` 已按幂等行为覆盖测试。篡改元数据、哈希不一致、MIME 伪装、尺寸不符、无音轨和声音时长越界均会被拒绝。

## 6. 私有访问和预签名 URL 安全

- 投诉证据最终进入 private Bucket，匿名访问被拒绝，不能获得公开永久地址。
- 声音名片采用短时签名 GET 地址；只有文件所有者、被允许的业务访问者或有权限的管理员可以请求。
- 声音名片必须处于已校验、审核通过且存在有效绑定的状态，才能受控试听。
- 管理后台文件预览使用同源流式代理，支持 Range 请求，并设置 `no-store`、`nosniff` 和受限 CSP。
- 预签名 URL 不写入数据库，不写入客户端持久状态，不写入日志，也不会返回给无权限用户。
- 客户端不保存 Bucket、永久对象位置或完整预签名 URL。
