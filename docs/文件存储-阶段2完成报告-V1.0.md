- `storage:local:prepare`、`storage:local:start`、`storage:local:configure`、`storage:local:verify` 的用途和执行顺序已在文件存储文档中说明；前台服务使用 `Ctrl+C` 停止，丢失终端时先定位精确 PID 再停止。

## 4. 代码与配置一致性

对象存储业务层统一依赖 `ObjectStorageProvider`，涵盖上传签名、HEAD、受限读取、下载签名、复制和删除。配置和模块装配至少支持：

- `disabled`：安全关闭，文件存储操作返回不可用，不影响其他 API 启动。
- `minio`：使用 S3 Signature V4 和 path-style Bucket URL，供本地开发使用。
- `aliyun-oss`：保留官方阿里云 OSS SDK 适配器边界；未注入适配器时安全失败，不会错误复用 MinIO 签名。

配置还保留 `injected` 以便测试或运行时注入。三个 Bucket 必须互不相同；MinIO 必须配置 Endpoint 和密钥；阿里云 OSS 还必须有真实 Region；生产环境拒绝明文 HTTP Endpoint。

阿里云 OSS 目前只完成接口和配置边界，尚未安装官方 SDK、创建 Bucket/RAM 身份、配置 CORS/生命周期或进行真实账号联调。

## 5. 文件校验与业务隔离

- 新文件只进入 quarantine Bucket，上传 URL 绑定 MIME、声明 SHA-256 和声明大小。
- 完成上传时先 HEAD，再受限读取对象，重新计算 SHA-256，嗅探真实 MIME，并解析图片尺寸或音频时长。
- 文件用途决定大小、格式、可见性和允许的调用者；业务绑定要求文件属于当前用户，并同时满足 `VERIFIED + APPROVED`。
- 管理员审核通过后，PUBLIC 文件复制到 public Bucket，SIGNED/PRIVATE 文件复制到 private Bucket，再尽力删除隔离对象。
- 文件响应不暴露 Bucket、`object_key` 或存储密钥；公开接口只允许已验证、已批准且非私有文件。
- 当前没有购买或接入恶意文件扫描服务。格式、哈希和人工审核不能替代恶意软件扫描；数据库当前也没有独立扫描状态字段。

## 7. 密钥、许可证与日志安全

- `.env*`、项目根目录 `.local/`、常见密钥和证书扩展名已被 `.gitignore` 排除。
- `.env.minio.local`、`.env.backend.local` 和项目内 MinIO 许可证均已通过 Git 忽略规则检查；本地环境文件和许可证文件权限为 `0600`，许可证目录权限为 `0700`。
- 没有跟踪 `.env`、许可证或 `.local/minio` 二进制文件。
- 准备、启动、配置和验证脚本不打印存储 Secret 或许可证内容；`mc` 的敏感配置输出被抑制。
- HTTP 日志只记录去除查询串后的路径，不记录预签名 URL；服务端错误日志不输出底层连接值。
- 配置示例仅含不可用占位符；Mobile 和管理员前端中没有存储 Access Key、Secret 或数据库连接串。
- 下载文件夹中的旧许可证没有被读取、修改或删除。若需要清理，应先取得用户明确授权并只删除确认的旧文件。

## 8. 用户端 App 接入情况

后端文件接口和公共文件展示接口已经存在，但用户端 App 尚未完成上传闭环：

- 当前头像页面只有本地选择、裁剪和预览，没有调用 `/api/v1/files/uploads`、PUT 预签名 URL 和 `/complete`。
- App 尚未计算上传 SHA-256、发送规定元数据请求头、显示上传进度、重试或审核状态。
- 卖家申请、资料和服务发布流程仍会阻止把本地 URI 当成服务端 `file_id`。
- App 已能通过后端公共文件接口显示既有公开文件，但不能据此认定上传已接入。

因此，后端与 App 的目标契约一致，但 App 侧尚未实现该契约。

## 9. 管理员后台检查

### 9.1 后端已经具备

- 管理员文件列表及上传状态、审核状态筛选。
- 管理员证据上传、上传完成确认和受控访问 URL。
- 审核通过、审核拒绝和必填审核原因。
- 文件响应包含所有者、用途、上传状态、审核状态、公开/私有状态和媒体元数据。
- 文件审核要求 MFA 和 `file.read`、`file.manage`、`file.review` 权限。
- 审核操作写入 `admin_operation_logs`；现有通用操作日志接口和页面可以查看日志记录。

### 9.2 管理员 UI 缺少

当前 `app/admin/page.tsx` 没有文件管理模块或 `/admin-api/v1/files` 接入，因此 UI 尚不具备：

- 文件列表与文件详情。
- 待审核文件列表。
- 文件预览。
- 审核通过、审核拒绝和审核原因填写。
- 文件所有者和用途展示。
- 公开/私有状态展示。
- 文件专用的管理员操作日志关联视图。

通用操作日志页面已经存在，但没有文件审核入口，不能视为文件管理 UI 已完成。本阶段按要求只报告缺口，没有设计或实现管理员 UI。

下一阶段需要用户确认的信息：

- 首个接入用途是否按“用户头像”优先。
- 真机或模拟器访问本机 API 的开发地址与端口；不得把 `127.0.0.1` 误当作真机上的 Mac。
- 各媒体用途是否沿用本文档现有格式、大小和时长限制。
- 上传交互是否需要暂停/取消、后台上传和弱网重试。

下一阶段本地开发预计不产生费用。未来真实阿里云 OSS 阶段可能涉及对象存储容量、请求次数、下行流量、CDN、图片处理、日志监控和安全扫描费用；在创建任何资源或产生费用前必须另行列出资源、权限、预计费用和回滚方式并等待授权。
