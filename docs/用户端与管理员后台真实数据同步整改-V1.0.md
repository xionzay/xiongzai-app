# 用户端与管理员后台真实数据同步整改 V1.0

## 1. 结论与边界

本轮已完成不依赖外部服务的真实数据同步整改：Web 用户端、移动端、管理员后台、API、PostgreSQL、MinIO、Worker 和 Scheduler 共用同一套服务端业务事实。账号注销、手机号换绑、个人数据导出不再显示“未开放”；已审核陪玩修改公开资料必须重新审核；后台新增换绑、导出和站内通知只读监控，并补齐中文字段、媒体对比和客服聊天工作台。

本轮只使用本地 PostgreSQL、MinIO、开发短信验证码和 Mock 资金渠道，没有连接真实支付、短信、实名、推送、内容审核或云服务。自动化验收已经通过；实体手机点击闭环未在本轮实际执行，因此仍是人工验收项，不能写成真机通过。

## 2. 原有问题与已完成整改

| 原有同步问题 | 整改结果 |
|---|---|
| 手机和 Web 仍把注销、换绑、数据导出标为未开放 | 两端均接入真实用户生命周期 API，展示服务端状态、阻塞条件、冷静期、错误和下载资格 |
| 已审核陪玩可直接覆盖公开内容 | 昵称、介绍、能力资料、头像、封面和声音名片改为草稿、提交、审核、发布；审核前公开旧版本 |
| 后台陪玩审核看不到新旧媒体 | 审核抽屉展示当前公开与待审核字段差异，并受控预览新旧头像、封面和声音名片 |
| 后台详情出现英文键和枚举 | 增加统一中文字段、状态、渠道、文件、风险、通知和审核动作映射；未知枚举安全降级 |
| 后台缺少换绑、导出和通知监控 | 增加三个独立导航，只读查询真实 PostgreSQL 记录，执行 MFA、RBAC 和错误状态处理 |
| 客服只有工单按钮，没有直观聊天区 | 客服工作台展示真实消息历史、回复、转交与关闭流程，不生成模拟消息 |
| 真机可能静默使用回环或模拟器地址 | 移动端真机缺少显式 API 地址时明确失败；局域网地址只通过忽略提交的环境配置提供 |
| MinIO 地址对真机不可达 | `LOCAL_LAN_HOST` 同步配置 API 监听、MinIO 监听和签名主机，只接受私有 IPv4 |
| 后台固定宣称 Worker/Scheduler 正常 | 健康页展示真实队列事实，并明确独立进程在线状态“未测量” |

## 3. 用户端页面

- Web 用户端：手机号换绑、个人数据下载、账号注销页面接入真实 API，处理加载、空数据、失败、409 刷新和服务端成功结果。
- 移动端：`settings/phone-change`、`settings/data-export`、`settings/account-cancellation` 接入同一 API；换绑完成后清理旧 Session，要求使用新手机号重新登录。
- 陪玩资料：已通过或已暂停陪玩编辑公开字段时保存资料变更草稿，提交新的审核版本；接单开关仍按现有 CAS 状态机独立更新。
- 数据导出：只有 `COMPLETED` 才显示受控短时下载；URL 只在运行内存中使用，不持久化。

## 4. 管理员后台页面

- 新增“手机号换绑记录”：脱敏新旧手机号、步骤、错误次数、完成/失败时间和安全日志请求编号，只读。
- 新增“数据导出任务”：脱敏用户、排队/处理中/完成/失败/过期事实，只读且不允许管理员下载副本。
- 新增“站内通知记录”：展示站内投递、已读状态和安全失败原因，不把未接入的外部推送标为成功。
- 账号注销：保留真实列表和详情；拒绝需要 `user.status.manage`、原因、最新 `version` 和服务端审计，不能强制批准或删除证据。
- 陪玩审核：明确区分“当前公开资料”和“待审核快照”，展示字段差异及新旧头像、封面、声音名片。
- 陪玩管理：展示当前公开主页、媒体、审核历史、治理历史、可接单状态和时段。
- 服务审核：受控显示真实服务图片；投诉证据和用户头像同样通过后台文件接口读取。
- 客服中心：真实工单消息历史、接入、回复、转交和关闭工作台。
- 通用详情：递归中文化，不直接显示原始 JSON，不暴露对象键或完整预签名 URL。

## 5. API 与权限

### 用户 API

- `POST/GET /api/v1/me/phone-change-requests`
- `POST /api/v1/me/phone-change-requests/:id/old-code/send|verify`
- `POST /api/v1/me/phone-change-requests/:id/new-code/send|verify`
- `POST /api/v1/me/phone-change-requests/:id/cancel`
- `POST/GET /api/v1/me/data-exports`
- `GET /api/v1/me/data-exports/:id/download`
- `POST/GET /api/v1/me/account-cancellations`
- `GET /api/v1/me/account-cancellations/eligibility`
- `POST /api/v1/me/account-cancellations/:id/revoke`
- `PUT /api/v1/seller/profile-revisions/draft`
- `POST /api/v1/seller/profile-revisions/:applicationId/submit`

### 管理员 API

- `GET /admin-api/v1/phone-change-requests` 与 `/:id`
- `GET /admin-api/v1/data-export-jobs` 与 `/:id`
- `GET /admin-api/v1/notification-deliveries` 与 `/:id`
- 现有 `/admin-api/v1/account-cancellations` 列表、详情和版本化拒绝接口
- 现有陪玩申请详情、审核、文件预览和客服接口
- `GET /admin-api/v1/system/health` 返回安全队列事实，不推断独立进程存活

本轮没有扩大高风险权限集合：生命周期与通知监控复用 `user.read`；注销拒绝复用 `user.status.manage`；资料变更审核复用 `seller_application.read`、`seller_application.review`；媒体预览继续使用 `file.read`、`file.review`；健康事实使用 `system_health.read`。所有管理员接口要求有效 Session 和 MFA，后端 RBAC 仍是最终边界。

## 6. 陪玩资料重新审核规则

1. 已通过或已暂停的陪玩直接修改公开内容会返回冲突，不能覆盖买家当前看到的资料。
2. 客户端使用当前陪玩 `version` 保存 `PROFILE_UPDATE` 快照；同一时间只允许一个待处理资料变更。
3. 提交审核前，公开资料与媒体必须完整；文件必须属于本人、上传校验完成且人工审核通过。
4. 审核中继续读取上一个已通过公开版本。
5. 管理员通过后在同一事务发布整个快照、更新文件绑定、写审核日志、管理员审计和 Outbox。
6. 驳回或要求补充只改变申请状态，不污染公开版本；原因保留给用户查看。
7. 历史申请、文件使用和审核证据保留，不物理删除。

该能力复用现有 `seller_applications.snapshot_json`、版本号和审核日志，不需要新增资料审核迁移。

## 7. 数据库迁移

- `packages/database/migrations/0007_user_lifecycle_requests.sql`：手机号换绑、个人数据导出和账号注销请求模型。
- `packages/database/migrations/0008_user_lifecycle_invariants.sql`：生命周期状态、并发、证据和一致性约束。

迁移保留已有数据；陪玩资料变更审核复用现有表，没有另建重复表。

## 8. 局域网真机配置

1. 使用 `ipconfig getifaddr en0` 查询常见 Wi-Fi 私有 IPv4；不要把地址提交到 Git。
2. 在可信同一 Wi-Fi 下临时运行 `LOCAL_LAN_HOST=<电脑私有IPv4> pnpm storage:local:prepare`。
3. 在已忽略的 `apps/mobile/.env.local` 设置 `EXPO_PUBLIC_API_BASE_URL=http://<电脑私有IPv4>:3002/api/v1`。
4. 运行 `pnpm local:doctor` 后启动本地服务和移动端。
5. macOS 防火墙只允许本次开发进程和可信局域网；不要做端口映射，也不要把 PostgreSQL、MinIO Console 或后台开放到公网。
6. 测试完成后清除 `LOCAL_LAN_HOST` 并重新准备本地存储，使监听恢复回环地址。

详细步骤见 `docs/本地测试环境运行手册-V1.0.md`。

## 11. 尚未执行与剩余风险

- 未操作实体手机，所以注册/登录、头像/封面/声音上传、后台审核回显、客服双向消息的真机闭环未执行。
- 未接真实短信、支付、退款、打款、实名、推送、内容审核、云存储或生产基础设施；这些仍是上线前工作，不属于本地同步整改。
- Worker/Scheduler 独立进程没有可证明在线的跨进程心跳，因此后台诚实显示队列事实和“进程存活未测量”。上线前应接真实进程监控。
- 本地 `TRUSTED_LAN` 配置有自动化契约，但不同路由器、macOS 防火墙和实体设备仍需人工验证。

结论：可以判定“用户端与管理员后台本地代码及自动化同步整改完成”，但不能判定“实体手机全链路验收完成”。实体手机闭环完成并留存真实结果后，才能关闭最后一项本地人工验收。
