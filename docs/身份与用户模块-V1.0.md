# 熊崽电竞身份与用户模块 V1.0

## 1. 范围

本模块实现手机号短信登录、Web Cookie 会话、原生 App Bearer 会话、个人资料、隐私设置、协议接受和实名认证。数据只使用现有 `users`、`user_profiles`、`identity_verifications`、`auth_sessions`、`sms_codes`、`user_devices`、`privacy_settings`、`policy_versions`、`user_policy_acceptances` 表。

本地测试阶段不接入付费短信渠道。手机号换绑、账号注销和个人数据导出已经补齐受控后端工作流；客户端尚未接入前仍应显示明确状态，不得在未调用真实接口时伪造成功结果或 `file_id`。用户媒体上传继续使用独立文件模块。

账号生命周期接口、状态机、Scheduler 任务和前端交接要求见 `docs/用户账号生命周期后端-V1.0.md`。

## 2. Public API

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/v1/auth/sms/send` | 公开 | 发送登录验证码；响应不包含手机号或验证码 |
| POST | `/api/v1/auth/sms/login` | 公开 | 验证码登录/注册；请求必须带当前 `LOGIN` 场景完整 `policy_version_ids`，接受记录与会话同事务保存；Token 通过 HttpOnly Cookie 下发 |
| POST | `/api/v1/auth/token/refresh` | Refresh Cookie | 原子轮换 Refresh Token |
| POST | `/api/v1/auth/logout` | 用户 | 撤销当前会话并清除 Cookie |
| POST | `/api/v1/auth/mobile/sms/login` | 公开 | 原生 App 短信登录；同样提交 `LOGIN` 场景 `policy_version_ids`，JSON 返回 Bearer Access/Refresh Token |
| POST | `/api/v1/auth/mobile/token/refresh` | Refresh Token + `device_id` | 原生 App 原子轮换 Refresh Token |
| POST | `/api/v1/auth/mobile/logout` | Bearer Access Token | 撤销当前 App Session，不接受 Cookie 代替 Bearer |
| GET | `/api/v1/me` | 用户 | 当前用户、资料、脱敏手机号和实名状态 |
| PATCH | `/api/v1/me/profile` | 用户 | 使用用户和资料双 version 更新资料 |
| GET | `/api/v1/me/privacy-settings` | 用户 | 查询隐私设置 |
| PATCH | `/api/v1/me/privacy-settings` | 用户 | 使用 version 乐观锁更新隐私设置 |
| GET | `/api/v1/me/sessions` | 用户 | 查询登录会话和脱敏设备摘要，标记当前 Session |
| DELETE | `/api/v1/me/sessions/{session_id}` | 用户 | 撤销本人指定会话 |
| GET | `/api/v1/me/identity-verification` | 用户 | 查询最新实名认证脱敏状态 |
| POST | `/api/v1/me/identity-verification` | 用户 | 提交人工审核实名认证 |
| GET | `/api/v1/policies/current?scene={scene}` | 公开 | 查询某业务场景必须接受的当前已发布且已生效版本；不传 scene 返回全部当前版本 |
| POST | `/api/v1/policies/acceptances` | 用户 | 保存不可变协议接受记录 |
| GET | `/api/v1/policies/acceptances` | 用户 | 查询本人的真实协议接受记录 |
| GET | `/api/v1/policies/{policy_version_id}` | 公开 | 查询指定已发布协议版本的正文和发布时间 |

## 3. Admin API

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/admin-api/v1/identity-verifications` | `identity.read` + MFA | 按状态查询脱敏实名记录 |
| POST | `/admin-api/v1/identity-verifications/{id}/review` | `identity.review` + MFA | version 乐观锁审核，并写管理员审计和 Outbox |
| GET | `/admin-api/v1/policies` | `config.read` + MFA | 按类型、状态查询协议版本 |
| GET | `/admin-api/v1/policies/{policy_type}/versions` | `config.read` + MFA | 查询版本历史 |
| POST | `/admin-api/v1/policies` | `config.manage` + MFA | 创建下一版本草稿 |
| PATCH | `/admin-api/v1/policies/{policy_version_id}` | `config.manage` + MFA | 以响应中的字符串 `version` 编辑草稿 |
| POST | `/admin-api/v1/policies/{policy_version_id}/publish` | `config.manage` + MFA | 发布并设置 `effective_at`、`requires_reacceptance` |
| POST | `/admin-api/v1/policies/{policy_version_id}/retire` | `config.manage` + MFA | 停用已发布版本；历史内容不变 |

## 4. 安全规则

- 手机号、姓名和证件号使用 AES-256-GCM 分域加密；查询使用独立密钥的 HMAC-SHA256；数据库另存脱敏展示值。
- 验证码和 Refresh Token 只保存分域 HMAC，不保存可还原明文。
- Web 用户 Token 不进入 JSON、localStorage 或普通日志，只通过 HttpOnly、SameSite Cookie 传输；生产环境增加 `Secure`。
- 原生 App Access Token 仅通过 `Authorization: Bearer` 发送并只保存在运行时内存；Refresh Token 由 iOS Keychain / Android Keystore 保存，不得进入 AsyncStorage、普通文件或日志。
- 移动端 Token 接口响应均使用 `Cache-Control: no-store`；生产环境通过 HTTP 调用返回 `AUTH_INSECURE_TRANSPORT`。
- 登录、资料、隐私、实名和审核响应只返回脱敏数据；后台审核列表也不能读取密文。
- 验证码有发送间隔、有效期、最大错误次数和一次性消费约束。
- Refresh Token 每次使用后原子轮换；退出、设备撤销、会话过期和用户封禁都会使访问失效。
- Session 列表不返回完整 `device_id`，仅返回末四位脱敏摘要和由当前 Access Token Session 推导的 `current` 标识。
- 移动端刷新同时校验 Refresh Token HMAC、Session、用户状态、`device_id`、设备平台和 `user_devices` 撤销状态；设备不匹配与 Token 重放统一返回 `AUTH_REFRESH_INVALID`，不泄露 Session 是否存在。
- 移动端 Bearer 写请求不执行浏览器 Cookie CSRF Origin 规则，但仍执行 Token 签名、issuer、audience、算法、Session、用户状态和资源权限校验。
- 资料、隐私和实名审核使用 `id/status/version` Compare-And-Set；冲突返回 `RESOURCE_VERSION_CONFLICT`。
- 实名审核只记录状态、操作者、原因、请求和 Trace，不把姓名或证件写入管理员操作日志。
- 草稿可编辑；已发布版本禁止覆盖修改，只允许转为 `RETIRED`。后台协议审计仅保存正文 SHA-256，不复制完整正文；本轮确认方式始终是 `ONLINE_CONFIRM`，不返回电子签成功。
- 提交人工实名前必须已接受当前 `IDENTITY_VERIFICATION` 协议；缺失时返回 `POLICY_ACCEPTANCE_REQUIRED`。

## 5. 配置

新增必填密钥：`PII_ENCRYPTION_KEY`、`PII_HMAC_KEY`、`AUTH_HMAC_KEY`，均至少 32 字节。开发环境使用 `SMS_PROVIDER_MODE=development`；生产环境禁止使用该模式，必须注入真实 Provider。

本地开发配置保存在 Git 忽略且权限为 `0600` 的 `.env.backend.local`。任何验证码、Token、密钥和完整连接串不得输出到终端、日志或提交到 Git。

移动端复用 `ACCESS_TOKEN_TTL_SECONDS`、`REFRESH_TOKEN_TTL_SECONDS`、`TOKEN_ISSUER`、`USER_TOKEN_AUDIENCE`、`USER_TOKEN_SECRET` 和 `AUTH_HMAC_KEY`，没有新增密钥。详细接入规则见《原生 App 认证接入 V1.0》。
