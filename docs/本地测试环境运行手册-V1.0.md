# 熊崽电竞本地测试环境运行手册 V1.0

## 1. 固定边界

本环境仅用于本地开发和测试：PostgreSQL、MinIO、API、Worker、Scheduler、管理员后台和移动端均在开发电脑或模拟器内运行。支付、退款、提现和短信只使用 Mock/开发实现；不连接微信、支付宝、阿里云、腾讯云或其他外网服务，也不需要域名、ICP备案、SSL、云服务器或生产密钥。

## 2. 服务清单与端口

| 服务 | 作用 | 本地端口/状态 |
|---|---|---|
| PostgreSQL 16 | 开发库与独立测试库 | `127.0.0.1:5432` |
| MinIO API | 文件对象存储 | `127.0.0.1:9000` |
| MinIO Console | 本地存储管理页 | `127.0.0.1:9001` |
| API | 用户端与后台接口 | `127.0.0.1:3002` |
| Worker | Outbox 异步任务 | 无 HTTP 端口，检查日志 |
| Scheduler | 超时、结算等定时任务 | 无 HTTP 端口，检查日志 |
| 管理员后台 | 本地 Web 管理端 | `localhost:3001` |
| iOS/Android App | 模拟器或同局域网真机 | 由 Expo 开发服务启动 |

## 3. 首次准备

在项目根目录运行：

```bash
pnpm local:prepare
```

该命令按顺序执行：启动/初始化本地 PostgreSQL、创建受限角色和两个隔离数据库、生成或补齐忽略提交的本地环境文件、准备 MinIO 本地配置、构建后端、执行开发库迁移、写入本地测试协议种子，最后做不联网的配置体检。

数据库固定为：

- `DATABASE_URL`：`xiongzai_api_dev`，用于手工测试和本地运行。
- `TEST_DATABASE_URL`：`xiongzai_database_test`，仅用于自动化测试。

两个连接必须不同，且均只允许连接本机 PostgreSQL。体检或数据库验证发现混用时会直接失败。

## 4. 启动顺序

确认旧终端中的同类服务已经按 `Ctrl+C` 停止，然后运行：

```bash
pnpm local:run
```

统一启动器的实际顺序为：

1. 检查 `9000`、`9001`、`3002`、`3001` 端口冲突。
2. 启动 PostgreSQL（已运行则复用，不会在退出时停止它）。
3. 启动 MinIO，等待就绪并创建/校验 Bucket。
4. 启动 API，等待 `/health/ready`。
5. 启动 Worker。
6. 启动 Scheduler。
7. 启动管理员后台。

统一启动器将输出写入 `.local/logs/`。在该终端按 `Ctrl+C`，它只停止自己启动的 MinIO、API、Worker、Scheduler 和后台；若 PostgreSQL 也是它启动的，则一并安全停止。意外退出任一核心子进程时，启动器会停止其余子进程，避免残留。

若需要手工分终端启动，严格按以下顺序：

```bash
pnpm db:local:start
pnpm storage:local:start
pnpm storage:local:configure
pnpm api:dev
pnpm worker:dev
pnpm scheduler:dev
pnpm dev
```

手工模式下 `storage:local:start`、`api:dev`、`worker:dev`、`scheduler:dev` 和 `dev` 各占一个终端。结束时分别按 `Ctrl+C`；PostgreSQL 另用 `pnpm db:local:stop` 停止。

## 5. 种子数据

本地栈就绪后，在另一个终端运行：

```bash
pnpm local:seed
```

该命令会：校验 MinIO、写入本地测试协议版本、生成管理员/买家/陪玩/商品/声音名片/提现账户等人工测试数据。协议包含当前发布版本、草稿和已停用版本，用于测试注册同意、陪玩入驻签署、订单确认和版本追踪；它不是第三方电子签约服务。

## 6. Mock 行为

- 微信支付和支付宝支付：用户仍选择两个独立渠道，后端分别走两个 Mock Provider；确认、失败、取消、退款和回调都只改本地数据库，不访问真实支付机构。
- 提现：支持本地微信/支付宝类型的 Mock 提现申请、审核、受理、成功/失败回调，不会向个人账户转账。
- 短信：开发验证码由本地配置注入，不发送短信，不写入普通业务日志，也不通过 API 返回。
- 退款：沿用本地订单/账务状态机和 Mock 支付渠道，不产生真实资金流。

安全门：`development` 和 `test` 才允许上述 Mock/开发模式；API 与 Worker 已在 `staging`、`production` 拒绝 Mock 支付、Mock 提现、开发短信、日志事件发布器和回环数据库。移动端 `production` 构建也拒绝开启 Mock 支付开关。

## 7. 健康检查

完整运行体检：

```bash
pnpm local:doctor
pnpm db:local:verify
```

只检查配置、文件权限和本地二进制，不要求服务全部运行：

```bash
pnpm local:doctor:config
```

可直接访问的健康地址：

- API 存活：`http://127.0.0.1:3002/health/live`
- API 就绪：`http://127.0.0.1:3002/health/ready`
- MinIO 存活：`http://127.0.0.1:9000/minio/health/live`
- MinIO 就绪：`http://127.0.0.1:9000/minio/health/ready`
- 管理员后台：`http://localhost:3001/`

Worker 和 Scheduler 不暴露管理端口。统一启动器负责进程存活联动；运行细节检查 `.local/logs/worker.log` 和 `.local/logs/scheduler.log`。

## 8. 移动端 API 地址

- iOS 模拟器：`http://127.0.0.1:3002/api/v1`
- Android Studio 模拟器：`http://10.0.2.2:3002/api/v1`
- Genymotion 模拟器（如使用）：`http://10.0.3.2:3002/api/v1`
- 同一局域网真机：`http://<开发电脑局域网IPv4>:3002/api/v1`

macOS 可运行 `ipconfig getifaddr en0` 查询常见 Wi-Fi 地址；无结果时再检查 `en1`。不要把查询到的地址写入仓库、截图或聊天记录。

默认配置严格使用回环地址，实体手机不会偷偷回退到 `127.0.0.1`。在确认手机和电脑处于同一个可信、隔离的 Wi-Fi 后，按以下方式准备一次局域网测试（尖括号内容由测试人员在本机填写）：

```bash
LOCAL_LAN_HOST=<开发电脑私有IPv4> pnpm storage:local:prepare
```

该命令只接受 `10.x.x.x`、`192.168.x.x` 或 `172.16.x.x` 至 `172.31.x.x` 的私有 IPv4，并完成三件事：让 API 临时监听本地网卡、让 MinIO API 临时监听本地网卡、让后端签发的本地 MinIO 地址使用同一个真机可达主机。MinIO 管理控制台仍只监听回环地址。

随后在忽略提交的 `apps/mobile/.env.local` 中设置：

```bash
EXPO_PUBLIC_API_BASE_URL=http://<开发电脑私有IPv4>:3002/api/v1
```

再运行 `pnpm local:doctor`，通过后启动 `pnpm local:run` 和移动端开发服务。iPhone/Android 与电脑必须在同一 Wi-Fi，macOS 防火墙只允许本次开发进程和可信局域网；不要做路由器端口映射，也不要开放 PostgreSQL、MinIO 控制台或管理后台到公网。

真机测试结束后，清除 `LOCAL_LAN_HOST` 并重新运行 `pnpm storage:local:prepare`，API 与 MinIO API 会恢复为回环监听。`EXPO_PUBLIC_API_BASE_URL` 也应恢复为模拟器对应地址。本手册只说明可复现配置，未实际点击实体手机时不得宣称真机全链路已通过。

## 10. 端口、日志和数据清理

端口冲突检查：

```bash
lsof -nP -iTCP:5432 -iTCP:9000 -iTCP:9001 -iTCP:3002 -iTCP:3001 -sTCP:LISTEN
```

日志位置：PostgreSQL 为 `.local/postgres.log`；统一启动器子进程为 `.local/logs/`；MinIO 本地数据为 `.local/minio/data/`。日志不得写验证码、令牌、连接串、存储凭证或支付签名值。

人工测试种子可以重复运行，不会删除不可变的交易、账务和审计历史。需要彻底清空开发测试数据时，先停止 API、Worker 和 Scheduler，再显式执行：

```bash
pnpm db:local:reset -- --confirm-local-dev-reset
pnpm db:migrate
pnpm policy:local:seed
pnpm manual-test:seed
```

重置脚本只接受固定本机角色和固定 `xiongzai_api_dev` 数据库名，且不会删除 `xiongzai_database_test`。不要在有需要保留的本地测试记录时执行。

## 11. 常见阻断

- `5432` 被非本项目 PostgreSQL 占用：停止冲突服务或修改整套本地端口配置后再初始化，不能混接。
- `9000/9001/3002/3001` 被旧进程占用：回到旧终端按 `Ctrl+C`，再运行统一启动器。
- MinIO 本地二进制或环境文件权限不符合要求：配置体检会指出文件名或权限，不会输出内容。
- API `/health/ready` 失败：先检查 PostgreSQL、迁移、MinIO 和三个 Bucket。
- 真机无法访问：确认 API 监听局域网网卡、手机和电脑同一 Wi-Fi、使用私有 IPv4，并检查 macOS 防火墙。
- 任何环境显示 `staging`/`production` 同时又配置 Mock：这是预期安全阻断，不应绕过。
